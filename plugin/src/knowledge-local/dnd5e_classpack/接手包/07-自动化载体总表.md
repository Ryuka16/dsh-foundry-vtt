## 〇 · 这份表是干什么的

判断一件东西「描述说的机制」与「数据里做的事」是否一致时，**必须先把数据里所有可能承载自动化的位置找全**。

**反例（我真实犯过的错）**：曾用一份自己写的字段清单去提取数据，只看了 `item.effects` ⇒ 报出「这件没有任何效果」⇒ 实际它用的是 `flags.chris-premades.embeddedMacros` 或 `flags.your-feats.options` ⇒ **把有自动化的件判成缺自动化**（记录在 `01-我犯过的错.md` 的 A6）。

**最坏的一种漏法不是「我查到有问题」，而是「我没查到」** —— 因为漏掉的那类载体，在我眼里等于「这件什么都没做」，而我会报「一致」。

⇒ **本表是提取器的唯一依据。** 遇到表外的路径，不许静默丢弃，必须单独列出报警。

**★ 三层是并列的，不是包含关系**：顶层 `flags` / 效果 `flags` / **活动 `flags`** —— 三层的模块名可以完全不同（同一个包，顶层可能是 `midi-qol`，活动层却是 `autoanimations`）。**只扫两层 = 漏一层。**

## 三 · ★ 活动层 `act.flags.<模块>` —— **上一轮整层漏掉**（2026-10-07 补扫）

### 为什么漏、怎么发现的

**漏的原因**：上一版普查脚本只走了 `o.flags` 和 `ef.flags` **两条路**，没走活动对象自己的 `.flags`。

**发现方式**：**不是我自己想到的** —— 是提取器自带的「未知字段报警闸门」在第 ④ 条规则下跑「血疟长生军」时**当场报出来的**：

```
"未知字段": [
  "items[].system.activities.dnd5eactivity000.flags.autoanimations",   ← 真漏（活动层）
  "effects[].flags.auraeffects"                                        ← 脚本里的已知族列表漏写了它（文档里本来有）
]
```

⇒ 这正是**为什么闸门必须是「报警」而不是「丢弃」**：丢弃的话这两条就静默消失了。

### 实测分布

| 族 | 件数 | 承载什么 | 出现在 |
|---|---|---|---|
| `act.flags.autoanimations` | 3 个活动（your） | **AA 动画挂在活动上**（不是物品上）：`primary.video.customPath`（如 `blfx.weapon.melee.longsword1.attack1.color1`）/ `primary.sound.file`（如 `psfx.weapon-attacks.sword.v1`）/ `secondary.video.customPath`（如 `jb2a.impact.dark_red.0`）/ `menu` / `label` / `isCustomized` / `version` | `your-dm-toolkit.your-actors`（血疟长生军：长剑 / 渴血斩 / 死疫汲能） |
| `act.flags.region-attacher` | **3 件（classpack）** | Region Attacher：把区域贴到模板上 | `dnd5e_classpack.spell`：困惑术 Confusion / 火球术 Fireball / 艾伐黑触手 Black Tentacles |

### ★★ 方法教训：这一层差点又被误判成「0」

补扫时第一次用 `d.system.activities.contents` 遍历 ⇒ **返回 0 个 flags**，看起来完全像「活动层没有 flags」。
用**阳性对照**（拿已知带 `autoanimations` 的那件跑同一个函数）才拆穿：

| 取活动的方法 | 阳性对照拿到几件 |
|---|---|
| `d.system.activities.contents` | **0** ✗ |
| `d.toObject().items[].system.activities` 的 `Object.values()` | **7** ✓ |

⇒ **`ActivityCollection` 必须走 `toObject()`**（`contents` 在 `getDocuments()` 返回的文档上不工作）。
⇒ **铁律：报「0 命中」之前必须先跑阳性对照。没有对照的 0，等于没测。**（同源坑见 `01-我犯过的错.md` B18）

## 五 · 提取器必须遵守的四条（从本表直接推出）

### ① 反向白名单，不是正向白名单
**只丢弃已确认的纯噪音**：`_stats` / `ownership` / `folder` / `sort` / `_source` / `_key`（描述里的 HTML 标签剥成纯文本）。
**其余一律原样保留**，包括**全部 `flags`**。
> 注：**不要丢空字符串**（`save.dc.formula:""` 表示「跟随施法 DC」，有语义）、**不要丢 `_id`**（CPR 的 `activityIdentifiers` 就是靠活动 `_id` 定位的）。

### ② 未知字段报警闸门
提取时以本表为对照：**遇到表外路径不许静默丢弃** —— 收集起来，每批结果末尾列出「本批发现 N 个未见过的字段」。
**它的第一次实战就抓出了本表自己的漏洞**（见第三节）。

### ③ 三层都要走，一层都不能少
`o.flags` + `ef.flags` + **`act.flags`**。
**活动层最容易漏，因为它藏在 `system.activities.<key>.flags`，而不是物品顶层。**

### ④ 活动层按「类型 × 全字段」提取
活动的字段集是**枚举得出的**，不是人工挑的。光 `utility` 就有 28 个字段，其中一半是自动化载体。

## 六 · 复现脚本（只读，逐包跑，单包 ≤600 件是安全线）

> ⚠️ **必须用 `pack.getDocuments()`**，不要用 `idx.contents` + 逐件 `pack.getDocument(id)`：
> 实测 `getDocuments()` 一次拿 **1679 件成功**，而逐件方式 **600 件就 HTTP 408**。

```js
const 族 = {};
const pk = "itempack";                       // 逐包替换
const pack = game.packs.get("dnd5e_classpack." + pk);
const docs = await pack.getDocuments();
for (const d of docs) {
  const o = d.toObject();                    // ★ 必须 toObject()，否则 activities 是 ActivityCollection（拿不到）
  const seen = {};
  const 加 = (p) => {
    if (!seen[p]) {
      seen[p] = 1;
      const m = (p.match(/^(flags|eff\.flags|act\.flags)\.([^.[\]]+)/) || []);
      if (m[2]) { const k = pk + " | " + m[1] + "." + m[2]; 族[k] = (族[k] || 0) + 1; }
    }
  };
  const 走 = (x, pre, dep) => {
    if (!x || typeof x !== "object" || dep > 6) return;
    if (Array.isArray(x)) { if (x.length) 走(x[0], pre + "[]", dep + 1); return; }
    for (const k of Object.keys(x)) {
      const v = x[k]; const p = pre + "." + k;
      if (v === null || typeof v !== "object") { 加(p); }
      else { const 是数 = Array.isArray(v); 加(p + (是数 ? "[]" : "{}")); 走(v, p, dep + 1); }
    }
  };
  走(o.flags, "flags", 0);
  for (const ef of (o.effects || [])) { 走(ef.flags, "eff.flags", 0); }
  for (const it of (o.items || [])) {                             // ★ 第三层：内嵌物品
    for (const a of Object.values((it.system && it.system.activities) || {})) { 走(a.flags, "act.flags", 0); }
  }
  for (const a of Object.values((o.system && o.system.activities) || {})) { 走(a.flags, "act.flags", 0); }
}
return JSON.stringify({ 件数: docs.length, 族: Object.entries(族).sort((a, b) => b[1] - a[1]) });
```

### 5. 递归是多余的（v3 更正）

族就是 `flags` 的**第一层键**，所以**只扫一层就够了，不要递归**。

我 v1/v2 的写法把同一段正则 `^(flags|eff\.flags|act\.flags)\.([^.[\]]+)` 用在**每一层递归**里 ⇒ 一个物品的 `flags.midiProperties` 带 29 个子键，就被记 **30 次** ⇒ 跑出 `flags.midiProperties = 506,426` 这种**看着像件数、实际是路径数**的假数字。**表格里的「件数」一列因此全部作废**（族名那一列仍然是对的）。

正确写法（v3 实测，226 包 / 34,569 文档只花 332 秒）：

```js
const 记 = (key, 包, id, 名) => {
  let r = C.族[key];
  if (!r) r = C.族[key] = { 键: new Set(), 例: [] };
  r.键.add(包 + "\u0001" + id);            // ★ 按「包 + 文档id」去重 = 真实文档数
  if (r.例.length < 3) { const s = 包 + " | " + 名; if (r.例.indexOf(s) < 0) r.例.push(s); }
  (C.包档[包] = C.包档[包] || new Set()).add(key);
};
/* ★ 只扫第一层，不递归 */
const 扫族 = (f, 前缀, 包, id, 名) => {
  if (!f || typeof f !== "object") return;
  for (const k of Object.keys(f)) 记(前缀 + "." + k, 包, id, 名);
};
```

### 8.5 踩坑（本轮新增，已记 `foundry_learn`）

1. **RegionBehavior 的脚本字段是 `system.source`，不是 `system.script`。**
   先按 `system.script` 读 ⇒ 5 件全报「脚本长度 0」⇒ **差一点就写成「这些区域行为是空壳」的假结论**。
   实测键：`system` = `{ events: string[], source: string }`；困难地形行为是 `{ magical, types, ignoredDispositions }`。
   ⇒ **教训：取不到值时，先把 `Object.keys(system)` 打出来，再下结论。**
2. **`activity.flags` 与 `effect.flags` 是两套独立的 flags 空间**，模块名可以完全不同（同一个包里顶层是 `midi-qol`，活动层却是 `autoanimations` / `region-attacher`）。
3. **`getIndex()` 的 `e.type` 是文档子类型不是文档类型**（返回 `consumable`/`spell`/`npc`），文档类型在**包级 `p.documentName`** ⇒ 用它筛 `Item`/`Actor` 才拿到 226 包。用 `e.type === "Item"` 会得 **0 包**。
4. 全库跑批的 **`错包`** 字段有用：本轮报出 `sgeh-monkeydm.sgeh-items` 读失败（其余 225 包全成功）。
