# 01 · 我（AI）自己制造的错误

> **为什么这一篇排第一？**
> 因为项目里真正的返工，绝大多数**不是**包里的数据错，而是**我判断错**。
> 包里的错修一次就好了；我判断错会**连改几百件、烧掉一整轮**，而且我自己不会发现。
>
> **每条格式：现象 → 我当时怎么想的（根因）→ 代价 → 正确做法 → 触发信号**
> 「触发信号」是给你用的：出现这个信号，说明你正要重演同一个错误，**立刻停下**。

---

# A 组 · 判断类错误（做了不该做的事）

## A1 · 没读模块 CHANGELOG 就批量改名 —— 整轮工作白做

**现象**
用户说 CPR（Cauldron of Plentiful Resources）匹配有问题。我判断「物品名是中文，CPR 按英文名匹配，所以要全改英文」，
于是把 7 个包 **496 件 CPK 物品名全部改成纯英文**，还改了活动名 316 个、效果名 142 个。

**根因**
我没读 `modules/dnd5e_classpack/CHANGELOG.md`。它开头 v5.0.5（2026-08-14）原文写着：

> 「为已被 chris-premades（CPR）自动化的条目写入 `flags.chris-premades.info` 预匹配标记
> （identifier/source/version），**安装 CPR 后无需修改物品名即可在医药箱中直接匹配自动化**」

而且模块目录里**一直躺着** `cpr-mapping.json`（82,425 字节 / 477 条，每条含中文名）。
**匹配靠的是 `flags.chris-premades.info.identifier`，跟物品名一个字都没关系。**

**代价**
- 一整轮工作（改名 + 后续救回）白做
- 包内中文名被覆盖，后来靠 `cpr-mapping.json` 才恢复
- 用户为此动怒，并指出：「**你不留存一份本地的备份的中文。然后到处去找。然后还说哎呀，原包居然被改了**」

**正确做法**
```
改任何数据之前，先读三样（一次拿全，别挤牙膏）：
① modules/<模块名>/CHANGELOG.md      ← 设计意图都在这
② modules/<模块名>/module.json       ← 版本、依赖、注册项
③ modules/<模块名>/ 目录列表          ← 有没有现成的映射表/文档
```

**触发信号**
> 当你准备「批量改 N 件东西的名字/字段」时 —— 先停下来读完 CHANGELOG。
> **一个成熟模块不太可能靠"改名字"来配对，它一定有映射表或 flag。**

## A2 · 声称「没有备份」，其实备份一直存在

**现象**
改名之后用户问「原文呢」？我回答「没有备份」——然后满世界找。

**根因**
**没勘察就下结论。** 我只扫了自己改过的地方，没有扫「这个东西可能存在于哪里」。

**正确做法**
```
说「没有 X」之前，必须先把 X 可能存在的位置列一遍：
① 模块目录（含 CHANGELOG / *.json / docs/）
② 世界里的副本（actor 身上的 item 也是来源）
③ 本地资料库（01_跑团工具\FVTT技术资料\）
④ 会话历史（若有）
列完再下结论；列不完就说「我查了 A/B/C 三处没有，还没查 D」。
```

**触发信号**
> 你要说「没有 / 不存在 / 找不到」时 —— 先问自己「我找过哪几处？列出来。」

## A3 · 把「自己人做的标记」判成「伪造的脏数据」

**现象**
扫到包里 495 件 CPR 物品的 `flags.chris-premades.info.version` 是 `99.0.0`，
我判定：「**这是上一个会话伪造的版本号**」，并准备全改回官方版本。

**根因**
用户纠正：

> 「**99.0.0 是我们自己自制 CPR 宏的标记**，不是伪造。」

复查后更发现：看似「乱」的版本号（`1.1.0` 占 273 件）**是官方真实版本** ——
**每个 CPR 宏有自己独立的版本号，不是模块版本号**。
真正异常的只有 13 件（`99.0.0`×10 / `2.1.38`×2 / `2.0.1`×1），官方确实没有对应宏。

**代价**
差点把 495 件正常数据「修正」成错的。

**正确做法**
```
看到"异常值"，先回答三个问题（答不出就不许改）：
① 谁写的？        （查 CHANGELOG / git / 会话记录）
② 什么时候写的？   （_stats.createdTime / 文件 mtime）
③ 改成"正常值"之后，什么会变？（说不出变化 = 相关而非因果 = 不许改）

★ 判定前先排除自己人：这个包是我们自己维护的，任何"奇怪"都可能是"有意的"。
```

**触发信号**
> 你要用「伪造 / 遗留 / 脏数据 / 上个会话留下的」当理由时 —— **这三个词是危险信号**。
> 它们是**结论**，不是证据。先拿证据。

## A4 · 措辞掩盖判定：「属玩法变更而非笔误」

**现象**
奥术射击·追踪矢：规则书明写「不投攻击骰 + 目标敏捷豁免 + 成功减半」，数据却是 `attack` 活动（点它会弹 d20）。
我汇报：「**这属玩法变更而非笔误**」。

用户回：
> 「**我没听懂，如果是弹 D20 不是说明他是错的嘛**」

**根因**
我用了委婉措辞去描述一个明确的错误。**措辞差异被当成了判定差异。**

**正确做法**
```
判定就两种：对 / 错。没有"玩法变更""设计取舍""合理近似"这类中间态。
如果确实是做不了的（无字段），要明确说「**这是错的，但我们改不了，因为 X**」——
错误定性和可行性是两个独立结论，不要混在一句话里。
```

**触发信号**
> 你写出「属……而非……」「算是……吧」「可以理解为……」时 —— 停。
> 用户要的是「对不对」，不是文学描述。

## A5 · over-claim：「技术上还能补」（没验证就说）

**现象**
战技（Battle Master Maneuvers）那轮，我报告「**擒拿击这类技术上还能补**」。
用户让我做，我拉出 18 件完整配置一看：**本来就全对，零改动**。

**根因**
**没看数据就先断言。** 我当时只有"类名 + 印象"，没有配置原文。

**代价**
报告里出现假缺口；用户按假缺口下了指令。

**正确做法**
```
说「能做而没做」之前，把配置原文拉出来看一眼。
判据：能不能贴出这件东西的 system.activities / effects 全文？
     贴不出 = 你还没看 = 不许下结论。
```

**触发信号**
> 你要说「X 还能做 / X 可以补 / X 缺了」时 —— 先 `foundry_get_entity{uuid, summary:true}` 看一眼。

## A6 · 把「零效果」判成「缺效果」（差点大规模误报）

**现象**
设计了一个判据：「物品有描述说给抗性，但 `item.effects` 为空 ⇒ 缺效果」。
跑下来命中几百件，差点批量补写效果。

**根因**
**包内的效果有四种不在 `item.effects` 里的合法形态**，我只看了一种：

| 形态 | 判据字段 | 规模 |
|---|---|---|
| **自选专长**（勾选后才生成效果） | `flags["your-feats"].options` | feats-all **50 件**，其中 38 件 `effects` 为空 |
| **CPR 嵌入宏** | `flags["chris-premades"].embeddedMacros` | 多件 |
| **ActiveAuras 光环** | 效果上的 `flags.ActiveAuras` | 防活物护罩等 |
| **dnd5e 原生 flag** | `flags.dnd5e.tavernBrawlerFeat` 等 | 斗殴高手等 |

**正确做法**
```
判「这件有没有自动化」必须五形态取并集：
  ① item.system.activities  非空
  ② item.effects            非空（注意：可能全是 disabled 或空壳载体）
  ③ item.flags["chris-premades"] 有 macros / embeddedMacros
  ④ item.flags["your-feats"] 有 options
  ⑤ 效果自身带 flags.ActiveAuras / flags.dae.macro / flags.itemacro.macro
```

**触发信号**
> 你的判据跑出「几百件命中」时 —— **几百件不可能是真错**。
> 真错一定是个位数的。命中太多 = 判据错，不是包错。

## A7 · 相信「上一个会话」的注释

**现象**
包里很多物品描述里有 `【自动化无法匹配】` / `【自动化提示】` 的自注，
我一度把它们当成「原作者有意不做」的理由，据此放过了 354 件 feat。

**用户原话**
> 「**没有作者，是你自己做的卡，上一个会话，所以他说的不可信**」
> 「都说了咩有作者，是上一个会话写的，不是准确的」

**根因**
我把**自己上一个会话写的注释**当成了**第三方权威**。
（复核后其实那些自注内容基本是对的，但**"基本对"不是"可信"** —— 判据必须回到外部锚点。）

**正确做法**
```
包内任何自注、注释、changelog 说明 —— 一律只当**线索**，不当**依据**。
判定回到三种外部锚点：官方包 / 规则书 / 运行时实测。
```

**触发信号**
> 你想引用「包里写着……」当理由时 —— 改去查规则书。

# B 组 · 技术操作类错误（改坏了 / 改不动 / 假成功）

> **这一组有个共同特征：它们几乎都不报错，或者报错信息完全误导。**
> 危险程度排序：静默失败 > 报错失败。**静默失败会让你以为改成功了。**

## B1 · ★★★ 最危险：`getIndex()` 用 `e.id`（应为 `_id`）—— 550 次循环静默全跳过

**现象**
写了一个批处理循环，遍历 22 批 / 550 次，逐件 `pack.getDocument(id)` 读取并修改。
结果：**0 改动、0 报错、脚本正常结束**。

**根因**
`CompendiumCollection#getIndex()` 返回的条目，id 字段是 **`_id`**，不是 `id`。
我写成 `e.id` → 全是 `undefined` → `getDocument(undefined)` 返回 `null` → 我的代码里
`if (!doc) continue;` 把每一次都静默跳过了。

**正确做法**
```js
// ❌ 错
const idx = await pack.getIndex();
for (const e of idx.contents) { const d = await pack.getDocument(e.id); }   // e.id === undefined

// ✅ 对
for (const e of idx.contents) { const d = await pack.getDocument(e._id); }
```

**触发信号**
> **批量脚本"跑完了但什么都没变"时 —— 第一怀疑对象是 id 取错了。**
> 每次批量操作后必须**读回验证**，且验证要**独立于修改脚本**（改完再拉一次原数据看变没变）。

## B2 · `d.update({effects:[...]})` 想替换效果 —— 实际是**追加**

**现象**
想把某件物品的一条效果改名，写了 `d.update({"effects.0.name":"新名"})`。
读回发现：**效果变成 2 条**（原有 + 新的，`_id` 不同）。

**根因**
Foundry 的 ArrayField 语义：
- 数组元素**带 `_id`** → 按 id **合并**（原地更新）
- 数组元素**不带 `_id`** → **追加**

而我尝试的两种写法都不对：
```js
d.update({effects:[{_id, name:"新名"}]})        // ❌ 丢字段（只给了 _id+name）
d.update({"effects.0.name":"新名"})             // ❌ 追加成两条
```

**正确做法**
```js
// ✅ 带整条效果对象（map 后原地更新，数量不变）
const o = d.toObject();
await d.update({ effects: o.effects.map(e => e._id === 目标id ? {...e, name: 新名} : e) });

// ✅ 要真正替换/删除效果 —— 只能重建文档
const 新 = JSON.parse(JSON.stringify(o));
新.effects = 新.effects.filter(e => e._id !== 要删的id);
await pack.documentClass.create(新, { pack: pack.collection, keepId: true });
```

**代价**
误伤后靠 `create(o,{pack,keepId:true})` 重建修复（前例 `dnd5e_classpack.spell/0GPWp8Rwlm5AizJD` 惊惧斩）。

## B3 · `d.update({"system.activities":{}})` 想清空活动 —— 无效

**现象**
想把一件物品的活动全清掉，写 `d.update({"system.activities":{}})`。返回成功，读回**活动还在**。

**根因**
`system.activities` 是 ObjectField（`ActivityCollection`），点号/整段赋值的写路径不通。

**正确做法**
```js
const o = d.toObject();
o.system.activities = {};                                   // 清空
await pack.documentClass.create(o, { pack: pack.collection, keepId: true });   // 重建
```
（已验证：`extra-ability/追猎如风 lvgd0LAWO41fbYRk` 用此法删掉错挂的「群体恐惧」活动，id 不变、描述保留。）

## B4 · 用 `-=<键名>` 删活动 —— 触发 TypeError

**现象**
`d.update({ ["system.activities.-=" + 键名]: null })`。
报错：
```
TypeError: Cannot read properties of undefined (reading 'cachedSpell')
```

**根因**
dnd5e 的 `FeatData.preUpdateActivities` 钩子会拿被删的键名当 id 去
`this.activities.get(id)`，拿到 `undefined` 后访问 `.cachedSpell` 抛错。**活动删不掉还报错。**

**正确做法**
```js
// ✅ 读 → 过滤 → 整段替换（走重建文档，见 B3）
// ✅ 或者保留原 key、只改内容（换活动类型也用这招，不需要删）
upd["system.activities." + 原key] = 新活动对象;
```

## B5 · 用**截断的** id 调 `getDocument` —— 返回 null

**现象**
扫描时为了省内存用 `id.slice(0,8)` 存索引，后面拿这个短 id 去 `pack.getDocument(...)`。
报错：
```
Error executing script: Cannot read properties of null (reading 'toObject')
```

**正确做法**
```js
// ✅ 一次 getDocuments() 建全量索引
const docs = await pack.getDocuments();
const idx = {}; docs.forEach(d => idx[d.id] = d);
// ✅ 或者保留完整 16 位 id 再逐件 getDocument
```

## B6 · 抄参考库模板写 `dc.calculation:"flat"` —— 运行时 DC 全落到默认 10

**现象**
按 `foundry_reference{topic:"save-activity"}` 的模板，给蕈孢木甲 6 件写
`save.dc = {calculation:"flat", formula:"15"}`。
实测：**DC 全部算出 10**，formula 被完全忽略。

**根因**
模板里那个 `"flat"` 是错的。包内 9 个**正确的** save 活动全是 `calculation:""`：
```
麻绳       formula "17"          → 17
巨人屠杀者刺剑 "15"              → 15
炸药       "12"                 → 12
反制善恶   "spellcasting"        → 8（跟随施法DC）
```

**正确做法**
```js
// 固定 DC
save: { ability:["con"], dc: { calculation:"", formula:"15" } }
// 跟随施法者 DC
save: { ability:["cha"], dc: { calculation:"spellcasting", formula:"" } }
```

**★ 更高一层的教训**
> **参考库模板 ≠ 实测。冲突时以实测为准。**
> 参考库是给人快速上手的，不是权威源码。用之前先看包内**同类的既有正确件**怎么写的。

## B7 · 一次扫 7~20 个包 `getDocuments()` —— 必然 HTTP 408

**现象**
`Error: HTTP 408`（relay 单次 `execute_js` 约 35 秒超时）。

**正确做法**
```
① 一次只处理 1~2 个包（最多 4 个，且要小包）
② 大包（itempack 1679 件）用 getIndex() 建索引 + 按 _id 分批 getDocument（每批 25~30）
③ 408 之后**先读回确认**（实测 408 的调用**其实已经写入**了），绝不重跑
④ 确认通道是否活着：跑 `return "活"` 这种极轻脚本
⑤ 长任务用「点火不 await + 结果写 game.__全局变量」
```

## B8 · 忘了设 `equipped` + `attuned` 就实测 —— 得出「修复无效」的错误结论

**现象**
给魔法物品补了 transfer 效果，装到测试桩上实测，发现**什么都没变** ⇒ 判定「修复无效」。

**根因**
**魔法物品的 `transfer:true` 效果需要「装备 + 同调」才生效。**
没设这两项，效果根本不应用。

**正确做法**
```js
await 桩.update({
  "system.equipped": true,
  "system.attunement": "attuned"     // 有些件还需要 system.attuned = 1
});
await new Promise(r => setTimeout(r, 300));   // DAE 写 flag 需要一拍
```

**触发信号**
> **实测结果 = 基线时，先怀疑测试环境，再怀疑数据。**

## B9 · 正则里 `+10` 没转义 —— 脚本直接报错

**现象**
```
Error executing script: Invalid regular expression: /(增加|提升|提高|+10|＋10)/: Nothing to repeat
```

**根因**
`+` 在正则里是量词，`+10` 被解析成「一个或多个 1」。

**正确做法**
```js
/(增加|提升|提高|\+10|＋10)/     // 或直接改用 indexOf / includes
```
**通用原则：判据里凡是搜「字面符号」的，一律用 `includes()` 或转义，不要裸写进正则。**

## B10 · `JSON.stringify(Set)` 恒为 `{}` —— 误判「键失效」

**现象**
读测试桩的 `traits.dr.value`，`JSON.stringify` 输出 `{}` ⇒ 判定「抗性键没写进去 / 键失效」。
此前**所有**「读 dr/ci 为空 ⇒ 键失效」的判断因此全部作废。

**根因**
`traits.dr.value` 是 **Set**，不是 Array。

**正确做法**
```js
Array.from(actor.system.traits.dr.value)      // ✅
[...actor.system.traits.dr.value]             // ✅
```
**同类坑**：`effects.statuses` 也是 Set。

## B12 · 用 `write` 工具建的 `.ps1` 没有 BOM —— 中文路径全乱码

**现象**
PowerShell 脚本里 `user` 变成 `榫欏崕`，所有路径操作失败。

**根因**
`write` 工具产出无 BOM UTF-8；PowerShell 5.1 按 GBK 解析。

**正确做法**
```powershell
$f = '脚本.ps1'
$c = [System.IO.File]::ReadAllText($f, [System.Text.UTF8Encoding]::new($false))
[System.IO.File]::WriteAllText($f, $c, [System.Text.UTF8Encoding]::new($true))
```

## B13 · 探针代码块带了 HTML 残留 —— 用户粘贴直接报错

**现象**
用户粘贴 F12 探针后报：
```
SyntaxError: Invalid regular expression: missing / (at VM4649:1:39)
```

**根因**
我给的代码块末尾带了 `</pre>` 之类的 HTML 残留，被一起粘进去了。

**正确做法**
> **代码块里只有代码，首尾不留任何标记、说明、空行外的字符。**

## B15 · 其他高频小坑（速查）

| 坑 | 现象 | 正确写法 |
|---|---|---|
| `const` 自增 | `Assignment to constant variable` | 用 `let` |
| 黑名单误伤 | `game.settings.set` 被拦 | 写 `game.settings["settings"]`（`game.settings.settings` 会命中） |
| 注释里写黑名单词 | 一样被拦 | 黑名单是**子串正则**扫全文，注释/字符串里也不行 |
| `game.modules` 直接 for..of | `.for is not iterable` | `game.modules.values()`（Collection 不是 Map） |
| `Item.system.activities` 当对象 | `Object.keys()` 恒 0，误判「没活动」 | `Object.values()` / `.contents` / `.get(key)` |
| `Actor#effects` 当全部效果 | 得到「效果全空」 | 用 **`actor.appliedEffects`**（transfer 效果不在 `effects` 里） |
| 技能熟练读 `proficient` | 恒 0 | 读 `system.skills.X.value`（0/1/2/0.5） |
| `attributes.spelldc` | 不存在 | dnd5e 5.3.3 无此字段，卡面 DC 是 UI 现算的 |
| `d.folder` 拿文件夹 | 不是 id | 用 `d._source.folder` |

# D 组 · 一句话总结这一路

| 错误类型 | 本质 | 统一解法 |
|---|---|---|
| 判断类（A 组） | **把假设当事实** | 三种外部锚点：官方包 / 规则书 / 实测 |
| 技术类（B 组） | **没有读回验证** | 改完必须独立读回，**尤其"跑完没变化"时** |
| 流程类（C 组） | **没有先勘察** | 先读 CHANGELOG + 资料库，再动手 |

**三条最贵的：**
1. **A1 没读 CHANGELOG 就批量改名** —— 整轮白做
2. **B1 `getIndex()` 用 `e.id`** —— 550 次静默全跳过，0 报错
3. **C1 不看资料库** —— 重新发明了三个月的积累

**一条通用自检句（写在每次交付前）**
> **「我这一版改动，能不能拿出对应的实测字段/读回结果？」**
> 拿不出 = 还在猜 = 不许交付。
