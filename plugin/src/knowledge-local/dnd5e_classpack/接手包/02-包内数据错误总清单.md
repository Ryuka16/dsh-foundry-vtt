# A 组 · 引用完整性（断链类）

## A1 · Plutonium 伪 uuid —— 110 件

**判据**：`uuid` 含 `plutonium-faux-id`（base64 段解码后形如 `{"tag":"spell","text":"jump"}`）

**发病条件**：世界未装 plutonium/5e-tools ⇒ `fromUuid` 返回 null ⇒ cast 活动的 `spell.uuid` 指向空气
⇒ **点「施放」无反应、不报错**。

**规模**：扫 4572 件 / 4707 处引用 ⇒ faux **285 处 / 110 件**，全在 `itempack` 的 cast 活动。

**修法**：建索引（`dnd5e_classpack.spell` 545 + `dnd5e.spells`，按名字去中文留英文 + `system.identifier`）匹配
→ 逐文档 `d.update({"system.activities": acts})`。**110 件全改、失败 0、读回复查 0 残留。**

**剩 6 处无解**（法术不在包内，跑批报错就是它们）：
老千牌组 `spray of cards|bmt`｜贤者印记(熊) `enlarge/reduce`｜头骨卡/头骨盔 `spirit of death|bmt`｜
小丑卡 `otto's irresistible dance`｜浪客斗篷 `antagonize|bmt`

## A2 · 引导神力消耗目标写死 uuid —— 23 件

**症状**：报「**无法找到由行动 X 配置在物品 Y 上的耗用项**」

**根因**：包内有两个**同名同 identifier** 的池：
```
v8z4Z2NuBAbYnjxk    uses.max = 1
WPevnsjK8Cjd9Fcl    uses.max = floor((@classes.cleric.levels+6)/12)+1
```
牧师 advancement 装的是**后者**，23 件子能力的 `consumption.targets[].target` 却写死**前者**的 uuid。

**修法**：target 全改 **identifier `channel-divinity`**（最稳的写法）。

**★ 机制**（dnd5e 源码 `Activity#_remapConsumptionTarget`）：
```js
if (!target || !this.actor || this.actor.items.has(target)) return target;
const {type} = foundry.utils.parseUuid(target) ?? {};
if (type === "Item") { const item = this.actor.sourcedItems?.get(target)?.first(); if (item) return item.id; }
else { const item = this.actor.identifiedItems?.get(target)?.first(); if (item) return item.id; }
return target;
```
⇒ 三种合法写法：**空串** / **物品 uuid** / **identifier**。判据只有一条：**能不能在这张 actor 上找到**。
官方还支持 `feat:<identifier>` 语法（如 `feat:bardic-inspiration`）。

## A3 · `triggeredActivityId` 填中文名 —— 20 处

**根因**：`midiProperties.triggeredActivityId` 只认 **活动 id / identifier / uuid**，**不认活动 name**
（源码 `getTriggeredActivity()` 三级回退）。填了中文名（「豁免」「治疗」「伤害」等）⇒ **永久不触发**。

**修法**：全改为活动 id 或 identifier。

# C 组 · 缺失类（官方有 ⟹ 本包必须有）

## C1 · 「+N 加值武器」全部缺攻击活动 —— 116 件

**规律极干净**：基础版有 1 活动，`+1/+2/+3` 全 **0 活动**；所有具名魔法武器正常。
**后果**：拖出来点它**没有攻击按钮**。

**修法**：按基础名建模板索引（`"长柄刀+3 Glaive +3"` → `"长柄刀"`），复制同族基础武器的 `system.activities`。
```js
const 键 = (s) => String(s).replace(/\s+/g, "")
  .replace(/[+＋][0-9１-９]/g, "").replace(/[（(].*?[)）]/g, "")
  .replace(/[A-Za-z].*$/, "").trim();
```
**结果 116/116 完成**（110 件模板配对 + 6 件单独处理：`月镰+1/+2/+3` 照抄镰刀 1d4 slashing；
`契约掌控者权杖+1/+2/+3` 照抄权杖 1d4 bludgeoning）。
**实测**：`长柄刀+3` 装到测试桩 ⇒ dnd5e 算出 **命中 +5 / 伤害 `1d10 + 6` / 射程 10 英尺** ✓

**回滚**：把 `system.activities` 清回空对象。

## C2 · 魔法护甲 AC 双算 —— 35 件

**机制**：dnd5e 算 AC = `armor.value + armor.magicalBonus`。
本包把魔法加值**算进了 value**，magicalBonus 又填一遍 ⇒ **双算**。

**A/B 实测**（测试桩；★ 必须先把 `ac.calc` 从 `natural` 改 `default`）：

| 件 | 本包（修前） | 官方同件 | 差额 |
|---|---|---|---|
| 链甲+1 | **AC 18** | 17 | +1 |
| 胸甲+3 | **AC 20** | 17 | +3 |

**规律 35/35 全中**：本包 value 精确等于 `官方 value + magicalBonus`。
**修法**：`d.update({ "system.armor.value": 官方基础值 })`，magicalBonus 不动。
**基础值取官方**：`dnd5e.items` 里筛「无 magicalBonus 的同名件」（**按归一化名 + magicalBonus 双键配对**），
**35 件全部有参照，无参照 0**。

**⚠️ 配对陷阱**：官方包同一归一化名下躺着 +1/+2/+3 三件，只按名字去重会把「胸甲+3」配到官方「胸甲+1」，凭空造 20 条假警报。

## E1 · 效果时长为空 ⇒ 0 秒立即掉

**★ 规则**（`ActiveEffect#_prepareDuration` 实测归纳）：
```
① 活动有实际时长  ⇒ 用活动的
② 活动是 inst     ⇒ 退回用**物品效果自己的 duration** ★ 最容易漏
③ 效果写 rounds/turns 而 game.combat 为 null ⇒ 显示「永久」
④ 两处都没写 ⇒ 0 秒立即掉
```

**实例**：奥术射击 8 矢里 **5 个带效果的矢有 4 个 duration 全 null** ⇒ **效果白做**。
已全补 `{seconds:6, turns:1}`（遮影矢 `xCgEhpLv8ObU3BDO` / 放逐矢 `XWt0kqSnDfv2f7L8` /
欺诈矢 `RaEpI8gByQ7DAmGN` / 虚弱矢 `59DnRL2TqhkaWMv5`）。

**修法模板**：
```js
const 新效 = o.effects.map(e => Object.assign({}, e, { duration: {...默认全null, ...目标时长} }));
const up = { effects: 新效 };
for (const k of Object.keys(o.system.activities))
  up["system.activities." + k + ".duration"] = 目标活动时长;
await d.update(up);
```

## G3 · 种族天赋法术缓存副本 —— 56 件

**用户报**：「提夫林给的炼狱叱喝可以一直使用」

**真根因**：dnd5e 自己会为 cast 活动建**缓存法术副本**（flags `dnd5e.cachedFor` 指向
`...Item.<featId>.Activity.<actId>`），`displayInSpellbook` 三要素 = `canUse ∧ magicAvailable!==false ∧ spell.spellbook`。
本包 120 条 cast 活动全是 `spellbook:true` ⇒ 副本被列进法术书与 midi 反应框，
而副本自己的 `uses.max` 为空 ⇒ **看着像无限次**。

**五次实测**：副本删了会重生；直接点火副本**会通过 `linkedActivity` 回扣 feat 次数**；次数耗完再点会被拦住。
⇒ **不是「能无限施放」，是「反应框一直显示一个没有次数的副本」。**

**修法**：`racial-traits` 里所有 `type === "cast"` 活动的 `spell.spellbook` 由 `true` 改 `false`（**56 件 / 120 条活动**）。

**★ 关键区分：L3+ 无 max 的 204 条全部正确、0 条真错** —— 龙纹法术 48 条与领域/结社/誓言 156 条
都是「加入施法职业法术列表」⇒ 用法术位、本来就无 max。**（用户「不要批量改」救下 156 件。）**

**官方金标准**：`dnd5e.races` 总共只有 12 个带 spell 的 advancement；天生法术一律
`method:"innate"` + `{max:"1",per:"lr"}`；戏法才是 max 空。

## 附 · 2026-10-09 新增：次数链断裂（全库 42 件 / 130 条活动）

### 错误形态
```json
"uses": { "max": "1", "recovery": [{"period":"lr","type":"recoverAll"}], "spent": 1 },
"consumption": { "targets": [] }        ← 空！
```
界面显示「1/日」，但**点了不扣**；且 `spent=1` 时**刚拿到就显示已用尽**。

### 两个子类
| 子类 | 现象 | 件数 |
|---|---|---|
| A · `spent` 被预设为 1（无消耗） | **拿到手就不能用**，直到第一次长休 | 17 条（全在 racial-traits） |
| B · 有次数但无消耗 | **可无限用** | 40 条（itempack 28 件：反魔法护甲 9 / 贤者印记 4 / 塔罗牌 7 / 权杖战镐等） |

### 修法（按次数池归属分流）
```js
// ① 物品级有 uses.max（整个特性每天 N 次）
活动.uses = { spent:0, recovery:[], max:"" };
活动.consumption.targets = [{type:"itemUses", value:"1", target:"", scaling:{}}];

// ② 物品级无 uses.max（每个法术各 N 次）
活动.uses.spent = 0;
活动.consumption.targets = [{type:"activityUses", value:"1", target:"", scaling:{}}];
```

### 包内正确先例（照抄这三件）
- `racial-traits/2k5hHvuqPQPhiw72` 控风操水(梭螺鱼人) —— 3 活动各 `activityUses` = **每法术各一次**
- `racial-traits/FInGZZmQ7IKxYjCH` 毒蛇魔法(MPMM原体蛇人) —— 同上
- `racial-traits/6CAUlJ4xOOVxkkLB` 魔法侦测(龙纹) —— `itemUses` = **共享一次**

### 附带：`uses.max` 写 `"@prof"`
描述说「次数等于你的熟练加值」而数据写死数字 ⇒ **全库 43 处**，改 `"@prof"`
⇒ 实测有效：装到 prof=1 的桩上，运行时 `max=1` / `label="长休后充能"`（dnd5e 在 prepareData 求值）
⇒ 包内先例：斯涅布力伪装 `racial-traits/l8j6Nk3L1VLLHbkn`（`uses=@prof`）
