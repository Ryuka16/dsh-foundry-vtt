## 三 · ★★★★ 本轮最大发现：**活动次数链断裂**（两类，全库 42 件 / 130 条活动）

### 病根
包内大量活动写成：
```json
"uses": { "max": "1", "recovery": [{"period":"lr","type":"recoverAll"}], "spent": 1 },
"consumption": { "targets": [] }        ← 空！
```
⇒ 界面显示「1/日」但**点了不扣**；要么无限用，要么**初始就是已用尽**。

### 两类错误

#### A · `spent` 被预设为 1（17 条 / 全在 racial-traits）—— 最严重
**现象**：活动 `uses.spent = 1` ⇒ **拿到手就是「已用尽」状态，直到第一次长休才能用**。
命中：费尔伯格人魔法×4条 ｜ 死灵环绕(EGW阿斯莫)×2 ｜ 治愈之手×2 ｜ 光辉焚化×2 ｜ 混入大地×3（MPMM/元素裔/EGW）｜ 烈焰之触×2（元素裔/EGW）｜ 呼唤波浪×2（MPMM/元素裔）
⇒ **已全部修**：`uses.spent → 0` + `consumption.targets → [{type:"activityUses",value:"1",target:"",scaling:{}}]`

#### B · 活动有次数但无消耗（itempack 40 条 / 28 件）—— 无限用
**样本核实**：
- 反魔法板条甲：描述「此属性一旦被使用，直到次日黎明前都无法被再次使用」⇒ 活动 `max:1/回日` 但 `消耗=[]` ⇒ 可无限放
- 贤者印记(雄鹿)：6 个 cast 活动（3 个 max:1/日 + 3 个无次数）⇒ 同上
- 太阳卡：描述「一经使用，直到次日黎明之前无法再次使用」⇒ 同上
- 水晶刀锋：物品 `uses.max="3" / dawn / formula 1d3`（权威）而活动也写 `max:3/dawn/recoverAll`（**两者不一致**）

**修法（按物品级是否有计数分流）**：
```js
if (物品级 uses.max 有值) {
  // 物品级才是权威计数 ⇒ 活动 uses 清空，消耗指向物品
  活动.uses = { spent:0, recovery:[], max:"" };
  活动.consumption.targets = [{type:"itemUses", value:"1", target:"", scaling:{}}];
} else {
  // 物品无计数 ⇒ 保留活动 uses，消耗活动自己的
  活动.uses.spent = 0;
  活动.consumption.targets = [{type:"activityUses", value:"1", target:"", scaling:{}}];
}
```
⇒ itempack 28 件 / 40 条修完；后续两轮补扫再修 11 条 + 103 件，**全库残留 0** ✓

   ```powershell
   $c = [System.IO.File]::ReadAllText($f, [System.Text.Encoding]::UTF8)
   [System.IO.File]::WriteAllText($f, $c, (New-Object System.Text.UTF8Encoding($false)))
   ```
