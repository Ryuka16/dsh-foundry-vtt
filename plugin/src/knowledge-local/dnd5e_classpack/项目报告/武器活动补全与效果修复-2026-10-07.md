  **116 件纯 `+N` 加值武器**全部 **0 活动**

### 修复（照抄同族基础武器的 attack 活动）

```js
const 键 = (s) => String(s).replace(/\s+/g, "").replace(/[+＋][0-9１-９]/g, "")
  .replace(/[（(].*?[)）]/g, "").replace(/[A-Za-z].*$/, "").trim();   // "长柄刀+3 Glaive +3" → "长柄刀"
// 1. 收集所有有活动的武器 → 按「基础名」建模板索引
// 2. 对每件无活动武器，按同样规则找模板
// 3. 复制模板的 activities（清 _stats / flags），d.update({ "system.activities": 新 })
```

- **结果**：**116/116 全部补上，剩余无活动武器 0**（其中 110 件走模板配对，6 件无基础版单独处理）

### 4.2 判据的可靠顺序（本轮实测确立）

1. **运行时实测**（造临时效果 → 读派生值 → 对照「不存在的键」做空白对照）—— **唯一算数**
2. midi-qol **官方 flag 文档**（`飞书知识库-全文\   midi Flags介绍.md`）
3. dnd5e 源码里的 `ActiveEffect5e.FORMULA_FIELDS` 白名单 + 迁移映射表
4. actor schema 递归 —— **只能当「可疑清单生成器」，不能当结论**

### 4.3 schema 遍历的正确写法（踩过一次）

```js
// ✗ 错：根写成 schema.fields，循环里又取 .fields ⇒ 双重间接 ⇒ 全部误报「断在 attributes」
const 根 = a.system.schema.fields;  层 = 根; … 层.fields[段[i]]
// ✓ 对：根就是 schema 本体
let 层 = a.system.schema;
const 子 = 层 && 层.fields ? Object.keys(层.fields) : null;   // MappingField/SetField 无 .fields ⇒ 当叶子
if (!子) return { ok: i === 段.length - 1 };
```

### 本轮踩的坑（全部实测）

1. **schema 遍历起点写错一层** ⇒ 全部误报「断在 attributes」，`可用:` 为空是信号
2. **`getDocument(硬编码 id)` 可能返回 null** ⇒ `Cannot read properties of null (reading 'toObject')`
3. **对象字面量键名/标识符不能带「」①② 等标点** ⇒ `Invalid or unexpected token`

   分批（15~25 件/次）+ 用「无活动」当幂等过滤条件最稳

### 8.3 ★ 新发现：compendium 内嵌效果的**删除不生效**

给这 4 件加效果后，物品里同时存在「原空壳 + 新效果」。**想删原空壳，两种写法都无效**：

```js
await d.update({ effects: 留 });                 // ✗ 传更短的数组 ⇒ 读回仍是 2 个
const up = {}; up["effects.-=" + 旧id] = null;
await d.update(up);                              // ✗ 未抛错，读回仍是 2 个
```

（同类现象此前记录为「僵尸物品」：`actor.items.get(id)` 拿得到，但 `delete()` / `deleteEmbeddedDocuments` 都报不存在。）

**⇒ 无害认定**：该空壳 `transfer:false` **且活动已不再引用它** ⇒ **永远不会被施加** ⇒ 不影响任何行为。
**⇒ 注**：`火焰护盾 / 指使术 / 支配野兽` 原本 0 效果，不受影响（只有新加的那 1~2 个）。
**⇒ 影响的只有原本已带 1 个空壳的那 4 件**，各留 1 个惰性空壳。

### 8.4 ★★ 判据再修正：读「键自己」不算数，要读**派生值**

验证 `system.attributes.ac.bonus` 是否有效时发现：

| 测法 | 结果 |
|---|---|
| 写假键 `system.bonuses.nosuch` m2=1，然后读**键自己** | `system.bonuses.nosuch = 1` ← **假键也能读到值！** |
| 写 `system.attributes.ac.bonus` m2=5，读**派生值** `system.attributes.ac.value` | AC 10 → **15** ✓ |
| 写假键 `system.attributes.ac.nosuchbonus` m2=5，读**派生值** | AC **10（无变化）** ✓ 对照成立 |

**⇒ DAE 只是把 change 写进 data，读「键自己」永远有值。**
**⇒ 唯一有效的测法：写 change → 读一个会被它影响的**派生值**（AC / 移动力 / 抗性集合…）→ 同时用假键做空白对照。**
