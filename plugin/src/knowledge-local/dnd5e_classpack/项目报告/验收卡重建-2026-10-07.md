## 二 · ★ 建卡三坑（全部实测钉死）

### 坑 1：`HitPoints.apply(L, {}, {initial:true})` 会静默不写值 → HP 0/0

dnd5e 源码判据：

```js
async apply(level, data, options={}) {
  if ( options.initial ) {
    if ( (level === 1) && this.item.isOriginalClass ) data[level] = "max";
    else if ( this.value[level-1] === "avg" ) data[level] = "avg";
  }
  ...
}
```

- L=1 走第一支 ⇒ 写 `"max"`
- L=2 判 `this.value[1] === "avg"` ⇒ 实际是 `"max"` ⇒ **不成立** ⇒ `data[2]` 不写
- 之后每一级同样不写 ⇒ **HP 恒为 0**

**修法**：不带 `initial`，显式传值 ——

```js
if (t === "HitPoints") { const d = {}; d[L] = (L === 1) ? "max" : "avg"; await adv.apply(L, d, {}); }
```

**验证（战斗大师 L20）**：HP `0/0` → **`164/164`**
人工验算：L1 max 10 + con 2 = 12；L2~20 avg 6 + con 2 = 8 × 19 = 152；合计 **164** ✅
AC 13 = 10 + dex 3 ✅

### 坑 2：没有职业 ⇒ 没有等级 ⇒ 没有 HP

「一级的简单卡」若只塞种族/背景物品，卡上没有 class item ⇒ 没有 level ⇒ 没有 HitPoints advancement ⇒ HP 0/0，整张卡处于「未准备」状态，**卡面什么都不显示、资源全空**。

**症状误导性极强**：用户看到的是「战斗大师没有回气、没有血量、什么都没有，只有几个子职特性」—— 实际物品都在（9 件：战士/战斗风格/回气/动作如潮/武术范型/战斗大师/替换武术/额外攻击/不屈），坏的是 prepareData。

**修法**：种族卡、背景卡一律带一个 L1 战士（用户钦定「职业随便选」）。

### 坑 3：并发跑批会互相拖

## 三 · 属性叉开方案（用户要求）

所有验收卡统一用同一套叉开的属性，覆盖正负调整值：

| 属性 | 值 | 调整值 |
|---|---|---|
| 力量 STR | 18 | **+4** |
| 敏捷 DEX | 16 | **+3** |
| 体质 CON | 14 | **+2** |
| 智力 INT | 12 | **+1** |
| 感知 WIS | 13 | **+1** |
| 魅力 CHA | 9 | **−1** |

```js
const ab = {}; for (const k of ["str","dex","con","int","wis","cha"]) ab[k] = { value: this.属性[k] };
await Actor.create({ name, type: "character", folder, system: { abilities: ab } });
```

**用途**：AC 是否正确 = 10 + dex 3 = 13 ✅；HP 是否正确 = 叠 con 2 ✅；任何把调整值算错的自动化都会露馅。

## 四 · 建卡流程（「正常升级路线」的脚本化）

```js
// 1. 建卡（先设属性，再塞物品）
const 卡 = await Actor.create({ name, type: "character", folder, system: { abilities: ab } });
await 卡.createEmbeddedDocuments("Item", [职业文档.toObject(), 种族/背景/专长文档.toObject()]);

// 2. 逐级升级（L=1..20）
let 职物 = 卡.items.find(i => i.type === "class");
for (let L = 1; L <= 20; L++) {
  await 职物.update({ "system.levels": L });      // 触发该级重算
  职物 = 卡.items.get(职物.id);
  await 跑级(职物, L);                             // 跑该级的 advancement
  if (L === 3 && 子职文档) {
    const sb = 职物.system.advancement.contents.find(a => a.type === "Subclass");
    await sb.apply(3, { uuid: 子职文档.uuid }, {}); // ★ 不带 initial（带 initial 会直接 return）
  }
}

// 3. 兜底设满 HP
const mx = 卡.system.attributes.hp.max; if (mx > 0) await 卡.update({ "system.attributes.hp.value": mx });
```

### 逐级跑的分派规则（`跑级`）

```js
for (const adv of 物.system.advancement.contents) {
  const t = adv.type;
  if (t === "Subclass" || t === "ScaleValue" || t === "Size") continue;
  let 跑 = false;
  if (t === "HitPoints") 跑 = true;                       // 每级都跑
  else if (t === "ItemChoice") 跑 = !!(adv.configuration && adv.configuration.choices &&
        adv.configuration.choices[L] && typeof adv.configuration.choices[L].count === "number");
  else 跑 = Number(adv.level || 0) === L;                  // ItemGrant / Trait / ASI
  if (!跑) continue;
  if (t === "ItemGrant" || t === "ItemChoice") await adv.apply(L, {}, { initial: true });
  else if (t === "Trait") { const au = await adv.automaticApplicationValue(L, { initial: true }); if (au) await adv.apply(L, au, { initial: true }); }
  else if (t === "HitPoints") { const d = {}; d[L] = (L === 1) ? "max" : "avg"; await adv.apply(L, d, {}); }
  else if (t === "AbilityScoreImprovement") await adv.apply(L, { type: "asi", assignments: { str: 2 } }, {});
}
```

**关键点**：
- `ItemChoice` 的等级**不能读 `adv.level`**（实例上是 undefined），要取 `configuration.choices` 里最小/命中的键
- 种族/背景的 advancement 等级是 **0**（不是 1），跑的时候直接传 `Number(adv.level || 0)`
- 种族的 L3/L5 法术授予要按 `adv.level <= 角色等级` 过滤
