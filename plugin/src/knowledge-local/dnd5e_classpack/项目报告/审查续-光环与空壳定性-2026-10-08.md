## 三 · 本轮真修（2 处，均有确凿依据）

### 修复 1 · 天眼通第 4 个效果是空壳，本该是「识破隐形」
**依据**：描述列出 **4 个选项**（黑暗视觉 / 灵视 / 高等理解力 / **识破隐形**），但只挂了 3 个有内容的效果 + 1 个完全空壳：
```
LQkOybEAjuLsMc61  名="天眼通"  changes=[]  flags={}
```
**修法（纯新增，不删任何东西）**：
```js
e1.name = "识破隐形 See Invisibility";
e1.changes = [{ key: "system.attributes.senses.special", mode: 5, value: "识破隐形 10尺", priority: 20 }];
e1.flags = { dae:{...同黑暗视觉...}, dnd5e:{riders:{statuses:[]}}, core:{overlay:false}, ActiveAuras:{...} };
```
**字段依据**：实测 `CONFIG.Actor.dataModels.character.schema.fields.attributes.fields.senses` 的键 = **`["ranges","units","special"]`**，`special` 是 StringField（可自由文本）。因是 StringField，**必须用 mode 5 (OVERRIDE)**（mode 2 会被解析成 `min(a,b)` —— 历史实测）。

**读回验证**：4 个效果名 = `黑暗视觉Darkvision` / `灵视Ethereal Sight` / `高等理解力Greater Comprehension` / **`识破隐形 See Invisibility`** ✓，数量仍为 4。

> 注：「灵视Ethereal Sight」（以太位面视觉）仍为空 —— dnd5e 感官只有 `darkvision / blindsight / tremorsense / truesight` 四种，**确实无字段**，描述里已注明。

## 四 · ★★★ 第 5 条判据被实测推翻（并纠正了我自己的一个错）

### 判据：「描述含『施法距离内』但活动级 `range.units === "self"`」⇒ **全是误报**
扫 7 包，命中 60+ 件（怪影杀手 / 植物滋长 / 缓慢术 / 粉碎音波 / 燃烧之手 / 传讯术 / 弱智术 …）。

**实测对照（决定性）**：

| 件 | 物品级 range | 物品级 template | 活动级 range | 活动级 template |
|---|---|---|---|---|
| 粉碎音波 | `60 ft` ✓ | `sphere/10` ✓ | `self` | 空 |
| 缓慢术 | `120 ft` ✓ | `cube/40` ✓ | `self` | 空 |
| 燃烧之手 | `self` ✓（本应自身） | `cone/15` ✓ | `self` | 空 |
| 弱智术 | `150 ft` ✓ | — | `self` | 空 |
| 传讯术 | `120 ft` ✓ | — | `self` | 空 |

⇒ **`活动级 range=self + 空模板` 是 dnd5e 的正常形态** —— 活动不覆盖时**继承物品级**。
⇒ 判据错误，**不能用于批量修改**。

### ★ 我自己的错（已纠正并回滚）
我按这条错判据先改了焚云术/暗黑星辰的**活动级**：
```
焚云术 活动级 range → 150ft，template → radius/20
暗黑星辰 活动级 range → 150ft，template → radius/40
```
⚠️ **物品级本来就是 `sphere/20`、`sphere/40`；我把活动级覆盖成了 `radius` —— sphere（球形，3D）与 radius（半径圆形，2D）是两个不同模板，这是把正确的改坏了。**

**回滚（两次才成功）**：
- 第一次失败：`system.activities.<key> = 对象` 是 **ObjectField 合并** —— 我传的对象缺字段（没带 `value`），旧值 `"150"` / `type:"radius"` **被保留**。
- 第二次成功：**显式传空值** `range={override:false,units:"self",value:"",special:""}`、`template={contiguous:false,units:"ft",stationary:false,type:"",size:"",count:""}`。

**回滚后实测**：活动级已还原 ✓；物品级 `range 150ft` / `template sphere/20`、`sphere/40` 完好 ✓；活动数与效果数均未变（1 / 1）。

> **教训**：改 `system.activities` 子字段时，**合并语义下必须显式给空值才能清空**；覆盖前必须先把「物品级 + 活动级」两层都读出来。

## 六 · 本轮踩坑（技术，可复用）

1. **正则里的中文全角括号** —— `（?的)?` 括号不匹配 ⇒ `Invalid regular expression: Unmatched ')'`。写中文正则时**一律用 `(?:...)` 非捕获组**，别混全角括号。
2. **`system.activities.<key> = 对象` 是合并不是替换** —— 缺字段的旧值会保留，**清空必须显式给空值**。
3. **`活动级 range/template 为空` ≠ 缺数据** —— 它继承物品级，覆盖它反而会改坏（sphere → radius）。
4. **`CONFIG.RegionBehavior.typeDefinitions` 是空的** —— 行为类型实际在 **`foundry.data.regionBehaviors`**（10 个类）。
5. **`executeScript` 的脚本是 `放置时固化`** 的（RegionBehavior 源码 `helpers.js` 把 behaviors 数组复制进 Region），改物品上的脚本**不影响已放置的 Region**。
6. **判据命中数超过个位数 ⇒ 先怀疑判据**（本轮第 5 次被验证：60+ 命中 / 0 真错）。
