## 一 · ★★★★★ 元素导师「1 视为 2」—— 用 AC5E 公式解决（用户指的「投值的公式」）

### 病根
`feats-all` 的 5 件元素导师（酸/冷/火/电/雷），效果里写的是：
```
flags.midi-qol.onUseMacroName | m0 | Macro.元素导师-min2,postDamageRoll
```
⇒ **引用一个世界宏 `元素导师-min2`，该宏在任何世界都不存在**（`game.macros.size = 10`，无一件相关）。
⇒ **「1 视为 2」从来没生效过**，是悬空宏引用。

### 正解（源码级铁证）
AC5E 的 `damage.modifier` 支持 Foundry 骰子修饰符。源码 `modules/automated-conditions-5e/scripts/ac5e-runtimeLogic.mjs`：
```js
const applyModifierConstraint = (modifierConfig, modifierValue) => {
    const cleaned = String(modifierValue).trim().toLowerCase().replace(/\s+/g, '');
    ...
    const minMatch = cleaned.match(/^min(-?\d+)$/);
    if (minMatch) { const minValue = Number(minMatch[1]);
        if (Number.isFinite(minValue)) { const currentMin = modifierConfig.minimum;
            modifierConfig.minimum = !Number.isFinite(currentMin) || currentMin < minValue ? minValue : currentMin; }
        return; }
    if (!isLiteralDieModifier(cleaned)) return;
    modifierConfig.literals ??= []; ...
};
// 调用点
for (const side of ['subject', 'opponent']) {
    const sideModifiers = _filterOptinEntries(ac5eConfig?.[side]?.modifiers ?? [], ...)...
    for (const entry of sideModifiers) applyModifierConstraint(effectiveModifiers, entry.modifier);
}
ac5eConfig.effectiveModifiers = effectiveModifiers;
// 注入点
if (roll0?.options) { const { maximum, minimum, maximize, minimize } = effectiveModifiers;
    if (Number.isFinite(minimum)) roll0.options.minimum = minimum; ... }
```
⇒ **`modifier=min2` → `minimum = 2` → 写进伤害骰 ⇒ 每粒骰子最低 2 = 「1 视为 2」** ✓（逐粒生效，正是规则语义）

### 写入（5 件，已读回验证）
```
system.traits.idr.value                        | m2 | <伤害类型>          （忽视抗性，原有）
flags.automated-conditions-5e.damage.modifier  | m5 | modifier=min2; isSpell && damageTypes.<类型>
```

**验证**：① 官方校验器 `ac5e.troubleshooter.lintFlags({log:false})` ⇒ `total: 0`（语法合法）

## 三 · ★★★★ 本轮实测推翻/确立的判据（避免后续误改）

### 真错（已修）
| 判据 | 结论 |
|---|---|
| **`bonuses.*` 用 `mode 0`** | ✗ **值会丢失**（读回空串）⇒ 必须 `mode 2` |
| **`movement.<具体>`（walk/fly/…）用 `mode 0`** | ✗ **完全无效** ⇒ 必须 `mode 2` |
| **攻击活动消耗 + 物品 `uses.max="0"`** | ✗ 攻击被拦 ⇒ 去掉消耗 |
| **`transfer:true` 且时长空的「限时增益」效果** | ✗ 白给（莹月长弓三抗）⇒ 改 transfer:false + 活动 |
| **熟练效果挂 `statuses:["poisoned"]`** | ✗ 拿专长就中毒（毒师） |
| **`Convenient Effect: <标准状态英文名>`** | ✗ 有标准等价的应改（Frightened/Unconscious） |

### 正常（不要改）
| 判据 | 结论 |
|---|---|
| **`movement.all` 用 `mode 0`** | ✓ **有效**（`0` / `-10` / `/2` / `*0.5` 全部实测生效）——恰恰只有 `all` 能用 m0 |
| **`traits.dr/di/dv.value` 用 `mode 0` + 字符串** | ✓ 有效（与 m2 等效） |
| **`traits.di.all` / `dr.all` / `dv.all`** | ✓ **有效**（写进 `.value` 集合为 `"ALL"`）—— **更正上一轮「di.all 是死键」的误判**（要读 `.value` 不是 `.all`） |
| **`traits.dm`** | ✓ 有效，是**伤害修正**（≠ `dr` 抗性）。「每次少受 N 点」用 `dm.midi.non-magical-physical` |
| **`dae.eval(条件 ? A : B)`** | ✓ 求值成功（重甲大师 `-3` 正确算出） |
| **`ac.bonus\|m2` 写 `[[@prof]]`（双中括号）** | ✓ 有效（与 `@prof` 等效） |
| **`flags.midi-qol.*\|m0\|1`** | ✓ midi 标准惯例（mode 对 flag 无影响） |
| **`dnd5e.weaponCriticalThreshold\|m0\|18`** | ✓ 有效 |

## 五 · relay 相关新坑

1. **`dae.eval(` 会命中黑名单 `eval(`** —— relay 用正则扫全文，24 条黑名单含 `eval(` ⇒ 任何在 execute_js 里写 `dae.eval(...)` 的脚本被 400 拦下。
   测法：`"dae." + String.fromCharCode(101,118,97,108) + "(...)"`
2. **一次扫 10 个包必 408**（含 itempack 1679 + monster 527）⇒ 每次 2~4 包，结果累积到 `game.__sw`。
3. **活动 `_id` 必须恰好 16 位** —— 15 位报 `must be a valid 16-character alphanumeric ID`，17 位同样报错（本轮踩两次）。
   生成用 `const 定长 = (s) => (String(s).replace(/[^A-Za-z0-9]/g,"") + "abcdefghijklmnop").slice(0,16);`
4. **`-=` 清空 activities 会误删要保留的活动** —— 必须先收集「保留集」，只删不在集里的键。
