### ★★ 本轮最重要发现：删活动必须用「源键」
`冲锋手` 残留的旧 utility **两种删法都无效**（`activities.get(id).delete()` 与 `{"-=<集合id>": null}`）。
诊断：
```js
Object.keys(d.toObject().system.activities)   // ["rNiGvvIvca0mZIh4", "Kwl7HF2CAh5y05Zx"]  ← 源键（桶键）
Array.from(d.system.activities.keys())        // ["3uGpSXvaVJLPmu4R", "Kwl7HF2CAh5y05Zx"]  ← 集合键
d.toObject().system.activities["rNiGvvIvca0mZIh4"]._id  // "3uGpSXvaVJLPmu4R"  ★ 源键 ≠ 内层 _id
```
⇒ **源里的字典键是「桶键」（常为 `dnd5eactivity000`），真 id 在内层 `_id`**；集合按内层 `_id` 建 ⇒ `-=<集合键>` 是空操作 ⇒ 整次 update 被判「无变化」而跳过，**不报错**。
✅ 正解：
```js
const 源 = d.toObject().system.activities || {};
const 源键 = Object.keys(源).find(k => (源[k] || {})._id === 要删的集合id);
await d.update({ "system.activities": { ["-=" + 源键]: null } });
```
**全库规模：四特性包 1625 件中源集错位 27 件**（22 个「卓越技巧战技」副本 + 野兽之形 + 25 个战技 + 灵巧动作 `cc0000…` + 树林之子 `aa0000…` + 巫咒魔法 `bb0000…`）。
**功能无损**（dnd5e 正常），**唯一后果就是脚本里按集合 id 删活动会静默失效** ⇒ 不批量重写，但脚本必须走反查写法。

### 连带：边遍历边删会漏删
`for (const a of d.system.activities.contents) await d.system.activities.get(a.id).delete();` **会漏**（集合在迭代中被改动）。
✅ 先 `const ids = d.system.activities.contents.map(a => a.id);` 快照再删 —— 这正是冲锋手残留的直接原因。

### 关键结论（已写入血泪教训第三十五节 + SKILL `fvtt-dnd5e-cast-cached-spell-level-gate`）
1. 判「法术太多」第一步永远是查 **`flags.dnd5e.cachedFor`**（区分真法术与 cast 缓存）
2. **cast 缓存法术在物品创建时全建，与等级无关**
3. **`visibility.level.min` 是唯一补救字段**（挡法术书 + 挡按钮，但缓存物品本身还在）
4. **删 cast 活动 = 该缓存自动从法术书消失**
5. **有明确等级阶梯的用 cast + min；纯扩充列表的用 ItemGrant 分档**
6. **改模块原件不影响已拖出的副本** —— 卡上副本必须单独处理
