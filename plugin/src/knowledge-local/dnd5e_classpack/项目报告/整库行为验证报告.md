## 一、今晚解决的核心问题

### ★★★ headless 行为验证：从「完全跑不通」到「901 件批量可跑」

**背景**：用户抽检 16 件抓出 11 件有问题（69%），而我的验证能力只到「数据落库」——因为 Foundry 的自动化**跑不出真实工作流**，我只能确认「写进去了」，无法确认「用起来对不对」。

**现在**：脚本能驱动 `activity.use()`、workflow 能完整跑完（中位 **1037 ms/件**），可以实现「真机跑一遍看有没有产出」。

**卡了 10 轮、否定了 10 个假设。三个真卡点全部有源码级证据：**

| # | 卡点 | 症状 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | **`game.user.targets` 超限** | `use()` 131ms 返回 `undefined`，`performState` 一次都不调用 | 目标数 > 活动 `target.affects.count` ⇒ midi 直接拒绝（报错被吞） | 跑前清 targets，只留目标 |
| 2 | **`message.create:false`** | workflow 冻在 `WaitForSaves`，无弹框、无报错、钩子 0 次 | `displaySaveTargets` 读 `.content` 崩 ⇒ 被 `performState` 的 catch **静默吞掉** | 第三参 **`{create:true}`** |
| 3 | **`doReactions`** | 卡在反应判定 | 世界 `doReactions:"allMI"` | 物品 flag + `workflowOptions.noProvokeReaction` |

**跑批中追加发现的 3 个：**

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 4 | `WaitForDamageRoll` 卡死 | `getAutoRollDamage(this)==="none"` ⇒ `shouldRollDamage=false ⇒ return Suspend` | `workflowOptions.autoRollDamage="always"` + `fastForwardDamage=true` |
| 5 | `NoAction` 卡死 | `setTargets` 里 `target.affects.choice===true` 弹 targetConfigurationDialog | 清 `affects.choice=false` + `workflowOptions.targetConfirmation="never"` |
| 6 | `displayDamageRolls \| no chat message` | **我的清理代码删聊天卡删早了**（workflow 还在等伤害骰） | 等 `workflows.size===0` 再清；超时先 `w.abort=true` |

**顺带查清的 4 条硬事实**：
- 压掷骰框的钩子名是**动态拼**的 `dnd5e.preRoll${name}V2` ⇒ 真名 **`dnd5e.preRollSavingThrowV2`**（带 V2），明文 grep 找不到
- `failedSaves = 1` 是**初始化值**（`this.failedSaves = new Set(this.hitTargets)`），不是掷骰结果；真判据是 `saves.size`
- **拿被吞异常的唯一途径 = `MidiQOL.TroubleShooter.errors`** —— 这一条本可以省掉 3 小时
- CPR 的 `DialogApp` 有 `submit(result)` API，可写**不依赖压缩类名**的自动提交器（靠「实例有 submit + 有 form」识别）

### ★★ CPR「显示已配置但是坏的」根因
- **显示层** `flags["chris-premades"].info` ≠ **执行层** `flags["chris-premades"].macros`
- 全库 497 件认领件里，只有 `info` 没 `macros` 的 = **徽章亮、宏永不跑**
- 已补：`macros` 绑定 **364 件** + `activityIdentifiers` **351 件**
- CPR 匹配靠**名字精确相等** ⇒ 模块物品名是「中文English」拼接 ⇒ 永远匹配不上（这就是用户说的「改名重新匹配才好」）
- **`rules→2024` 评估结论：不做** —— 只多救 16 件（368 件 legacy 表本来就有宏），代价是动 497 件的显示值

## 五、可复用的最终配方（抄这个）

```js
// 一次性
const cfg = MidiQOL.configSettings();
cfg.doReactions = "none"; cfg.rollNPCSaves = "auto"; cfg.rollNPCLinkedSaves = "auto";
const 钩 = (c, d) => { try { d.configure = false; } catch (e) {} };
for (const h of ["dnd5e.preRollSavingThrowV2","dnd5e.preRollSkillV2","dnd5e.preRollAbilityCheckV2",
                 "dnd5e.preRollAttackV2","dnd5e.preRollDamageV2","dnd5e.preRollToolV2"]) Hooks.on(h, 钩);
// 每件
canvas.tokens.placeables.filter(t => t.isTargeted && t.id !== 桩.id).forEach(t => { try { t.setTarget(false); } catch(e){} });
桩.setTarget(true, { releaseOthers: true });
await MidiQOL.Workflow.clearWorkflows();
const 物品 = (await actor.createEmbeddedDocuments("Item", [src.toObject()]))[0];
await 物品.update({ "flags.midi-qol.noProvokeReaction": true });
const 改 = {};
for (const a of 物品.system.activities.contents) {
  const o = a.toObject();
  if (o.type === "summon") continue;
  o.consumption = Object.assign({}, o.consumption||{}, { targets: [], spellSlot: false });
  if (o.target) o.target = Object.assign({}, o.target, {
    template: {}, prompt: false,
    affects: Object.assign({}, o.target.affects||{}, { choice: false }) });
  if (o.midiProperties) o.midiProperties = Object.assign({}, o.midiProperties, {
    autoTargetAction: "none", forceRollDialog: "never", forceConsumeDialog: "never",
    forceDamageDialog: "never", forceConfigDialog: "never" });
  改[o._id] = o;
}
await 物品.update({ "system.activities": 改 });
a.use({ scaling: false, create: {},
  midiOptions: { targetsToUse: new Set([桩]), ignoreUserTargets: true, configureDialog: false,
    fastForwardAttack: true, fastForwardDamage: true, fastForwardHeal: true,
    workflowOptions: { noProvokeReaction: true, autoRollDamage: "always", fastForwardDamage: true,
                       autoRollAttack: true, fastForwardAttack: true, targetConfirmation: "never" } } },
  { configure: false },
  { create: true, rollMode: "gmroll" });        // ★ create 必须 true
// 等结束 → 等 workflow 全死 → 再清理
```
