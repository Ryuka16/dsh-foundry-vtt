## 一 · ★★★ 重大：35 件魔法护甲 AC 双算（已修 + 实测闭环）

### 判据
dnd5e 的 AC 算法是 **`armor.value + armor.magicalBonus`**（官方件实测证实）。
本包把魔法加值**算进了 `armor.value`**，`magicalBonus` 又填了一遍 ⇒ **双算**。

### A/B 实测铁证（测试桩 `Actor.E4OlKBqN2dFen4ZX`，需先把 `system.attributes.ac.calc` 从 `natural` 改 `default`）

| 件 | 本包（修前） | 官方同件 | 差额 |
|---|---|---|---|
| 链甲+1 Chain Mail +1 | **AC 18** | AC 17 | +1 |
| 胸甲+3 Breastplate +3 | **AC 20** | AC 17 | +3 |

装备后读 `actor.system.attributes.ac.value`；修后复测 **本包 17 = 官方 17**（两件都一致）。

### 规律（35/35 全中，无一例外）
`本包 armor.value` **精确等于** `官方 armor.value + magicalBonus`：

```
链甲+1    v17→应16 mb1 ｜ 镶钉皮甲+3 v15→应12 mb3 ｜ 半身板甲+2 v17→应15 mb2
链甲衫+2  v15→应13 mb2 ｜ 鳞甲+1   v15→应14 mb1 ｜ 布甲+3   v14→应11 mb3
胸甲+3    v17→应14 mb3 ｜ 盾牌+2   v4 →应2  mb2 ｜ 鳞甲+2   v16→应14 mb2
皮甲+1    v12→应11 mb1 ｜ 板条甲+2 v19→应17 mb2 ｜ 半身板甲+3 v18→应15 mb3
环甲+3    v17→应14 mb3 ｜ 板条甲+3 v20→应17 mb3 ｜ 链甲+3   v19→应16 mb3
盾牌+3    v5 →应2  mb3 ｜ …… 共 35 件
```

### 修法
`d.update({ "system.armor.value": 官方基础值 })`，`magicalBonus` **不动**。
基础值取法：官方包 `dnd5e.items` 里**无 magicalBonus** 的同名件（按归一化名配对），35 件**全部有参照，无参照 0**。

### 修后验证
```
残留双算 = 0
链甲+1 → 本包AC=17 官方AC=17
胸甲+3 → 本包AC=17 官方AC=17
测试桩已还原（calc 回 natural、0 物品残留）
```

**包内 utility 法术活动模板**（10/10 完全一致的约定）：
```json
{ "type":"utility",
  "activation":{"type":"action","value":null,"override":false},
  "consumption":{"targets":[],"scaling":{"allowed":false,"max":""},"spellSlot":true},
  "duration":{"units":"inst","concentration":false,"override":false},
  "range":{"override":false,"units":"self"},
  "target":{"prompt":true,"template":{"contiguous":false,"units":"ft","stationary":false},"affects":{"choice":false},"override":false},
  "effects":[], "roll":"" }
```

⇒ **活动级一律 `inst` + `self`，与物品级无关**（物品级的 range/duration 才是真的）。
⇒ 物品级 `activation` 是另一回事：1 分钟施法写 `{type:"minute",value:1}`，1 动作写 `{type:"action"}`——三件都本来就对。

## 七 · 本轮踩坑

1. **测试桩 `ac.calc = "natural"` 会让所有护甲 AC 测试失效**（AC 恒 = 10）⇒ 测护甲前必须先临时改 `system.attributes.ac.calc = "default"`，测完还原。第一次测就栽在这，得出「装本包=装官方=10」的无效结论。
2. **同名配对必须带 `magicalBonus` 做键**：官方包同一归一化名下躺着 +1/+2/+3 三件，只按名字去重会把「胸甲+3」配到官方「胸甲+1」，凭空造出 20 条假警报。
3. **`pid.slice(16)` 是 bug**：数组里存的是短包名，`"itempack".slice(16)` 恒为 `""`。要想拿包名就直接用 `pid`。
4. **`计划.slice(15)` 的 off-by-slice**：修完一批后，已修的条目已不在新名单里，再 `slice(15)` 会**静默跳过剩余全部**。改为直接遍历全量。
5. 规则书查询走 `00_规则资料\5E 不全书-纯文本\`（grep 出文件名+行号再 read），别翻 HTML 原库。
