## 三 · 运行时验证证据（不是「写进去了」，是「真的生效」）

> 铁律：**键是否生效只有运行时实测能判**。曾有一次 schema 递归扫出 333 条「失效键」，逐条实测后**真死的只有 3 条**
> —— 不实测就批量改，**会毁掉 330 条正确数据**。

### 3.1 静态效果（蓝龙面具 + 堕影冥界印记刺青）

在测试桩 `Actor.E4OlKBqN2dFen4ZX` 上装入并装备+同调：

| 步骤 | `senses.darkvision` | `traits.dr.value` |
|---|---|---|
| 基线（裸卡） | **0** | **[]** |
| 装入两件 + 装备 + 同调 | **60** | **["lightning"]** |
| **★ 空白对照**：再加一个必假键 `system.attack.bonus\|m2\|99` | 60（**纹丝不动**） | ["lightning"]（**纹丝不动**） |
| 清理后 | 0 | [] |

⇒ **空白对照不动** = 证明前面的变化是**真键**造成的，不是污染。

### 3.2 midi 优势键（这是最容易误判的一个）

```
① 对照（无刺青）           MidiQOL.computeSkillAdvantage(actor,"ste")
   → advantage.active = false

② 装上堕影冥界印记刺青后
   → advantage.active = true
   → attribution: { ADV: { "skill.ste": "优势 (隐匿)" } }     ← midi 自己标注出来了
   → legacyAttribution: ["ADV:skill.ste"]

③ ★ 对照：同一时刻查「体操 acr」 → advantage.active = false  ← 证明不是恒返回 true

④ 清理后 → false
```

**源码级铁证**（midi-qol 13.0.55 `computeSkillAdvantage(actor, skillId, options, tracker)`）：
```js
advantageFlags: [ "advantage.all", "advantage.skill.all", `advantage.skill.${skillId}` ]
```
⇒ `flags.midi-qol.advantage.skill.ste` 正是 midi 自己查找的键。

> ⚠️ **踩坑**：`computeSkillAdvantage` 是 **async** 函数。不 `await` 会拿到空对象 `{}`，会误判成「键无效」。

### 5.1 502 件「点一下只出聊天卡」

判据：**只有 utility 活动 ∧ 0 效果 ∧ 无 `flags.dae.macro` / `flags.itemacro.macro` ∧ 无 CPR 绑定**。

抽样 22 件逐条读描述后的分布估计：

| 类别 | 占比 | 例子 | 能否补 |
|---|---|---|---|
| 明确无字段可做 | ~45% | 风暴导向（天气）、坚守战线（借机攻击规则）、收束未来（跳骰） | ❌ |

> **建议**：若继续推进，优先扫「有明确**数值/骰子**机制但完全没实现」的，别碰「规则条文类」——
> 后者做出来的宏往往比手动还麻烦。
