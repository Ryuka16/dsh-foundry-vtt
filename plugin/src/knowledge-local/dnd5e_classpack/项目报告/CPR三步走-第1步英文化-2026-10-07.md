## 四 · ★★★ 技术突破：effects 带 `_id` 是「合并」而非「追加」

**背景**：旧记录说「compendium 的 `effects` 是追加语义，改效果必须重建文档」。

**实测推翻**：
```
# 方式 A（错的）：点号路径
updateDocuments([{_id:"0GPWp8Rwlm5AizJD", "effects.0.name":"Staggering Smite"}])
⇒ 结果 ["惊惧斩Staggering Smite", "Staggering Smite"]   ← 变成 2 条！

# 方式 B（对的）：传带 _id 的完整数组
const o = doc.toObject();
updateDocuments([{_id: doc.id, effects: o.effects.map(e => Object.assign({}, e, {name: 新名}))}])
⇒ 结果 ["12oJ5jVCx8i48uFC:护盾术 Shield"] → ["12oJ5jVCx8i48uFC:Shield"]   ← 数量不变、原地更新 ✓
```

**⇒ Foundry ArrayField 规则**：数组元素**带 `_id`** ⇒ 按 id 合并；**不带 `_id`** ⇒ 追加。
**⇒ 必须把整条效果对象都带上**（只给 `_id` + `name` 会丢其他字段）。
**⇒ 误用点号路径造出的重复**，用 `pack.documentClass.create(o, {pack, keepId:true})` 重建修复（实测有效）。

**副作用修复**：试坏的那件 `spell/0GPWp8Rwlm5AizJD`（惊惧斩）已重建 ⇒ `name:"Staggering Smite"` / `effects:["Staggering Smite"]` ✓

## 五 · 第 1 步执行结果

### 5.1 名称转英文规则
```js
const toEn = (s) => {
  if (typeof s !== "string" || !/[\u4e00-\u9fa5]/.test(s)) return null;
  const m = s.match(/^[^A-Za-z]*([A-Za-z][\s\S]*)$/);   // 中文在前 ⇒ 取第一个 ASCII 字母起
  if (!m) return null;                                  // 纯中文 ⇒ 不动
  const c = m[1].trim();
  return c && c !== s ? c : null;
};
```

- `惊惧斩Staggering Smite` → `Staggering Smite` ✓

## 九 · 本轮踩坑（已记 foundry_learn [L008]）

1. **compendium 写入前必须解锁** —— 报 `You may not update documents in the locked compendium`；新世界 import 的包默认 `locked:true`
2. **effects 用「带 `_id` 的完整数组」合并**；点号路径 `effects.0.name` 会追加成 2 条
3. **`pack.getDocument(id)` 要完整 16 位 id**（截断 id 返回 null）
4. **改名后要复验重名** —— 去掉中文后缀可能让变体与基础版同名（本次 14 组，已修正）
