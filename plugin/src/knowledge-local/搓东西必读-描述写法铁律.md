> **写任何 FVTT 物品 / 特性 / 怪物部件之前，先读这一份。**

## 一、动态引用：名字、骰子、加值一律不许写死

做出来的部件要**挂到任意怪身上都自动适配**，所以名字、骰子、加值一律用动态引用。

### 1. 名字 —— `[[lookup @name]]`
- 描述里写 `[[lookup @name]]` → 渲染成**宿主怪自己的名字**
- **回退写法**：`[[lookup @name]]{creature}` ← **强烈建议永远带回退**（取不到 rollData 时会显示一个灰色的 @name，最典型就是物品躺在侧边栏被预览时）
- 别写「雪人」「巨魔」这种具体名，也别只写「该生物」
- 实测：德拉肯海姆部件里用了 35 次

### 2. 骰子 —— 无参 `[[/damage average]]`
- 写**无参**形式 → 自动引用该物品自己的伤害活动
- **别写** `[[/damage 1d6 + 4 type=slashing]]` 这种写死形式 —— 活动一改描述就不对了

### 3. 属性检定与豁免（提示词库原来缺这条，本插件补）
- 豁免：`[[/save ability=cha dc=@attributes.spelldc format=long]]{魅力豁免}`
- 检定：`[[/check ability=int skill=arc dc=@attributes.spelldc]]`
- 这两条是从世界里的**官方法术描述**直接抄到的（力场监牢 / 侦测思想），不是推测
- 其他可用：`[[/attack]]`、`[[/heal]]`、`[[/item]]`、`&Reference[Prone]`

### 4. 攻击加值用公式 —— 三个字段必须**同时**给
缺一个公式就不生效：
```
attack.bonus   = "@prof + max(@abilities.dex.mod, @abilities.str.mod)"
attack.flat    = true      ← 关掉系统自动计算
attack.ability = "none"    ← 同上
```

### 5. 伤害 / 治疗用公式 —— 固定走 custom
```
damage.parts[].custom = { enabled: true, formula: "2 * @prof" }
```
实测可用实例：`2 * @prof`（按熟练回血）、`1d6 + max(@abilities.dex.mod, @abilities.str.mod)`（取力敏较高）、`(floor(@prof / 2))d6`（熟练决定骰数）、`(@flags.xxx)d10`（flags 决定骰数）、`@classes.paladin.levels`（按职业等级）。

### 6. 可用的 @ 引用
`@prof` / `@abilities.X.mod` / `@abilities.X.dc`（= 8 + prof + 调整值）/ `@attributes.*` / `@details.cr` / `@details.level` / `@classes.X.levels` / `@flags.*` / `@scale.*`
完整清单（唯一权威）：https://github.com/foundryvtt/dnd5e/wiki/Roll-Formulas

### ⚠️ 不要靠「从别的怪身上抽特性」来攒部件库
那些物品的描述是写死骰子的死文本，activities 还多半是空壳，抽出来既没自动化、又带着原怪名字。
**要部件库就得重写，不是搬运。**

## 三、描述排版（官方格式）
- **总述一段 + 每个独立效果各自一段**，段与段之间空一行
- **是自然段，不是 markdown 小标题**（不要 `##`、不要 `-` 列表、不要拿加粗条目名当标题 —— 卡面上读起来像说明书）
- 第 1 段写外观与来历（2~3 句）；之后一个独立效果一段；并列项（按钮 1 / 2 / 3）各自一段
- FVTT 实现：`system.description.value` 是 HTML，**用多个 `<p>` 分段**
- 官方样例：城主指南《王者权杖》共 11 段（总述 1 段 + 六个按钮各 1 段 + 三个效果各 1 段）

## 四、机制必须写进描述（血泪教训）
**玩家不会点开活动页** —— 第一次拿到这个东西的人只能靠描述知道它能干什么。
每个效果要交代全 7 件事：
1. 用什么动作
2. 什么时候能用
3. 距离或范围
4. 对抗方式（DC X 的【属性】豁免）
5. 结果（失败受 NdM 点【伤害类型】伤害 / 陷入状态 / 成功减半）
6. 持续与重试
7. 充能与恢复

术语用官方译名：**豁免**（不是「检定」）、一个动作 / 一个附赠动作 / 一个反应、**黯蚀**（不是「暗蚀」）、**充能**（不是「次数」）、**同调**（不是「绑定」）。

**只写氛围不写机制 = 交付不合格。**

## 五、去 AI 味（写 useFlavor / chatFlavor 时）
- **每多写一句，问一句：这句不写，玩家会错过什么？** 错过线索 / 伏笔 / 情绪 → 留；只是「画面更美、更全」→ 删
- 写完**念一遍** —— AI 味 = 没有逻辑重音
- 烂句式黑名单四类：
  - 「显得就你知道」类：很多人不知道的是 / 你可能想不到 / 鲜为人知的是 / 你有没有想过 / 你会发现 / 答案可能会颠覆你的认知
  - 「强行拔高」类：这背后隐藏着一个深刻的秘密 / 看似…实际上是 / 站在历史的长河中 / 从某种意义上来说
  - 「假转折假逻辑」类：我们不妨换一个角度来看 / 首先我们要明确一个概念 / 值得一提的是 / 真正重要的不是…而是
  - 「假装深沉强行闭环」类：值得我们深思的是 / 或许这是…留给我们的启示 / 这告诉了我们一个道理 / 真正的原因是 / 背后的逻辑是 / 这也是为什么
- 战斗与效果文案不能用：模板填空式语言（抄起 / 压低重心 / 自斜上方劈落）、分段报告（第一斧 / 第二斧）、大白话（啪啪啪三下）、规则说明（造成 2d6 火焰伤害）、DM 视角（它对玩家造成）
- 追求「展示，不要告知」；**未命中和豁免成功也可以很精彩** —— 不是「你砍偏了」，而是对手做了什么
- 伤害类型感官映射：火焰 = 水泡鼓起 / 焦臭；冷冻 = 呵气成冰 / 关节僵死；闪电 = 肌肉抽搐 / 臭氧味；强酸 = 皮肤融化成糊；暗蚀 = 肤色灰败 / 眼眶凹陷；心灵 = 颅内有异物感 / 念头变陌生；毒素 = 血管发黑从伤口蔓延 / 视野发绿
