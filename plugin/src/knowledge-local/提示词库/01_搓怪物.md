## 动态引用写法（写物品/特性必用，别写死）

做出来的部件要**挂到任意怪身上都自动适配**，所以名字、骰子、加值一律用动态引用，不许写死。

- **权威样本**：你世界已装的 `drakkenheim`（德拉肯海姆）自带两个部件包 ——
  `drakkenheim-monsters.features`（69 条）、`drakkenheim-scgd.features`（258 条）。
  这两包就是「面向 DM 的搓怪部件库」成品范例，拿不准就先去看它们怎么写的（`foundry_execute_js` 读 `pack.getDocument()`）。

- **名字**：描述里写 `[[lookup @name]]` → 渲染成**宿主怪自己的名字**。
  别写「雪人」「巨魔」这种具体名，也别只写「该生物」。
  实测：德拉肯海姆部件里用了 35 次。回退写法 `[[lookup @name]]{creature}`。

- **描述里的骰子**：写**无参** `[[/damage average]]` → 自动引用该物品自己的伤害活动。
  别写 `[[/damage 1d6 + 4 type=slashing]]` 这种写死形式 —— 那样活动一改描述就不对了。

- **攻击加值用公式**：三个字段必须**同时**给，缺一个公式就不生效：
  ```
  attack.bonus   = "@prof + max(@abilities.dex.mod, @abilities.str.mod)"
  attack.flat    = true      ← 关掉系统自动计算
  attack.ability = "none"    ← 同上
  ```

- **伤害 / 治疗用公式**：固定走 `damage.parts[].custom`：
  ```
  custom = { enabled: true, formula: "2 * @prof" }
  ```
  实测可用实例：`2 * @prof`（按熟练回血）、`1d6 + max(@abilities.dex.mod, @abilities.str.mod)`（取力敏较高）、
  `(floor(@prof / 2))d6`（熟练决定骰数）、`(@flags.xxx)d10`（flags 决定骰数）、`@classes.paladin.levels`（按职业等级）。

- **可用 `@` 引用**：`@prof` / `@abilities.X.mod` / `@abilities.X.dc`（= 8 + prof + 调整值）/
  `@attributes.*` / `@details.cr` / `@details.level` / `@classes.X.levels` / `@flags.*` / `@scale.*`
  **完整清单**（唯一权威）：https://github.com/foundryvtt/dnd5e/wiki/Roll-Formulas

- ⚠️ **不要靠「从别的怪身上抽特性」来攒部件库** —— 那些物品的描述是写死骰子的死文本，
  activities 还多半是空壳，抽出来既没自动化、又带着原怪名字。
  （实测：你世界那 437 只怪的物品全是这个状态。）**要部件库就得重写，不是搬运。**

## 任务要求
按以下流程搓怪物：
1. **确认需求**：询问或读取【怪物名字/主题/挑战等级CR/阵营/环境】，缺信息先问我，不瞎编
2. **设计数值**：按 CR 表定属性、HP、AC、伤害，说明设计理由
3. **写数据文件**：产出标准 **FVTT Actor JSON**（遵循 monster-spec 规范），输出为 `.json` 文件存到【输出位置，默认 01_跑团工具/怪物与物品卡/ 或 提示词库/输出/】
4. **可选扩展**：需要特效宏（fxMacro）时按 `01_跑团工具/FVTT技术资料/FVTT特效同步规范-fxExecCode.md` 附带 JS 宏
5. **自我审查**：交付前对照规范检查字段完整性，列出 CR 平衡性估算
