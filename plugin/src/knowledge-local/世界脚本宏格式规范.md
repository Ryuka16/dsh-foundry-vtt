# 世界脚本宏 · 格式规范（做世界脚本必须这么做）

> 适用：user DM 工具箱（`your-dm-toolkit`）里的《宏后台核心（勿动）》宏。
> **简单说：世界脚本 = 一段「JSON 数组」存在一个宏的 `command` 里。做世界脚本 = 正确编辑这段 JSON。**
> 本规范是**怎么做才安全**的底线：格式一乱，整个脚本全挂，且很难修。**务必先读第四节「怕格式乱了怎么办」。**

---

## 一、世界脚本到底是什么

你的世界脚本不是一段散装 JS，而是 **好多个「脚本块」的数组**，集中在宏《宏后台核心》里。

- **哪个宏**：合集包 `your-dm-toolkit` → 《宏后台核心（勿动）》。
- **结构**：它的 `command` 字段存这一段 **JSON 数组**。
- **谁执行**：脚本工坊启动时，把数组里每个块的 `code` 依次当成一段 JS，在同一个全局作用域下执行。

> 所以「做世界脚本」= **编辑这个宏的 `command` 里的 JSON 数组**。你加块、删块、改块，都是在改这段 JSON。

---

## 二、一个块的格式（四字段，一个都不能少）

数组里每个元素是一个**对象**，固定四个字段：

```json
{
  "name": "骰控",
  "description": "商团骰运干预：挂载 mapRandomFace、socketlib 分骰面",
  "enabled": true,
  "code": "// 这一段是你写的 JavaScript"
}
```

| 字段 | 类型 | 必须 | 说明 |
|---|---|---|---|
| `name` | 字符串 | ✅ | 块名，左边列表显示它。一眼看出是干嘛的 |
| `description` | 字符串 | ✅ | 一句话说明，方便以后再找 |
| `enabled` | 布尔 | ✅ | `true`=启用执行；`false`=保留但跳过 |
| `code` | 字符串 | ✅ | **你的 JS 代码本体**。整个包在一对引号里 |

> ⚠️ `code` 里**不能**有裸换行 + 半角双引号直接堆——那是 JSON 语法大忌，见第四节。

---

## 三、数组格式（块与块之间）

整个东西是 **`[` 开头、`]` 结尾**的数组，块与块用**逗号**隔开：

```json
[
  { "name": "冒险者履历", "description": "...", "enabled": true, "code": "..." },
  { "name": "环境滤镜",   "description": "...", "enabled": true, "code": "..." },
  { "name": "核心加载器", "description": "地基，别挪到其它块后面", "enabled": true, "code": "..." }
]
```

- **执行顺序 = 数组从上到下**。依赖别的块（比如调用 `globalThis.YGM`）的必须排在它后面。
- 前一个块定义的全局函数/变量，后一个块能用。

---

## 四、⚠️ 怕格式乱了怎么办（最关键）

### 4.1 为什么会乱？四个大坑

JSON 对格式**极度严格**，差一个标点就整段报错。常见案犯：

1. **`code` 里用了半角双引号 `"` 没转义** —— 比如 `xxx.setFlag("world", "k")`。JSON 里字符串内部的 `"` 必须写成 `\"`。**这是头号杀手。**
2. **`code` 里有裸换行** —— 代码我写成了多行，却直接用回车换行。JSON 字符串里换行必须写成 `\n`。
3. **中文标点冒充** —— 用了中文逗号 `，` / 中文引号 `“”`。JSON 只认半角 `,` 和 `"`。
4. **块之间少了 `/` 多了逗号** —— 最后一块的末尾多一个逗号（尾随逗号），或两块之间漏了逗号。

### 4.2 铁律：改之前，先备份

打开《宏后台核心》宏 → 把 `command` **全选复制一份**存到一个 `.txt` 里。改坏了随时贴回去，一键还原。**这一步永远不要省。**

### 4.3 改之前，先验证（最推荐）

**不要直接保存后心惊胆战刷新**。改完先在 F12 控制台跑下面这段「验证宏」——它是你把 `command` 贴进去，它帮你 JSON 解析，**合法就报「✅ 格式正常，共 N 块」，违规就明确告诉你错在哪一行、哪个位置**：

```js
// === 世界脚本格式验证器（粘贴 command 到这里验证） ===
const raw = /* 把你的 command 内容整段粘贴进这里 */;
let arr;
try { arr = JSON.parse(raw); }
catch (e) {
  const m = /position (\d+)/.exec(e.message || "");
  const pos = m ? +m[1] : -1;
  let ctx = "";
  if (pos >= 0) ctx = "\n……" + raw.slice(Math.max(0, pos - 40), pos) + "▶" + raw.slice(pos, pos + 20) + "……";
  console.error("❌ JSON 不合法！" + (pos >= 0 ? "出错位置约在字符 " + pos : "") + ctx);
  console.error("报错: " + e.message);
} finally { /* 无论成败都继续 */ }
if (arr) {
  console.log("✅ 格式正常，共 " + arr.length + " 块");
  arr.forEach((b, i) => console.log("  " + (i + 1) + ". " + (b.name || "(无名字)") + "  " + (b.enabled === false ? "[停用]" : "[启用]")));
}
```

> **粘贴技巧**：把 `const raw = ` 后面的内容整个替换成你的宏 `command`。最稳的做法是：先复制整个 `command`，在验证器里把 `const raw = 后面的引号块` 整块替换为 `const raw = \`你的command\`;`（用**反引号**包住，反引号里就不怕 `"` 和换行了——见 4.4）。

### 4.4 最省心的写法：用反引号包 code（强烈建议）

如果你要**亲手**新建一块，`code` 用**反引号 `` ` ``** 包起来，而不是双引号——这样里面随便写一行、随便放双引号，都不会坏 JSON 格式：

```json
{
  "name": "骰控",
  "description": "商团骰运干预",
  "enabled": true,
  "code": "`\n  // 你的 JS 随便写，里面随意使用双引号\n  game.settings.set(\"xx\", \"yy\");\n`"
}
```

> 但注意：**这不是标准 JSON**（标准 JSON 字符串只能用双引号）。所以「反引号写法」只适合**你自己在脚本工坊里手敲**的场景；若要导出成 `.json` 给人 / 给 Foundry 导入，还是得用标准双引号 + 转义。
>
> **所以真正靠谱的分工是**：
> - **自己写/改脚本** → 用脚本工坊的图形界面，往「代码」框里粘 JS，**它帮你处理转义**，你永远不用碰 `\"` 和 `\n`。
> - **导出成文件** → 用脚本工坊的「导出」按钮，它生成标准 JSON。
>
> **这才是防乱的正解：尽量走脚本工坊界面，别手撸 JSON。**

### 4.5 已经乱了，怎么救

- **有备份** → 直接把备份的 `command` 整段贴回去，刷新，完事。
- **没备份** → 用 4.3 验证器看报错位置，对着 4.1 的四个大坑改。**报错会告诉你大致字符位置**，定位到那一带，八成是 `"` 或 `\n` 或尾随逗号。
- **实在救不回** → 用最初打包的分块 JSON（`world-scripts-blocks.json`）重新导入。它是权威快照。

## 五、做世界脚本宏 · 硬规则速查

| 规则 | 必须做 |
|---|---|
| 改前 | **先备份** command 到 .txt |
| 改后 | **先跑验证器**再刷新 |
| 块字段 | name / description / enabled / code **四件套一个不少** |
| code 内容 | 不在里面手动写 `"` 换行；能用脚本工坊界面就别手撸 |
| 数组 | `[` 开头 `]` 结尾，块间用半角逗号，最后一块无尾随逗号 |
| 顺序 | 依赖别的块的排它后面 |
| 标点 | **全部半角**，禁用中文 `，` `“”` |
