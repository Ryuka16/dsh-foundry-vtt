## 0. 一页速览（最重要，先看这十条）

1. **Foundry 游戏内任何代码都无法自动删除服务器文件**——三层铁证见 §1。正解：
   模块做「清单面板」（浏览/预览/发送/复制路径），删除引导用户服务器侧手动删。
2. **HTTP 服务器上 `navigator.clipboard` 是 undefined**——复制一律用
   `game.clipboard.copyPlainText(text)`，官方 API 自带降级。见 §2。
3. **v1 Dialog 底部标准按钮（.dialog-button）不走你的主题变量**——窗口整体染深色时
   按钮黑字落黑底。必须模块作用域覆盖。见 §3。
4. **版本三处同步**：module.json + JS 头注释 + 探针 `window.__VLAB_VER`。远程调试
   第一件事拿探针版本，别信用户「已经升级了」。见 §4。
5. **部署必须整包替换**：只覆盖 scripts/styles 不换 module.json 会跑出「混合版本」
   （探针是旧的、却请求已删除的 lang/cn.json）。见 §4。
6. **拖拽文件进面板**：dragover/drop 必须判
   `Array.from(e.originalEvent.dataTransfer.types).includes("Files")` 才 preventDefault，
   所有其他拖拽 handler 加 Files 守卫 return，否则文件拖不进去或误触发。见 §5。
7. **Dialog 确认按钮读状态**：批量导入面板的行状态（radio/checkbox/改名 input）在
   callback 里 `dialog.element.querySelector` 读 DOM，别存闭包变量。见 §5。
8. **cmd 批处理两大坑**：UTF-8 编码 + LF 换行会「吞行首字符」（echo→cho）；正确姿势
   GBK(936) 编码 + CRLF。实测两次才坐实。见 §6（本模块最终已弃 bat 方案）。
9. **模块 CSS 是 `<style>` @import 注入**，诊断用 `querySelectorAll('style')` +
   `getComputedStyle` 实测（承 CSS面板配置篇）。
10. **V1 Application deprecation 警告是刻意选择**（Dialog 金标准），v15 前安全，
    v16 才需要迁 V2。见 §7。

## 1. 「模块能不能自动删服务器文件」——查证全过程与最终结论

**需求来源**：模块里「清理临时文件夹」功能。第一版做成了 FilePicker browse 模式
（点文件=复制路径），用户点「清除临时」发现根本删不掉。

### 1.1 三层铁证：官方没有删除途径

- **证据一 · 文件 socket**：FVTT 安装目录
  `<FVTT安装目录>\resources\app\dist\files\files.mjs`
  的 socketListeners 里 `manageFiles` **只有三个 action**：`browseFiles` /
  `createDirectory` / `configurePath`，没有删除。
- **证据二 · HTTP 路由**：`dist/server/views/view.mjs` 的 View 基类只有
  `hasGet` / `hasPost`（`_methods` 只收 get/post）。全部 views
  （auth/players/game/join/setup/license/update/quit/api/upload/error）无一有 delete
  方法。**游戏内任何代码发 HTTP DELETE 都是 404。**
- **证据三 · 模块代码跑在哪**：模块的 esmodules/scripts 只由
  `dist/server/views/view.mjs` 的 `_getStaticContent` 注入**客户端 HTML 页面**，Node 端
  根本不加载模块代码（dist 全库无加载机制）→ 浏览器代码摸不到服务器硬盘。

### 1.2 金标准对照（用户记忆里「能删」的真相）

用户记得 origin-vault（`01_跑团工具\Foundry模块\sora的专属mod，未使用，作为参考\origin-vault`）
界面能删文件。查证：它是**索引删除**，不是磁盘删除——
- `LibraryData.js:1181` 注释原话：「由于 Foundry VTT 不支持 HTTP DELETE，我们使用标记删除法」，
  `LibraryData.js:1184-1204` removeItem 只写 `item.deleted=true`；
- `AssetData.js:233` / `ThumbnailManager.js:699-706` 里的
  `fetch('/'+relativePath,{method:'DELETE'})` 是「尝试」删除，catch **静默吞失败**。

### 1.3 socket 方案也走不通（如果将来有人想试）

- 模块 manifest 的 `"socket": true` **只是布尔字段**（出处：
  `common/packages/base-package.mjs:387`），不等于给了服务器权限。
- `game.socket.emit/on` 只转发 `module.<id>` 和 `system.<id>` 命名空间，`world.*` 被
  **静默丢弃**（用户世界实测坐实：`之前踩过的坑.txt:89`）。
- 模块代码没跑在 Node 侧，socket 转发的两端都是浏览器，永远到不了 fs。

### 1.4 正解（本模块 v1.6.3 最终形态）

清理面板 = 浏览 vlab-temp → 每行文件可「预览」（图片 ImagePopout 灯箱 / 视频新标签）、
可「发送」到聊天、可「复制路径」；底部固定文案：
**「FVTT 源码不支持删除文件，请在下方地址手动进行删除：Data/vlab-temp/」**
+ 一键复制文件夹地址。自托管用户去服务器删，平台托管用户用平台文件管理。

## 2. HTTP 服务器剪贴板：navigator.clipboard 是 undefined

**现象**：用户贴日志
`复制失败：Cannot read properties of undefined (reading 'writeText') @ foundry.mjs:115132`。

**根因**：用户服务器是 HTTP 地址（如 `http://146.56.232.12:30000`），浏览器把 HTTP 页面
视为**非安全上下文**，`navigator.clipboard` 直接不存在。这不是代码笔误，是浏览器安全策略。

**正解**：FVTT 官方 API `game.clipboard.copyPlainText(text)`——出处
`<FVTT安装目录>\resources\app\client\core\clipboard.js:19-34`：
先查 `navigator.permissions`，有 granted/prompt 走 `writeText`，否则降级
`document.execCommand("copy")`。**模块里所有复制动作一律用它，别自己碰 navigator.clipboard。**

## 3. 自绘深色面板：Dialog 底部标准按钮黑字落黑底

**现象**：白色主题下按钮正常，深色主题下「复制文件夹地址 / 刷新 / 关闭」纯黑看不清。

**根因**：`.video-lab-app.window-app` 用 `background: var(--vlab-bg) !important` 把
**整个窗口（含底部 .dialog-buttons 按钮栏区域）**染成主题底色（deep 近黑 `#0a0a0c`），
但 Dialog v1 底部按钮 `.dialog-button` 走 FVTT 全局默认样式（深色字）——黑字落黑底。
白色主题恰好是默认浅色底配深色字，所以「只有深色主题炸」。

**正解**：模块作用域内显式覆盖（官方模板类名出处
`<FVTT安装目录>\resources\app\templates\hud\dialog.html:4-6`，
`.dialog-buttons` 容器 + `.dialog-button` 按钮）：

```css
.video-lab-app .dialog-buttons { background: var(--vlab-bg2) !important; border-top: 1px solid var(--vlab-border) !important; }
.video-lab-app .dialog-buttons .dialog-button {
  background: var(--vlab-surface2) !important;
  border: 1px solid var(--vlab-border) !important;
  color: var(--vlab-text) !important;
}
.video-lab-app .dialog-buttons .dialog-button:hover {
  border-color: var(--vlab-accent) !important;
  color: var(--vlab-hover-text) !important;
  box-shadow: 0 0 12px var(--vlab-glow) !important;
}
```

**铁律：凡「窗口整体染色」的设计，Dialog 底部标准按钮区必须一并覆盖，不能只覆盖自绘元素。**

## 4. 版本探针 + 部署整包替换（混合版本事故）

**事故**：用户说「升级了」，实际 `window.__VLAB_VER` 还是 `"1.6.0"`，且服务器仍请求
`modules/lh-video-lab/lang/cn.json`（该文件 v1.6.0 起已删）报 404；报错行号也是旧版行号。
诊断结论：用户只覆盖了 scripts/styles 两个文件，**没换 module.json**，新版整个没生效。

**铁律**：
- 模块版本三处同步：`module.json version` + JS 头注释 + 探针
  `window.__VLAB_VER = "x.y.z"`（探针变量在 ready 前尽早赋值）。
- 远程调试第一步永远是拿探针版本，再谈其他。
- 部署指引必须写「整包替换」：删服务器 `Data\modules\lh-video-lab` 整个文件夹 → 解压 zip
  → 提醒解压时选「解压到 lh-video-lab」防双嵌套 `lh-video-lab\lh-video-lab` → Ctrl+F5 →
  探针验版。

**打包教训**：`Compress-Archive -File` 只包顶层文件会漏 scripts/styles 目录（zip 异常小
3.5KB 才发现）→ 用 `-Path` 列全条目（module.json/README/LICENSE/scripts/styles）。
zip 条目分隔符是**反斜杠**，抽验用 `GetEntry("scripts\\video-lab.js")`。

## 5. 粘贴 / 拖拽批量导入面板（v1.6.1）

- **剪贴板粘贴**：document 级 paste 监听，`clipboardData.items` 取 `image/*`/`video/*`
  的 `getAsFile()`；拿到 file 走批量导入面板；拿不到但剪贴板是文件路径文本 → 提示走
  本地上传按钮。
- **无名图默认名**：剪贴板图片文件名形如 `image.png`（正则 `/^image\.(png|jpe?g)$/i`），
  默认名给 `粘贴-时间戳.ext`。
- **拖拽**：面板 render 时挂 dragover/drop/dragleave 到 window 元素。
  **dragover 必须判** `Array.from(e.originalEvent.dataTransfer.types).includes("Files")`
  才 preventDefault + 高亮类；**归组等既有拖拽 handler 加同款 Files 守卫 return**
  （否则文件拖不进去，或误走归组逻辑）。drop 里 stopPropagation 后开导入面板。
- **多文件一个面板**：`openImportPanel(files)` 单例追加模式（面板存在则往列表追加行，
  不新开窗口）。每行 = 缩略图（图片 objectURL 点击开 ImagePopout 灯箱；视频
  `<video preload="metadata" muted>` + 预览按钮 `window.open(objectURL)`）+ 改名 input +
  radio 去向（留存/临时，临时默认）+ checkbox 是否发送（默认勾）。
- **确认读状态**：Dialog 按钮 callback 里从 DOM 读每行
  `radio:checked`/checkbox/改名 input 的值（DialogV2 教训：内联事件不触发，callback 读
  DOM 才是正解）。
- **防重名**：`used = new Set(dirSetCache)`，撞名加 `-1`/`-2`。
- **objectURL 用完 revoke**，批量导入 finally 里统一回收。
- **导入动作**：`FilePicker.createDirectory` → `FilePicker.upload` → 按勾选 `sendDirect`
  （私聊/群发走 ChatMessage.create，whisper 数组）→ 有留存才 loadList 刷新列表。

## 6. cmd 批处理文件两大坑（已弃用方案，教训留存）

曾做 `vlab-cleanup-temp.bat` 让用户双击删 vlab-temp（后来用户要求通用化、已删）。
实测翻车两次：

- **坑一**：UTF-8 编码下 `chcp 65001` 切换代码页会破坏 cmd 缓冲解析；
- **坑二**：LF-only 换行会吞下一行行首字符（`echo`→`cho`、`del`→`el`、`set`→`ET`），
  报 `'cho' is not recognized`。
- **正解**：文件编码 GBK(936) + CRLF 换行，实测通过（PowerShell 里用
  `[IO.File]::WriteAllText($p, $text, [Text.Encoding]::GetEncoding(936))` 或先写 UTF-8
  再转码；换行写 `\r\n`）。

## 7. 本次沿用的既有金标准（没踩坑，但值得记录）

- **Dialog v1 构造**：`new Dialog(data, { classes, width, resizable, ... })`——CSS 变量和
  classes 放**第二参数**（第一参数只放 content/title/buttons）。
- **按钮图标**：`icon` 用 `<i class="fa-solid ...">` HTML，不用纯字符串。
- **聊天图片放大**：document **捕获阶段**委托 + ImagePopout（game.mjs:2018 冒泡阶段
  `_onClickHyperlink` 无条件 preventDefault+window.open，捕获阶段 stopPropagation 才不双开）。
- **场景按钮**：1500ms 常驻轮询 `insertAfter("button.control.ui-control.layer.icon.fa-solid.fa-bookmark")`，
  严禁 clearInterval 即停（切场景重建 DOM）。
- **V1 deprecation 警告**：刻意留在 v1（Dialog 金标准），v15 前安全。

## 8. 铁律（本次沉淀）

1. **游戏内删服务器文件 = 不存在**。模块做清单面板 + 指引，别在「能不能删」上再花一分钟。
2. **复制一律 `game.clipboard.copyPlainText`**，HTTP 服务器上 navigator.clipboard 是 undefined。
3. **窗口整体染色的面板，Dialog 底部标准按钮必须一并覆盖配色。**
4. **版本三处同步 + 部署整包替换 + 探针验版**，一个都不能少。
5. **拖拽文件：types 判 Files 才 preventDefault，其他 handler 加 Files 守卫。**
6. **批量表单状态从 Dialog callback 读 DOM，不存闭包。**
7. **cmd 批处理：GBK + CRLF**，UTF-8/LF 会吞行首字符。
8. **用户报「没生效」先验探针版本**，混合版本事故不是个例。
