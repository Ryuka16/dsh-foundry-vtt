## 0. 一句话根本

> 我一直在解「用户刚提的那一条需求」，从没拿尺子把**整体**量过一遍。
> 那 12 条几乎一一对应一张跟 Foundry 无关的通用清单——他们不是比我更懂 Foundry，

**另一个根因（必须承认）**：v1.0.0 → v1.1.0 是十几轮增量打补丁攒出来的。

作者自审天然弱于外部审阅 —— 但不是不能补：把「陌生人视角通读」变成固定动作即可。

## 1. 复盘：为什么 52 项测试没抓到那 3 条

| 那 3 条问题 | 测试为什么没抓到 |
|---|---|
| 新世界漏恢复（快照里有、本世界没写过的模块不出现在列表里） | 我的测试世界里**恰好**有那几个模块的设置。测试数据是我按「正常世界」构造的，而 bug 出在「新世界」 |

## 2. 通用审阅清单（14 项 · 逐条打勾）

> 用法：每条都问自己那个问题，然后**动手查**（grep / 读代码 / 构造场景），别只在脑子里过。

### 1. 状态模型一致性
- **问**：这份状态存在哪里？以什么为键？两个同类对象同时存在（两个世界 / 两个角色 / 两个窗口 / 两份配置）会不会串？
- **怎么查**：把每个持久化状态列成表（文件 / localStorage / world 设置 / flags），逐行问「键够不够唯一」。
- **真实反例**：回档账本固定写 `apply-log.json` 且只记世界**标题** → A 世界恢复、B 世界恢复（覆盖）、回 A 点回档 → 写进 A 的是 B 的旧值。
- **过关标准**：状态的键用的是**稳定 ID**（`world.id` / `actor.id`），不是可改的显示名。

### 2. 首次使用与边界场景
- **问**：全新安装 / 空数据 / 第一次运行 / 目标对象缺少数据源时，会不会静默失效？
- **怎么查**：把测试世界**清空到最干净**再跑一遍主流程（不是用你的「常用测试世界」）。
- **真实反例**：模块勾选列表只由「当前世界已有的 Setting」生成 → 新世界没有该模块的设置，就永远不出现在列表里，恢复不到。
- **过关标准**：空世界能跑通全流程，且**不依赖任何历史残留**。

### 3. 命名与行为相符
- **问**：按钮 / 函数名 / 提示语承诺的语义，代码真做到了吗？
- **怎么查**：把 UI 上每个按钮的文案抄出来，对着它的 handler 读一遍，看是否同义。
- **真实反例**：按钮叫「从文件导入」，实际只把当前世界恢复成该快照，**没写服务器主快照** —— 而 README 把它写成跨服务器迁移手段。
- **过关标准**：文案能逐字对应到代码行为；做不到就改文案（改文案永远比改行为安全）。

### 4. 控件联动必须双向
- **问**：全选 / 单选 / 父项勾选，是单向联动还是双向？取消一个之后，全选状态还正确吗？
- **怎么查**：对每个 checkbox/radio 组，**手动画出状态转移表**：全选→取消子项→再全选→再取消全部。
- **真实反例**：「全选」默认勾上且只做单向联动 → 用户取消某个模块后点恢复，仍会恢复它。
- **过关标准**：子项永远是唯一真源，父项只是它的投影（`checked` + `indeterminate`）。

### 5. 同一规则多处实现必须一致
- **问**：同一个判断，在几条路径里分别写了几遍？它们一致吗？
- **怎么查**：`grep -n` 把同一语义的表达式全找出来（如 `ns !== "core"`），逐处比对。
- **真实反例**：core 命名空间在手动恢复里被包含、在自动提醒里被排除 → 状态栏一直报差异、自动恢复永不处理。
- **过关标准**：抽成一个函数（`buildSelection()`），所有路径调用同一个，禁止各写一遍。

### 6. 用户偏好持久化
- **问**：用户在界面上调过的东西（范围 / 主题 / 开关），关掉页面后还在吗？自动流程遵守它吗？
- **怎么查**：把界面上每个可调项列出来，逐个问「存在哪」。
- **真实反例**：恢复范围只存在内存里 → 手动恢复遵守，进世界自动提醒自己造了另一套范围。
- **过关标准**：调过即落库，且**自动路径与手动路径读同一份偏好**。

### 7. 外部输入硬校验
- **问**：从文件 / 剪贴板 / 网络 / 表单进来的数据，校验有多硬？损坏文件会不会把世界写坏？
- **怎么查**：构造 8 类坏输入各一份（非 JSON、类型不对、缺字段、重复键、版本过新、超大、编码错、空）逐个喂进去。
- **真实反例**：`parseSnapshot` 只检查 `settings` 存在 → 非法文件可能写一半。
- **过关标准**：宁可拒收，不可写坏；拒绝时给出人话原因。

### 8. 幂等与可重复执行
- **问**：同一个操作连点两次 / 隔几天再点一次，会发生什么？
- **怎么查**：对每个写操作，连续调用两次，看第二次的结果是否与第一次相同、是否重复计入。
- **真实反例**：回档可以无限重复执行，几天后再点一次仍写旧值。
- **过关标准**：写操作带状态标记（`status: pending/rolled-back`），重复执行要么无害、要么被拦。

### 9. 并发与重入
- **问**：两个 GM / 两个标签页 / 双击按钮同时操作，会怎样？
- **怎么查**：开两个客户端同时点同一个按钮；或直接并发调用两次函数。
- **真实反例**：无任何锁，两人同时恢复 → 互相覆盖。
- **过关标准**：有锁或冲突检测；锁要有 TTL，崩溃不留死锁；文档里写清「这是尽力而为，不是原子」。

### 10. 权限纵深防御
- **问**：限制只在 UI 层，还是能力层也拦了？暴露到 `window` 的接口 / 宏 / 控制台能不能绕过？
- **怎么查**：`grep -n "window\."` 找到所有对外暴露的入口，逐个问「非 GM 调用会怎样」。
- **真实反例**：界面对玩家隐藏，但 `window.lhWorldSync.applySnapshot()` 对所有人生效。
- **过关标准**：每个写入口第一行就是身份守卫，并单独测试「非 GM 调用被拒」。

### 11. 文档与实现一致
- **问**：README / 注释 / 提示语里写的，和代码做的一样吗？尤其是**你没验证过就写下的断言**。
- **怎么查**：把 README 里每个「事实性断言」拉出来，逐条去源码里找依据；找不到依据的，删掉或标「未验证」。
- **真实反例**：README 写「同一服务器的所有世界共享用户列表」并标注「坐实」—— 查源码 `users.mjs:21 class Users extends WorldCollection` → **User 是世界级数据**，写反了。
- **过关标准**：文档里每条事实性结论都能指到出处（文件 + 行号）。

### 12. 工程卫生
- **问**：有没有死代码 / 定时器 / 用 `JSON.stringify` 做深比较 / 转义不全 / 版本号不同步？
- **怎么查**：
  - `grep -n "setInterval"` —— 定时器能不能改成事件 hook？（轮询只在**官方没有 hook 且 DOM 会被重建**时才是必要的）
  - `grep -n "JSON.stringify(.*)===JSON.stringify"` —— 对象键序不同会误判成差异，改稳定序列化
  - `grep -n "function .*(" ` 对照调用点找**从未被调用**的函数
  - HTML 转义函数是否转引号（被用在 `value="…"` 属性上下文时必须）
- **真实反例**：死代码 `storageList()` / `getItemValue()`；`isJSONEqual` 用 `JSON.stringify`；`escapeHtml` 不转引号；侧边栏 1.5 秒常驻轮询。
- **过关标准**：上面四条 grep 全部干净，或有明确理由。

### 13. 版本三处同步与部署
- **问**：`module.json` 的 version、JS 头注释、`window.__XXX_VER` 探针 —— 三处一致吗？用户拿到的会是新版吗？
- **怎么查**：三条一起打印对照；打包后在 zip 里再抽验一次。
- **真实反例（反复发生）**：用户只覆盖了 `scripts/` 和 `styles/`，没换 `module.json` → 服务器上跑的是**混合版本**（探针报 v1.6.0，却仍在请求旧版的 `lang/cn.json`）。
- **过关标准**：三处同步 + 探针可查 + 交付话术里**永远强调「整包替换」**。

### 14. 写操作可逆性（最硬的一条）
- **问**：这个操作会不会覆盖 / 删除用户的东西？回得去吗？
- **怎么查**：把每个写操作按「可逆 / 需备份 / 不可逆」标一遍。
- **硬规矩**：
  - 任何**删除、覆盖、替换**——先请示，说清「删什么 / 为什么 / 影响范围 / 有没有备份」，**没同意一律不许删**。
  - 改既有代码前先留一份本地备份（源码全量 + 打包好的旧 zip + git tag）。
  - 升级涉及数据结构变更时，**旧数据只读、不写、不删**：能读就兼容读，确认迁移无误后由用户自行清理。
- **真实反例**：账本改文件名后，如果顺手把旧 `apply-log.json` 删掉，用户就永久失去旧记录（且 v13 无删除 API，删了也回不来）。
- **过关标准**：新版本落地后，旧文件**原样保留**，程序只读它。

#### 14.1 备份/保护动作失败时，该继续还是该停下？（补的判据）

- **判据不是「这个动作重不重要」，而是「这次失败会让用户失去什么」**：
  - 失去**唯一副本 / 唯一撤销点** → **fail closed**（停下，并说清「一个设置都没改动」以及为什么）；
  - 只损失**一次便利**（重试即可） → 可以继续，但**必须出声**，不能静默降级。
- **真实反例（设计取舍本身错了，不是写错）**：某模块把「恢复前另存上一份回档账本」的失败
  处理成 fail-open —— `console.warn` + 通知一句，然后照常写新账本；代码注释里写的理由是
  「不要因为一个辅助动作失败就阻断主操作」。但账本是**唯一**的撤销点，覆盖即永失
  （服务器上没有它的副本，平台也没有删除/恢复文件的 API），而 fail-closed 的代价只是
  「这次没做成，修好磁盘/权限后重试即可」。
- **自检问法**：把每个「失败后继续」的分支挑出来，逐个问 ——
  「这一支继续下去，用户手里会少掉什么？那个东西还能不能再造出来？」
  答案里只要有一个「不能再造」→ 改成 fail closed。
- **配套**：fail closed 抛出的错误要**自带完整说明**（什么失败了、世界有没有被改动、下一步做什么），
  不要让它在通用错误处理里被套上一句不相干的文案。

## 3. 怎么用（SOP · 五步，顺序别换）

1. **动手前**：扫一眼本清单的 14 个标题（10 秒），心里知道这轮要碰哪几条。
2. **写完代码、跑测试前**：以**陌生人视角通读改动所在的整个文件**（不是只看 diff）。
   读的时候把「我本来想干什么」这句话从脑子里删掉，只问「这行字面行为是什么」。
3. **测试通过后、打包前**：逐条走上面 14 项，能 grep 的 grep、能构造场景的构造场景，逐条打勾。
4. **打包后**：走《血的教训-发布校验与查证纪律篇》的产物清单（数文件、对版本、验资产）。
5. **交付时**：主动说清「哪些验过了、哪些没验、没验的部分有什么风险」——
   **不要用「应该没问题」交付。**

### 写新代码时就该有的三个习惯（治根因）

- 每写完一个交互控件，立刻问一句**反面操作**：取消、重复、空选、超量，会怎样？
- 每写完一个持久化动作，立刻问一句**另一个同类对象同时存在**会怎样？
- 每写完一段逻辑，**换个入口再走一遍**：如果自动路径和手动路径都调用它，两条都试。

## 4. 铁律（本次沉淀）

1. **测试全绿 ≠ 没问题**：测试只覆盖你想到的路径；清单负责覆盖你没想到的。
2. **交付前把整体量一遍**，不是只解最后一条需求。
3. **作者视角换掉**：读代码时问「这行字面行为是什么」，不问「我当时想干什么」。
4. **同一规则只写一遍**，多条路径调用同一个函数。
5. **UI 限制 ≠ 能力限制**：写入口一律身份守卫。
6. **文档里的每条断言都要能指到出处**，指不出来就删或标「未验证」。
7. **任何删除/覆盖先请示，改前先备份**；数据升级时旧文件只读不删。
8. **「保守」不能成为「不改」的理由** —— 那往往是维护自己已经写好的东西。
   （本次实例：轮询、账本同文件两条，我上一轮以「风险低」为由没改，被审阅再点一次才改。）
9. **失败策略按「会失去什么」定，不按「重不重要」定**（详见 §2 第 14 项 14.1）：
   失去唯一副本 / 唯一撤销点 → fail closed；只损失一次便利 → 可继续但必须出声。
   **「辅助动作失败就继续」是一个错误的默认值。**
10. **善意的兜底也是语义**：写「检测到异常输入就退回成某种默认行为」之前，先问
    「这个异常输入有没有可能只是我没考虑到的正常需求？」
    （实例：一句「空 custom 视为全部」，把「取消所有模块 + 只保留一个开关」这个
    **完全合法**的组合整份放大成了「全部同步」。）
11. **同一件事有几套语义，就有几个 bug 候选**：范围 / 目标值 / 锁 / 失败策略 ——
    任何一类事实只要有两处以上各自实现，就会出现「用户看到的 ≠ 实际发生的」。
    改的时候必须**逐个点名**：本项目曾把「有效目标值」只改了写入路径、漏了差异检测，
    结果是永不收敛的假差异（恢复 → 刷新 → 报同样的差异 → 再恢复）。
12. **承诺的能力要配得上数据模型，配不上就改承诺**：想用「一个标量锁文件」表达
    「一把全局锁 + 多把世界锁」，在信息量上就不成立 —— 要么改数据模型，要么把
    并行改成串行。**别在实现细节上打转，先看承诺本身能不能兑现。**

## 5. 写给下一个接活的智能体

> 用户花钱买的不是「你写完了」，是「你写对了」。
> 你的测试跑给自己看，所以它永远抓不到你看不见的东西；
> 而这张清单，是别人花了钱替你换来的尺子 —— **别让它躺在硬盘上**。
>
> 每次交付前，照着跑一遍。跑不完就直说跑不完，别假装跑过。
