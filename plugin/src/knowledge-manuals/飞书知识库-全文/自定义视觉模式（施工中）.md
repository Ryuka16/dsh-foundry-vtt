# 自定义视觉模式（施工中）

在FVTT中，所有的视觉模式都被存储为`VisionMode`类，其主要的成员是各种着色器。着色器的功能强大，这是一种直接工作在GPU的程序片段，不过在WEBGL中，我们仅关注着色器中的两类：顶点着色器Vertex Shader和片段着色器Fragment Shader，前者用于处理像素位置，后者用于处理像素颜色。通过自定义这些着色器，我们可以实现绚烂的视觉效果。

有很多专门的编程语言用于编写着色器程序。在浏览器中，我们使用`GLSL`来进行着色器编程，其语法类似于C语言。

在这篇教程中，我们并不会过多的介绍GLSL的语法，因此强烈建议你查阅额外资料以事先熟悉这些知识。

---

在实际介绍`VisionMode`类如何使用之前，我们必须先学习FoundryVTT中是用什么来描述着色器的。在FVTT中，所有着色器类都派生自`AbstractBaseShader`类，其同其它着色器一起位于`foundry.canvas.rendering.shaders`中。

考察其源码或是[文档](https://foundryvtt.com/api/classes/foundry.canvas.rendering.shaders.AbstractBaseShader.html)，我们可以获知其具有以下主要成员：

- `static fragmentShader`。其内应该存放着你的片段着色器代码字符串。
- `static vertexShader`。其内应该存放着你的顶点着色器代码字符串。
- `static defaultUniforms`。uniform是一种使运行于GPU上的着色器程序同运行于CPU上的寻常程序进行数据交互的方法，也就是：在着色器中被uniform修饰的变量可被CPU程序访问。这个静态成员定义了uniform变量的初值。
- `uniforms`。这个成员定义了着色器要用到的uniform变量，我们可以通过修改着色器类实例的这个成员来进行数据传递。

`AbstractBaseShader`是一个虚基类，因此在实际运用中，我们总是使用其派生类们。

现在我们已经知道FVTT是如何组织一个着色器程序的了，让我们开始正式对`VisionMode`类的学习！

---

当我们查询或修改角色的视觉模式时，FVTT会读取位于`CONFIG.Canvas.visionModes`中的`VisionMode`实例，然后将其作为选项提供给用户。如果我们想要使用自定义的`VisionMode`类，那就必须将其存储在这一数据路径下。

一个`VisionMode`类由数个着色器类组成，它们大多运行于不同的场景层。你可以通过`foundry.canvas.perception.VisionMode`访问到它。

<callout emoji="💬">
在FVTT中，一个场景由数个层构成，每一层都负责各自的渲染任务：GridLayer负责渲染场景上的网格，WeatherEffects负责渲染场景天气等视觉效果，TileLayer负责存放和渲染你的图块……
VisionMode通过替换指定场景层中的着色器来达成功效。不同的场景层会调用着色器类的`create`静态方法，将其存储在特定位置。以GridLayer为例，其着色器程序能使用`canvas.layers[1].mesh.shader`进行访问。
</callout>

让我们先来考察`VisionMode`类的canvas成员。它用于调整角色视野之外，已探索区域战争迷雾的颜色。我们最终所得的颜色结果等于：canvas内片段着色器的颜色结果 和 场景设置中已探索区域战争迷雾颜色 的混合。

canvas具有两个成员：`shader`：一个着色器类，其特殊点在于必须是`ColorAdjustmentsSamplerShader`或其派生类；`uniforms`：其内存放着色器所要用到的uniform变量的初值。在下面这个示例中，我们的重点将放在shader上而非uniforms。

`ColorAdjustmentsSamplerShader`已经为我们实现了顶点着色器和片段着色器，因此我们只需要按需进行修改。以下程序片段派生了一个着色器类，并修改了其片段着色器，令其颜色随时间而变化：

```JavaScript
class CoolVisionShader extends foundry.canvas.rendering.shaders.ColorAdjustmentsSamplerShader {
  static fragmentShader = `
    uniform float uTime;
    void main(){
    float time = uTime/10000.0;
    gl_FragColor = vec4(abs(sin(time*5.0)),abs(sin(time)),abs(sin(time*10.0)), 1.0);
  }`;
  _preRender(mesh, renderer) {//每帧都会调用一遍这个方法。
    super._preRender(mesh,renderer);
    const uniforms = this.uniforms;
    uniforms.uTime = game.time.serverTime;
    //ColorAdjustmentsSamplerShader并没有类似于uTime这种随时间变化的uniform变量，
    //因此我们需要自行创建。
  }
};

class CoolVisionMode extends foundry.canvas.perception.VisionMode{
  /*animate(dt){
    super.animate(dt);
    canvas.primary.sprite.shader.uniforms.uTime = game.time.serverTime;
  }*/
  //另一套运行时修改uniform的方法，需要在VisionMode.animated为真时才会调用。
}

const coolVisionMode = new CoolVisionMode({
  id: "cool-vision",
  label: "Cool Vision",//显示给用户的名称。
  canvas: {
    shader: CoolVisionShader
  }
});
//coolVisionMode.animated=true;

CONFIG.Canvas.visionModes["cool-vision"] = coolVisionMode;
//存储的键名必须等于这个VisionMode的id
```
