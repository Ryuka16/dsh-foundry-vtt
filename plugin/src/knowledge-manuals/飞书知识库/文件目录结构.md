# 文件目录结构

通常的，一个游戏系统存储在 `FVTT用户数据路径/Data/systems` 中。观察其中已经存在的游戏系统实例，你会发现，系统的文件目录结构大致如下：

```Plain Text
your-system-id/
├─system.json
├─your-system-id.mjs
├─assets/
│ ├─logo.webp
│ └─pic.webp
├─lang/
│ ├─cn.json
│ └─en.json
├─templates/
│ └─characterSheet.hbs
└─......
```

在这繁多的文件中，只有一个是**必须**提供给FVTT的：`system.json`。一个没有`system.json`文件的系统不会被FVTT读取。

`system.json`必须被放置在系统的顶层目录。它通常会包括这个系统的规范化描述：名称，id，作者，认证版本号……

让我们观察一个可能的`system.json`实例：

```JSON
{
    "id":"helloworld",
    "title":"你好世界！",
    "description":"一个简单的自建系统。",
    "version":"0.0.1",
    "compatibility":{
        "verified":13
    },
    "authors":[{
        "name":"paper1"
    }],
    "documentTypes":{
        "Actor":{
            "character":{}
        },
        "Item":{
            "weapon":{}
        }
    }
}
```

其中，三个字段尤其值得注意：

- id代表此系统的唯一标识符。它应当同系统所在的文件夹名称相同，且由小写字母组成。
- title代表此系统展示给用户的，人类可读标题。

FVTT规定，一个`system.json`**必须**具有上述两个字段。

- documentTypes声明了对应文档的子类型。对于`Actor文档`——即我们平日使用的角色所对应的文档，我们为它声明了一个叫做character的子类型；对于`Item文档`——即我们平日使用的物品所对应的文档，我们为它声明了一个叫做Item的子类型。

若一个文档不具备可用的子类型，那么它是无法被正常创建的。好在，FVTT默认地为除人物和物品以外的文档都创建了对应的类型，因此我们只需要对这二者进行类型声明。

将这个系统放置到 `FVTT用户数据路径/Data/systems` 中，然后重启你的FVTT。此时，你应当已经可以看到FVTT载入了这个系统，并且能够用它来正常创建世界了。

进入世界后，你应该会发现在创建角色或物品时，可以选用自己声明的类型来创建。

这个系统尤为重要，此后若无特殊提及，则我们默认都是在基于这个系统进行讨论和开发。

---

`system.json`中的可用字段当然不止这些！你可以访问[这里](https://foundryvtt.com/article/system-development/#manifest)来获得更多关于可用字段的信息。

`system.json`会被FVTT用来实例化一个System类。你可以通过game.system访问到它。
