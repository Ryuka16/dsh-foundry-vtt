# 部署与排障（内置手册 · 随插件发布）

> 本文件随插件包发布，任何环境都能读到（topic: `deploy`）。
> 遇到「配对 / 装模块 / 连不上 relay / 请求超时 408」**先读这里**：不要自己造脚本，不要靠猜，不要逐文件读 relay 源码找根因。

---

## 一、架构（30 秒看懂）

```
DSH 插件 ──HTTP──▶ http://localhost:3010（relay，跑在用户本机）
                        ▲
                        │ WebSocket（由 FVTT 页面主动拨出）
                        │
              FVTT 页面（GM 浏览器）──▶ 模块 foundry-rest-api ──▶ 世界
```

关键点：**通道由 GM 浏览器里的那个 FVTT 页面发起**。所以 FVTT 服务器不需要开端口、不需要公网、不需要内网穿透。代价是——**那个 FVTT 页面必须开着**，关掉页面世界就离线。

---

## 二、一次性安装（四步）

1. **FVTT 装模块**：manifest URL
   `https://github.com/ThreeHats/foundryvtt-rest-api/releases/latest/download/module.json`
   装好后在模块列表**启用**（模块 id：`foundry-rest-api`），然后刷新页面。
2. **启动 relay**：拿到 `relay.exe`（编译或用发布包），改 `start-relay.ps1` 里的 `ADMIN_EMAIL` / `ADMIN_PASSWORD`，双击 `start-relay.bat`。
   验证：浏览器打开 `http://localhost:3010/api/health` 返回 `ok`。
3. **模块里配对**：模块设置 → REST API Connection → Manage Connection →
   - 「Edit URL」填 `ws://localhost:3010`（**必须 ws:// 开头**，填 http:// 连不上）
   - 点「Enter Code」，输入 6 位配对码（配对码怎么来见第三节）
4. **建 API key + 写配置**：
   - `POST /auth/login {email,password}` → 拿 `sessionToken`
   - `POST /auth/api-keys`（Bearer session，body `{name, scopes:[...]}`，**不传 `scopedClientIds` = 全局 key**）→ 拿 `key`
   - 写 `~/.dsh/dsh-foundry-vtt/config.json`（UTF-8 **无 BOM**）：`{"relayUrl":"http://localhost:3010","apiKey":"<key>","clientId":""}`

---

## 三、配对码怎么来（AI 直接调工具，别自己实现）

**首选：调 `foundry_mint_pairing_code`**。它内部走完整个流程（字段均取自 relay 源码 `auth.go` / `pair_request.go`）：

| 步骤 | 请求 | 关键返回 |
|---|---|---|
| 1 | `POST /auth/login` body `{email,password}` | `sessionToken` |
| 2 | `POST /auth/pair-request` body `{worldId(必填),worldTitle,systemId,serverFingerprint}`（匿名可调） | `{code, pairUrl}` |
| 3 | `POST /auth/pair-request/{code}/approve`（Bearer session）body `{remoteScopes:["*"],allowedTargetClients:[],remoteRequestsPerHour:10000}` | `{success:true}` |
| 4 | `GET /auth/pair-request/{code}/status`（匿名） | `{status:"approved", pairingCode:"XXXXXX"}` |

把 `pairingCode` 给用户，让他在模块里点「Enter Code」输入（**5 分钟内有效**）。

若工具报「未配置 relay 管理员账号」→ 让用户在 `config.json` 补 `relayAdminEmail` / `relayAdminPassword`（必须与 relay 启动时的 `ADMIN_EMAIL` / `ADMIN_PASSWORD` 一致）。

> ⚠️ 不要写 `.ps1` 脚本去实现这个流程：Windows 默认执行策略会拦（`running scripts is disabled on this system`），实测三次全失败，白耗时间。

**配对是「一次配一个世界」**：换世界 / 开新世界要重新配对一次，配对过就永久有效。`clientId` 变了才需要重建 API key。

## 四、故障速查表

| 现象 | 根因 | 处理 |
|---|---|---|
| `relay 返回 HTTP 408：{"error":"Request timed out"}`，但世界显示 online | relay↔模块 WebSocket 僵死 | **重启 relay**（见第五节） |
| 工具报 `No connected Foundry clients found` | 世界页面没开 / 模块没配对 | 让用户打开 FVTT 世界页面并确认配对 |
| `Multiple clients connected` | 同时开了多个世界页面 | 让用户只留一个世界页 |
| `API key is not authorized for this client` | key 是 scoped 且不含该世界 | 换全局 key（建 key 时不传 `scopedClientIds`） |
| `relay 返回 HTTP 401` | apiKey 错/失效 | 重新建 key 并更新 config.json |
| 工具报 `xxx is not a function` | 插件没加载 | 让用户刷新 DSH，或 `dev_reload_package dnd-foundry-vtt` |
| 模块里改了设置没生效 | 模块设置**只能人手点** | 脚本无法修改（`Scripts cannot modify REST API module settings`） |
| `/api/clients` 返回 404 | 路径错 | 数据 API 无 `/api` 前缀：正确是 `/clients`（只有 `/api/health` 有） |
| `abilityUuid or abilityName is required` | dnd5e 的 use-item 等工具只传了 itemName | 补 `abilityUuid` 或 `abilityName` |

## 五、408「世界显示在线，但所有请求超时」（最高频、最耗时的坑）

**现象**：`foundry_list_worlds` 返回 `online: true`，`/clients` 也 200，但任何数据工具都报
`relay 返回 HTTP 408：{"error":"Request timed out"}`。

**根因**：relay 与 FVTT 模块之间的 WebSocket 连接僵死——relay 侧仍登记着客户端（所以显示「在线」），但模块进程已不再回包。**「在线」是假象。**

**处理（实测有效，30 秒）**：
1. 结束 `relay.exe` 进程；
2. 重新启动 relay（DSH 启动时插件会自动拉起；也可双击 relay 目录的 `start-relay.bat`）；
3. FVTT 页面按 F5 刷新一次（模块会重连）；
4. 重试原操作。

**不要做的事**（都是实测踩过的）：
- ❌ 逐文件读 relay 的 Go 源码找根因 —— 朋友那台为此耗掉近一小时，最后结论就是「重启 relay」；
- ❌ 反复重试同一个请求（会撞上「重复工具调用」检测）；
- ❌ 以为世界没开、去 FVTT 里翻设置。

> 插件已内置自诊断：遇到 408 会在错误信息里直接给出上面的结论和处理办法，不需要人肉分析。

## 六、配置文件字段

`~/.dsh/dsh-foundry-vtt/config.json`（UTF-8 **无 BOM**，否则 JSON.parse 失败）：

```json
{
  "relayUrl": "http://localhost:3010",
  "apiKey": "<全局 API key>",
  "clientId": "",
  "relayExePath": "C:\\path\\to\\relay.exe",
  "relayDataDir": "C:\\path\\to\\relay\\data",
  "relayAdminEmail": "you@example.com",
  "relayAdminPassword": "<relay 启动密码>",
  "knowledgeDir": "",
  "sampleDir": ""
}
```

- `apiKey`：**全局 key**（建 key 时不传 `scopedClientIds`），多世界通吃；
- `clientId`：留空 = 自动路由到「当前唯一在线」的世界（推荐）；
- `relayExePath`：填了才会在 DSH 启动时自动拉起 relay（不填则需手动启动）；
- `relayAdminEmail` / `relayAdminPassword`：填了才能用 `foundry_mint_pairing_code`。

## 七、日常运维

- **备份 `relay.db`**（在 relay 的 `DATA_DIR`，默认 `<relay.exe 同目录>/data/`）：配对记录和 API key 都在里面，删了就全丢，要重新配对 + 重建 key。
- relay 没开机自启 → 在 config.json 配 `relayExePath`，DSH 启动时插件会自动拉起；或把 `start-relay.bat` 放进启动文件夹。
- 云端 FVTT 与本地 relay 完全解耦：relay 只连「浏览器里的那个页面」，不碰服务器端口。
