# 04 · 纪律与坑（内置知识）

> 来源：血的教训-开工方法论五病根七铁律 + 之前踩过的坑.txt + FVTT-已验证机制速查与开工铁律 + 图标真源。速查版：foundry_reference{topic:"iron-rules|pitfalls"}。

## 开工五病根（对照自查）

1. 臆造优先于查证——键名/路径凭记忆写
2. 把资料当实测——资料写了就以为能跑
3. 未验证即交付——没本地验证就发给用户
4. 绕路不复盘——踩坑后不记教训，下次再踩
5. 教训不闭环——坑不沉淀回资料库

## 七条根治铁律

1. 开工三查：先查参考库 → 再查资料库（foundry_knowledge）→ 最后才猜
2. 出处责任制：交付的每个键名/参数/路径必须能指出处
3. 先方案后代码：动手前想清楚失败点、报错、补救
4. 本地验证：能验证的部分先验证再交付（JSON 结构、引用完整性）
5. 资料 ≠ 实测：资料库内容标注「未实测」的一律实测后用
6. 失败走三步：如实报错 → 换思路 → 说明新旧方案区别
7. 教训即时沉淀：验证过的机制立刻写回资料

## 高频坑速查（pitfalls）

- **effects 层级**：ActiveEffect 挂物品顶层 effects 数组；activity.effects 是空壳 `{_id, onSave:false}`——往里塞 name/statuses/duration 会被 dnd5e 5.3.x 清洗成空
- **伤害骰两说**：5.3.x 走 `damage.base{number,denomination,bonus,types}`；旧版 `parts[].formula` 会被清洗。版本不明先 get_entity 读一个现成物品照抄
- **DC 两说**：`dc.calculation:"flat"` 实测落库保留；另有资料记载 flat 不合法被丢回默认 10。DC 不生效时改 `calculation:""` + `formula:"16"`
- **activity _id**：必须 16 位字母数字（如 dnd5eactivity100）
- **图标 404 清单**：icons/svg/status.svg、trap.svg、dice-target.svg、claw-hooked-barbed.webp 等不存在——图标写死前用 list_status_effects 或资料库图标真源 grep 确认
- **update 回读误报**：写操作报「does not exist / failed to update」多为模块端 fromUuid 间歇失败，写入实际已执行——先 get 读回确认再判定失败
- **execute_js**：默认被 REST API 模块设置禁用（400 "execute-js is disabled"）——优先用 update_entity 内嵌 uuid
- **内嵌物品 uuid**：`Actor.<actorId>.Item.<itemId>` 可直接读/改 actor 身上物品
- **查询数组参数**：JSON 数组（如 details）必须 JSON 字符串序列化，直接 String() 会 400
- **中文/UTF-8**：配置走 JSON 文件（UTF-8 无 BOM）；PowerShell 管道写中文会 GBK 损坏——验证时别把 pwsh 显示乱码当数据错误

## 卡面纪律

- 卡面描述必须有对应真实机制（无机制的纯风味文字禁止）
- 怪物数值按 CR 设计（monster-spec 表），写后自我审查：AC/HP/AB/DPR/豁免是否对档
- 状态自动化优先用现成 statusId（list_status_effects），不要手搓重复 ActiveEffect

## 世界数据纪律

- 删除/覆盖前必须确认（delete 不可逆）
- 改世界数据前先 get 读现状；改后回读确认
- 世界内 Scene 用 get_scene 查（search 只索引 compendium）
- 放 token 先 get_scene(active=true) 拿网格尺寸，x/y 取 grid 整数倍且在场景尺寸内
