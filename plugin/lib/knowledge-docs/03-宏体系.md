# 03 · 宏体系（内置知识）

> 来源：data-dict v9.1 §20/§21/§22/§26 + midi 物品宏使用指南提炼。纯文本宏走 foundry_create_entity{entityType:"Macro"}。

## 宏能挂在哪（6 位置）

快捷栏 / 角色卡（actor）/ 物品（item）/ Hook（世界脚本）/ 区域图块（tile）/ DAE 效果（macro.* 特殊键）。物品宏标准三件套见 02-效应配方「物品宏」。

## Document 模型铁律（写宏必背）

- 直接给 doc 属性赋值只改本地内存，**必须 `await doc.update({...})`** 才持久化到库
- 传 schema 之外的字段会被系统**静默忽略**（不是报错——别以为写了就生效）
- 写 flag：`await doc.setFlag(scope, key, value)` / 读 `doc.getFlag(scope, key)` / 删 `doc.unsetFlag`
- 取文档：`fromUuid()` 异步（推荐，会自动处理 compendium）/ `fromUuidSync()` 同步（仅世界内文档）
- v12+ 状态切换：`actor.toggleStatusEffect("poisoned", {active:true})`
- DialogV2：content 里的内联 onclick 不生效（要事件就上 FormApplication）
- 宏 JSON 导入：删掉 _id / author 字段；Import Data 只认单个对象

## MidiQOL 常用函数（§21 精选）

- `workflow` 变量 = 当前工作流（宏内直接可用）；`MidiQOL.currentWorkflow` 兜底
- workflow.hitTargets（实际命中的）/ workflow.targets（全部目标）/ workflow.actor（攻击者）/ workflow.item（物品）/ workflow.damageRoll / workflow.attackRoll
- miss 判定：hitTargets 为空数组 = 没命中。切勿用 `hitTargets.length > 0` 判命中（施放瞬间 targets 已计入，必然 >0）
- 目标兜底链：`wf?.hitTargets?.[0] ?? wf?.targets?.[0] ?? game.user.targets?.[0]`
- 自己兜底：`canvas.tokens.controlled[0] ?? token`

## 世界脚本（world-script）与 CPR fork

- 世界脚本写 `Hooks.on(...)`，打包发布用 `export let <identifier> = {...}` + rules；CPR fork 改宏：export let 改 return，`identifier` 全小写唯一 + `rules` 数组逐条
- 用户侧坑：world.* 命名空间的事件玩家端静默丢弃；socket 才能让玩家端通知 GM 做事（`module.<id>` 且 manifest `socket:true`）

## DAE 宏

- 挂法：`flags.dae.macro = {name, type:"script", scope:"global", command}`
- 执行时机键：macro.execute（效果每次生效）/ macro.itemMacro / macro.createItem / macro.createItemRunMacro / macro.actorUpdate / macro.deleteUuid
- args[0]="on"（激活）/ "off"（移除）/ "each"（每轮）；off/each 分支必须用 `lastArg = args[args.length-1]`（args[0] 是 on/off 不是数据）
- effectmacro 在 onLongRest 不触发 → 改用物品 uses recovery:"lr"

## 远程委托（socket）备忘

玩家端无权改他人/场景 → 委托 GM：world 脚本里 socket 请求 `game.socket.emit`；GM 端 `Hooks.on` 监听执行。委托操作支持 move / addStatuses / damage / deleteFlag / deleteEffectIds / createEffects（LHGM.request({sceneId, ops}) 形态）。ownership 深合并收回权限：`{"-="+userId: null}`。
