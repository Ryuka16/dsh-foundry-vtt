## 三十秒速览

**在做什么**
把 `dnd5e_classpack`（21 个 compendium 包 / 约 4900 件）里的物品、法术、专长、种族特性、职业子职，
**逐件核对「描述说的」和「数据实际做的」是否一致**，发现错误就修，目标是：
> 「PL 车卡拖进去就是好的，有自动化的，效果齐全的，能用的不会报错的，拿起来就能用的」

**三条硬约束（不可违反）**
1. **改包，不改卡** —— 只改 `dnd5e_classpack.*` 里的原件；玩家卡上的副本是独立副本，不碰
2. **不动 PL 卡** —— 5 张（维兰/贝瑟/安史地/星逸/伦恩.雷德），`hasPlayerOwner=true`，一张都不许改
3. **删除 / 覆盖前必须请示** —— 说清删什么、为什么、影响范围、有没有备份

**当前进度**
- 内容层 1082 件带效果物品：**逐件核对完成**
- 抽样 100 件逐条人工读：**9 件真错已修**
- 全库复扫：**断链 0 / 非法枚举 0 / 无活动武器 0**（剩余 6 个假状态 id 是用户同意保留的）
- 未完成：见 `06-没做完的事.md`

### 2. 判据只信三种外部锚点
```
✅ 官方包逐字段对照   方向只有一条：官方有 ⟹ 本包必须有（0 误报）
✅ 规则书原文         00_规则资料\5E 不全书-纯文本\  （grep 出文件名+行号再 read）
✅ 运行时实测         装到临时角色上量派生值 + 假键做空白对照
❌ 中文描述 ⇄ 程序结构 的静态判据 —— 精确率长期 0~25%，一律不要用
```

### 3. 动手前过三道闸
```
① 勘察闸  模块 CHANGELOG + module.json + 目录 + 200 件样本，一次拿全
② 因果闸  说不出「X 改正确之后 Y 会变成什么」就不许改
③ 备份闸  说不出怎么恢复就不许执行；dump 后必须落盘成本地文件
```

## 最后一句

**这个项目真正的教训只有一条**：
> 中文描述和程序结构之间**没有**可靠的自动判据。
> 唯一靠得住的是「官方包怎么写的」「规则书怎么说的」「实际跑一遍会怎样」这三件事。
> 任何"我觉得应该"都是错的开始。
