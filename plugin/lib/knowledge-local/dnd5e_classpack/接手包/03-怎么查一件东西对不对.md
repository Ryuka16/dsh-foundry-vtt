# 03 · 怎么查一件东西对不对

> **这是整个项目最核心的一篇。**
> 判据：**「效果实际做的事」 ≠ 「描述说的事」**（典型：重力井 —— 描述说"移动至由你选择的空间"，实际是无条件强制推离 5 尺）。
>
> 本项目的目标不是"全库健康"这四个字，而是**逐件找这种错配**。

---

## 〇 · 先记住一件事：为什么不能靠自动判据

**实测战绩表（真金白银换的）**

| 判据 | 命中 | 真错 | 精确率 | 结论 |
|---|---|---|---|---|
| **描述时长 ⇄ 活动/效果 duration** | 22 | **14** | **64%** | ✅ 唯一全对的通用静态判据 |
| **官方包逐字段对照** | 160 | 全部有效 | **~100%** | ✅ 方向：官方有 ⟹ 本包必须有 |
| **引用断链扫描** | — | 全部有效 | **~100%** | ✅ |
| **运行时枚举合法性** | 14/24 | 全中 | **~100%** | ✅ |
| 描述骰子 ⇄ 数据骰子 | 多轮 | — | **0~25%** | ❌ 三次迭代全失败 |
| 描述状态名 ⇄ statuses | **588** | ~0 | **~0%** | ❌ |
| change 键 ⇄ actor schema | **333** | **3** | **0.9%** | ❌ **最危险** |
| 机制词 → 必备字段 | **719** | 极少 | **~0%** | ❌ |

**为什么失败：中文自然语言和程序结构之间没有可靠映射。**
- 「描述提到"中毒"」≠「这件东西会施加中毒」——可能只是在说"免疫中毒"
- `change` 键不在 actor schema 里 ≠ 无效 —— 433 条"失效键"实测**只有 3 条真死**（`system.traits.di.all`）。
  **不实测就批量改，会毁掉 430 条正确数据。**

**⇒ 三条铁律**
1. 自动判据只用来**缩小范围**，不用来**定罪**
2. 命中数超过个位数 ⇒ **判据错，不是包错**
3. 最终一定要**人工逐条读**，或**运行时实测**

## 一 · 查一件东西的八步流程

### 第 0 步 · 先拿资料（别跳过）

**看什么**：它声称做什么、什么时候能触发、持续多久、给谁、对抗什么、数值多少。


### 第 2 步 · 读数据（一次拉全，别挤牙膏）

### 第 3 步 · 查外部锚点（三选一或全用）

**A · 规则书原文**（最权威）
```
00_规则资料\5E 不全书-纯文本\    （4276 个 .txt / 18.5 MB）
```
搜索技巧：
- 中文和英文之间**没有空格**（`野兽知觉Beast Sense`）—— 单独搜中文名或英文名
- 搜不到就**换词根**（葡萄酒 → 酒 → Wine），**不要凭译名直觉断言"资料库没有"**
  （PHB 把 `Wine` 译作「红酒」而非「葡萄酒」）
- 先 grep 拿**文件名 + 行号**，再 read 精读那一段，**不要整读大文件**
- ❌ 别搜 `5E 不全书 v2024.6.1 原汁原味版\`（原始 HTML，中文词组被 `<span>` 物理切断，搜不到）

**B · 官方包逐字段对照**
```
dnd5e.spells / dnd5e.items / dnd5e.classes / dnd5e.subclasses
dnd5e.classfeatures / dnd5e.races / dnd5e.monsters
```
- **方向只有一条：官方有 ⟹ 本包必须有**（0 误报）
- 反向（本包有而官方没有）**全是增强，不动**
- ⚠️ 匹配必须**带 magicalBonus 做键**：官方同一归一化名下躺着 +1/+2/+3 三件，
  只按名字去重会把「胸甲+3」配到官方「胸甲+1」，凭空造 20 条假警报
- ⚠️ 格式差异要识别：本包效果带 `Convenient Effect: ` 前缀 ⇒ 字面不等但内容相同 ⇒ 误报
- ⚠️ 一次只取单个包 `game.packs.get("dnd5e.items")`（872 件）；遍历全部 `dnd5e.*` 必 408

**C · 运行时实测**（见第四节，最有力）

### 第 4 步 · 对四问（**这是人工核对的核心动作**）

```
问 1 · 描述说的动作，活动里有吗？
        「附赠动作」⇄ activation.type === "bonus"
        「反应」    ⇄ activation.type === "reaction"
        「1 动作」  ⇄ activation.type === "action"

问 2 · 描述说的对抗方式，豁免/攻击写对了吗？
        「DC 15 体质豁免」⇄ save:{ability:["con"], dc:{calculation:"", formula:"15"}}
        「法术攻击」      ⇄ attack:{type:{value:"spell"}}
        ★ DC 属性也要对：奥术射击 = 8+熟练+智力 ⇒ dc.calculation = "int"

问 3 · 描述说的结果，效果里有吗？
        「挂中毒」  ⇄ 效果 statuses 含 "poisoned"
        「抗性」    ⇄ changes 含 system.traits.dr.value
        「加 AC」   ⇄ changes 含 system.attributes.ac.bonus
        「加移速」  ⇄ changes 含 system.attributes.movement.*

问 4 · 描述说的时长，两处都写对了吗？（★ 唯一全对的自动判据）
        「N 分钟」⇄ 活动 {value:"N",units:"minute"} ∧ 效果 {seconds:N*60}
        「1 回合」⇄ 活动 {value:"1",units:"turn"}   ∧ 效果 {seconds:6}
        「专注」  ⇄ concentration:true + flags.dae.specialDuration:["concentration"]
        「永久」  ⇄ 两处都不写
        ★★ 活动是 "inst" 时，效果必须自己写 duration.seconds —— 否则 0 秒立即掉
```

```
物品 flags["chris-premades"].info.identifier → CPR 宏库里必须存在
```

## 二 · 判据三档（用哪一档，看你有多少信心）

### 第一档 · 高精度（可直接定罪）
```
① 官方包逐字段对照        官方有而本包没有 ⇒ 缺
② 引用断链                指向不存在的东西 ⇒ 断链
③ 枚举值非法              不在 CONFIG 表里 ⇒ 非法
④ 描述时长 ⇄ duration     对不上 ⇒ 错（64% 精确，需人工复核）
⑤ 运行时实测              值没变 ⇒ 无效
```

### 第二档 · 缩小范围（必须人工复核）
```
⑥ 机制词 → 必备字段       命中 719 件、真错极少 ⇒ 只用来列候选
⑦ change 键 ⇄ actor schema 333 命中 / 3 真错 ⇒ 只用来列候选
⑧ 效果名指向另一物品       14 命中 / 2 真错 ⇒ 好判据但要逐条看
```

### 第三档 · 禁用（精确率 0~25%，用了就是浪费时间）

```
❌ change 键 ⇄ actor schema
   433 条"失效键"实测只有 3 条真死（system.traits.di.all）
   ★ 不实测就批量改 = 毁掉 430 条正确数据
```

## 三 · 分对象专属清单（一票否决项）

### 3.1 物品（weapon / equipment / consumable / loot / tool / container）

| 查什么 | 一票否决项 |
|---|---|
| 类型对不对 | 描述明写是武器/护甲，却是 `loot`/子型 `gear` ⇒ **错**（loot 不支持 activities、不进武器栏、不参与 AC） |
| AC 双算 | 魔法护甲把加值算进 `armor.value` 又填 `magicalBonus` ⇒ **双算**。规律：本包 value 应 = 官方基础值 |
| 护甲特性 | 重甲缺 `stealthDisadvantage`；精金系列还缺 `ada` |
| 武器活动 | 「+N 加值武器」缺 attack 活动 ⇒ 拖出来点它没有攻击按钮 |
| 武器射程 | 远程武器必须给 `rangeValue`，否则落默认 20ft |
| 武器基础 | `system.damage.base` 有骰子（**不是** parts），attack 活动 `includeBase:true` + `parts:[]` |
| 消耗品 | `uses.max` 与描述对得上吗？药水/弹药/毒药/卷轴 `autoDestroy:true`；**魔杖/法杖 false** |
| 效果时长 | 魔法物品的 transfer 效果需要**装备 + 同调**才生效 |
| 同名空壳 | 同名 + **描述逐字一致** ⇒ 真重复；描述不同 ⇒ 变体，不动 |

### 3.2 法术

| 查什么 | 一票否决项 |
|---|---|
| 环阶/学派 | `system.level` 与 `school` 对得上规则书吗 |
| 活动类型 | 要目标豁免的，是 `save` 活动（**不是 `attack`** —— 弹 d20 就是错）；要过攻击的，是 `attack` |
| **`spell.level` 必须给数字** | 给 `null` ⇒ `TypeError: Cannot convert undefined or null to object`，**连最小 cast 都建不了**（包内既有的 `level:null` 是系统规范化后的形态） |
| DC 公式 | 固定 DC 写 `{calculation:"", formula:"15"}`；跟随施法 DC 写 `{calculation:"spellcasting", formula:""}` |
| 升环缩放 | 写 `(ceil(@classes.fighter.levels/17)*2)d6` 这种公式 |
| cast 活动 uuid | 不能是 Plutonium 伪 uuid（世界未装 plutonium 时 `fromUuid` 返回 null ⇒ 点了没反应不报错） |
| 天生法术 | 种族天生法术一律 `method:"innate"` + `{max:"1",per:"lr"}`；戏法才是 max 空 |
| `spellbook` 三要素 | `canUse ∧ magicAvailable!==false ∧ spell.spellbook` ⇒ 种族的 cast 活动要 `spellbook:false`；L3+ 领域法术表是 `true`（走法术位、本就无 max） |

### 3.3 专长（feat）

| 查什么 | 一票否决项 |
|---|---|
| **四形态并集** | `effects` 空**不等于**没效果：自选专长走 `flags["your-feats"].options`；CPR 走 `embeddedMacros`；光环走 `flags.ActiveAuras`；原生走 `flags.dnd5e.*` |
| 属性加值 | 描述给 +1，数据里有没有（可能在自选项里） |
| 被动特性 | `type:"feat"` + `transfer:true` 效果 ⇒ 拖进去即生效 |
| 自身 vs 目标 | 给自己挂的用 `transfer:true`；给目标挂的不能 transfer |

### 3.4 种族特性

| 查什么 | 一票否决项 |
|---|---|
| `languages.value` | **必须全大写 `"ALL"`**（dnd5e `prepareLanguages()`: `if (languages.value.has("ALL"))`） |
| 感官键 | `system.attributes.senses.darkvision` 平铺路径**有效**，与 `ranges.*` 互通；**mode 2 = 相加**，mode 4 = 取大 |
| 移速 | `system.movement.walk/fly/swim`；跟随后者写 `{mode:5, value:"@attributes.movement.walk"}` |
| 天生法术 | 见 3.2 |
| 抗性/免疫 | Trait advancement `choices:[{count:1, pool:["dr:acid",...]}]`（pool 语法：`dr:`/`di:`/`dv:`/`ci:`/`skills:`/`languages:`/`tools:`） |

### 3.5 职业 / 子职

| 查什么 | 一票否决项 |
|---|---|
| **`spellcasting.ability` 污染** | `progression === "none"` 的职业（武僧/野蛮人/战士/游荡者）**必须 `ability:""`**。否则卡面凭空多出「法术 DC / 法术攻击」（dnd5e 拖入职业时无条件写 `attributes.spellcasting`，**不检查 progression**；DC 兜底 `ability.dc : 8 + prof` ⇒ 永远有值） |
| 施法职业 | 与官方 `dnd5e.classes` 逐字对照（牧师 = `{"progression":"full","ability":"wis","preparation":{"formula":"@abilities.wis.mod + @classes.cleric.levels"}}`） |
| **advancement 空 ≠ 缺口** | dnd5e **5.x 用 `class.system.spellcasting`** 表达施法，不是 Spellcasting advancement。14 个职业全无 Spellcasting advancement 是**正确的** |
| 授予链 | 检查 `advancement` 里的 uuid 能不能在世界/包里找到 |
| 消耗目标 | 见 3.6 |

### 3.6 ⚠️ 消耗目标（高频错误源）

dnd5e 源码 `Activity#_remapConsumptionTarget`：
```js
if (!target || !this.actor || this.actor.items.has(target)) return target;
const {type} = foundry.utils.parseUuid(target) ?? {};
if (type === "Item") { const item = this.actor.sourcedItems?.get(target)?.first(); if (item) return item.id; }
else { const item = this.actor.identifiedItems?.get(target)?.first(); if (item) return item.id; }
return target;
```
**三种合法写法 —— 判据只有一条：能不能在「这张 actor」上找到。**
```
① 空串        → 指向自己物品的 uses
② 物品 uuid   → 必须与 advancement 实际装入的那个池一致
③ identifier  → ★ 最稳（如 "channel-divinity"）
   官方还支持 feat:<identifier> 语法（如 feat:bardic-inspiration）
```
**真实错例**：包内有两个**同名同 identifier** 的引导神力池（`v8z4Z2NuBAbYnjxk` uses.max=1 与
`WPevnsjK8Cjd9Fcl` uses.max=`floor((@classes.cleric.levels+6)/12)+1`），牧师 advancement 装的是后者，
23 件子能力却写死前者的 uuid ⇒ **找不到 ⇒ 报「无法找到由行动 X 配置在物品 Y 上的耗用项」**。

**⚠️ `consumption.targets` 的 `spellSlots` 类型下 `target` 字段完全被忽略**（只能 `itemUses` 分支用）。

## 四 · 运行时实测（唯一能证明「键生效」的方法）

### 4.1 核心原则
```
写 change → 读一个会被它影响的**派生值**（AC / 移动力 / 抗性集合 / 技能优势）
         → 同时用**假键**做空白对照
```
**★ 写假键后读"键自己"也能读到值** —— DAE 只是把 change 写进 data，不代表生效。
**必须读派生值。**

### 4.2 测试桩标准流程
```js
// ① 建临时桩（用现成的也行）
const 桩 = await Actor.create({ name:"LH测试桩", type:"npc", system:{ attributes:{ hp:{value:9999,max:9999} } } });

// ② 记录基线（★ 必须基数化，Set 要 Array.from）
const 基线 = {
  ac: 桩.system.attributes.ac.value,
  dr: Array.from(桩.system.traits.dr.value),
  dv: Array.from(桩.system.traits.dv.value),
  ci: Array.from(桩.system.traits.ci.value),
  walk: 桩.system.attributes.movement.walk,
  swim: 桩.system.attributes.movement.swim,
  暗视: 桩.system.attributes.senses.darkvision,
  str: 桩.system.abilities.str.value
};

// ③ 装入并装备+同调（★ 魔法物品必做）
const 物品数据 = (await pack.getDocument(id)).toObject();
delete 物品数据._id; delete 物品数据._stats;
物品数据.system.equipped = true;
物品数据.system.attunement = "attuned";
const [装上] = await 桩.createEmbeddedDocuments("Item", [物品数据], { keepId:false });
await new Promise(r => setTimeout(r, 300));       // ★ DAE 写 flag 需要一拍

// ④ 读变化
const 后 = { ...同上 };

// ⑤ 空白对照（★ 加一个必定无效的键，看它有没有动静）
await 桩.update({ "system.attributes.ac.calc": "natural" });   // 举例

// ⑥ 清理（★ 必须还原，别留污染）
await 桩.deleteEmbeddedDocuments("Item", 桩.items.map(i => i.id));
// 或直接 await 桩.delete();
```

### 4.3 已实测钉死的值

| 测什么 | 怎么写 | 怎么读 |
|---|---|---|
| 抗性 | `changes:[{key:"system.traits.dr.value", mode:2, value:"fire"}]` | `Array.from(actor.system.traits.dr.value)` |
| 暗视 | `key:"system.attributes.senses.darkvision", mode:2, value:60` | `actor.system.attributes.senses.darkvision` |
| AC 加值 | `key:"system.attributes.ac.bonus", mode:2, value:"+2"` | `actor.system.attributes.ac.value` |
| 移速跟随 | `key:"system.attributes.movement.swim", mode:5, value:"@attributes.movement.walk"` | 改 walk 看 swim 跟不跟 |
| 技能优势 | `flags.midi-qol.advantage.skill.ste`（m0, value "true"） | `await MidiQOL.computeSkillAdvantage(a,"ste",{})` → `r.attribution.ADV["skill.ste"]` |
| 豁免优势 | `flags.midi-qol.advantage.save.all` | 同上，看 `ADV["save.all"]` |

### 4.4 AC 测试的两个必设项
```
★ 护甲 AC 测试前必须临时把 system.attributes.ac.calc 从 "natural" 改成 "default"
```

### 4.6 mode 语义（★ 实测钉死，**极易误解**）
| change 目标类型 | 例 | m2 ADD | **m3 DOWNGRADE** | m4 UPGRADE | m5 OVERRIDE |
|---|---|---|---|---|---|
| NumberField | `abilities.con.value` | 10→12 ✓ | **10→1（取小！）** ✗ | 10→10 ✓ | 10→2 ✓ |
| StringField(公式) | `bonuses.abilities.save` | "-2" ✓ | **变 `min(-2, 1)`** ✗ | — | 直设 ✓ |
| SetField | `traits.dr.value` | 加入集合 ✓ | **空操作（安全）** ✓ | — | 整体覆盖 |
| StringField(枚举) | `attributes.ac.calc` | **静默失效** | — | — | ✓ |

**⇒ `mode 3` = 「取更小的值」（数值取 min、公式包成 `min(a,b)`），绝不是「禁用」。**
**禁用要用 `disabled:true`。**（曾误用 mode3 当"中性化"，导致体质 10→1 自伤。）

## 五 · 效果时长的完整规则（唯一全对的自动判据）

**物品效果时长的来源，按优先级：**
```
① 活动有实际时长  ⇒ 用活动的（勇气联结 活动 10minute ⇒ 实测 600s ✓）
② 活动是 inst     ⇒ 退回用**物品效果自己的 duration** ★ 这条最容易漏
③ 效果写 rounds/turns 而 game.combat 为 null ⇒ 算不出剩余 ⇒ 显示「永久」
   （源码 ActiveEffect#_prepareDuration：
     else if (d.rounds || d.turns) { const cbt = game.combat;
       if (!cbt) return { type:"turns", _combatTime: undefined }; }）
④ 两处都没写 ⇒ 0 秒立即掉
```

**修法模板（两处都写对）**
```js
const 新效 = o.effects.map(e => Object.assign({}, e, { duration: {...默认全 null, ...目标时长} }));
const up = { effects: 新效 };
for (const k of Object.keys(o.system.activities)) up["system.activities." + k + ".duration"] = 目标活动时长;
await d.update(up);
```

## 六 · 高频坑速查（读运行时值的陷阱）

| # | 陷阱 | 正确做法 |
|---|---|---|
| 1 | `traits.dr.value` 是 **Set**，`JSON.stringify` 恒 `{}` | `Array.from()` |
| 2 | `effects.statuses` 是 Set | `Array.from()` |
| 3 | `MidiQOL.computeSkillAdvantage` 是 **async**，不 await 得 `{}` | `await`，且读 `r.attribution.ADV[...]` 不是 `r.advantage` |
| 4 | DAE 写 flag 需要**一拍** | `await new Promise(r=>setTimeout(r,300))` |
| 5 | `Actor#effects` **只含卡文档自身的效果**，transfer 效果不在里面 | 用 **`actor.appliedEffects`** |
| 6 | 技能熟练读 `proficient` 恒 0 | 读 `system.skills.X.value`（0/1/2/0.5） |
| 7 | `attributes.spelldc` 不存在 | dnd5e 5.3.3 无此字段，卡面 DC 是 UI 现算的 |
| 8 | 魔法物品不设 equipped+attuned | 必设，否则 transfer 效果全不生效 |
| 9 | 护甲 AC 测试时 `ac.calc` 是 natural | 临时改 `default`，测完还原 |
| 10 | `item.system.activities` 是 ActivityCollection | `Object.values()` / `.contents` / `.get(key)`（`Object.keys()` 恒 0） |
| 11 | `d.folder` 不是 id | 用 `d._source.folder` |
| 12 | 想判「有没有效果」只看 `item.effects` | 五形态取并集（见 3.3） |

```js
    .replace(/@UUID\[[^\]]*\]\{([^}]*)\}/g, "$1").replace(/\[\[\/[^\]]*\]\]/g, "〔骰〕")
    .replace(/\s+/g, " ").trim();
  const 效 = (o.effects || []).map(e => e.name.slice(0,16) + "[" +
    (e.changes||[]).map(c => c.key.replace(/^system\.attributes\.|^system\./,"") + "|m" + c.mode + "|" + String(c.value).slice(0,26)).join(" , ").slice(0,90) + "]" +
    (e.disabled?"(禁)":"") + (e.transfer?"(转)":"") + ((e.statuses&&e.statuses.size)?"(状:"+Array.from(e.statuses).join("/")+")":"") +
```

**要点**：① 必须用 `getDocuments()`（逐件 getDocument 会慢到超时）② 每批换 `偏移 = 步长/2` 避免与上一批重复 ③ 探针里**不要对要判断的值做 slice**（截断会造假警报）。

### 逐件四问（照这个问，不要凭感觉）

### 三条「不要改」的判据（本轮各自挡住了一次误伤）
1. **工具物品的描述里写「拥有 X 工具熟练项的角色……」** —— 那是**规则说明**，不是给熟练（122 条命中 ⇒ 判据太宽）。
