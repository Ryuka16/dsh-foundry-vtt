## 一 · ★★★★★ 本轮第一个判据错误：官方索引被 2014/2024 混合污染

上一轮的对照表把官方 15 个 Item 包塞进**同一个 identifier 字典**：

```
dnd5e.items(872) → dnd5e.equipment24(635) 覆盖了 991 个重叠 identifier
```

实测：`official identifier 2258 个`，其中 **2014 与 2024 重叠 991 个**。
⇒ 上轮报的「A=45 / B=125」**是污染结果**。

**正确做法**：两套索引分开，按本包物品的 `system.source.rules` 选表。

```js
官方2014包 = ["dnd5e.items","dnd5e.tradegoods","dnd5e.spells","dnd5e.backgrounds",
             "dnd5e.classes","dnd5e.subclasses","dnd5e.classfeatures","dnd5e.races","dnd5e.monsterfeatures"];
官方2024包 = ["dnd5e.classes24","dnd5e.origins24","dnd5e.feats24","dnd5e.spells24",
             "dnd5e.equipment24","dnd5e.monsterfeatures24"];
// 官2014 唯一 identifier 1665 ｜ 官2024 唯一 identifier 1584 ｜ 重叠 991
```

本包规则分布：**2014 = 4478 件 / 2024 = 146 件 / 空 = 48 件**（共 4672 件，13 个 Item 包）。

## 三 · ★★★★★ 本轮最核心的机制发现：`Item5e#areEffectsSuppressed`

前几轮验证「被动加值效果是否生效」时一直失败，根因是**测试方法不完整**。

**dnd5e 源码（`systems/dnd5e/dnd5e.mjs`）**：

```js
/**
 * Should this item's active effects be suppressed.
 * @type {boolean}
 */
get areEffectsSuppressed() {
  const requireEquipped = (this.type !== "consumable")
    || ["rod", "trinket", "wand"].includes(this.system.type.value);
  if ( requireEquipped && (this.system.equipped === false) ) return true;
  return !this.system.attuned && (this.system.attunement === "required");
}

// ActiveEffect5e
get isSuppressed() {
  if ( super.isSuppressed ) return true;
  if ( this.type === "enchantment" ) return false;
  if ( this.parent instanceof dnd5e.documents.Item5e ) {
    if ( this.parent.areEffectsSuppressed ) return true;
    if ( this.dependentOrigin?.active === false ) return true;
  }
  return false;
}
```

**⇒ 物品上的 `transfer: true` 效果要生效，必须同时满足：**
1. `system.equipped === true`（**consumable 类型豁免**，除非子类是 rod/trinket/wand）
2. 若 `system.attunement === "required"` ⇒ 还必须 `system.attuned === true`

**实测证据（食人魔力量手套 `system.abilities.str.value(m5)=19`）**：

| 状态 | STR |
|---|---|
| 未装备、未调谐 | 10（不变）|
| **已装备、未调谐** | 10（不变）← 我前几次就卡在这 |
| **已装备 + 已调谐** | **19** ✓ |

**⇒ 艾恩石是「需同调」物品，验证时必须 `equipped:true` + `attuned:true`。**

## 四 · ★★★★★ 第三个机制发现：`@@` 自引用在 transfer 效果里失效

本包原有的「艾恩石（洞悉）」用的是：
```
system.abilities.wis.value  mode 5  value = "min(@@abilities.wis.value+2,20)"
```

**实测（临时角色，基线 STR 19）**：

| 写法 | 结果 | 判定 |
|---|---|---|
| `m2` `"2"` | 21 | 生效但不封顶 |
| `m2` `"+2"` | 21 | 同上 |
| **`m5` `"min(@abilities.str.value+2,20)"`** | **20** | **✅ 正确** |
| `m5` `"min(@@abilities.str.value+2,20)"` | **2** | ❌ **`@@` 解析成 0** |
| `m5` `"@@abilities.str.value + 2"` | 2 | ❌ 同上 |
| `m5` `"@abilities.str.value + 2"` | 21 | 生效但不封顶 |

⇒ **`@@` 是坏的，单 `@` 才对**。全库扫 `@@`：**只 6 件**（我新写的 5 件 + 原有的洞悉），已全部改成单 `@`，复查剩余 **0**。

## 八 · 其它实测事实（可复用）

1. **NPC 数据模型没有 `traits.weaponProf`**
   - 测试桩 `Actor.E4OlKBqN2dFen4ZX` 是 `type: "npc"`，`Object.keys(system.traits)` = `[size,di,dr,dv,dm,ci,languages,important,da,ida,idr,idv,idi,idm,sizeNumeric]`
   - **武器熟练是角色（character）专属字段** ⇒ 验证武器熟练必须用角色卡
2. **新建角色默认 `movement.walk = 0`** ⇒ 验「爬=走」「游=走」必须先设走速，否则 0=0 无法判别
3. **`system.skills.ath.bonuses.check` 是字符串**（`""`），要读计算值用 **`system.skills.ath.total`**
4. **`system.attributes.movement`** 键 = `[walk,burrow,climb,fly,swim,bonus,special,units]` ＋ 派生 `[hover,ignoredDifficultTerrain,jump,speed,max,slowed]`
   - **NPC 默认 `fly: 30`** ⇒ 验飞行效果必须用角色卡
5. **`system.bonuses`** 键 = `[mwak,rwak,msak,rsak,abilities,spell]`，每个含 `{attack,damage}`
6. **`getIndex({fields:[...]})` 极快**：`dnd5e.spells` 319 条 **153ms**（对比 `getDocuments()` 441 条 1506ms）
7. **`Hooks.events[k]` 是只读属性**（`Cannot assign to read only property 'dnd5e.preUseActivity'`）⇒ 要临时摘钩子只能原地改数组（`原.length = 0` 再 `push` 回去）
8. 本世界 `dnd5e.preUseActivity` 上挂了 **101 个监听器**
