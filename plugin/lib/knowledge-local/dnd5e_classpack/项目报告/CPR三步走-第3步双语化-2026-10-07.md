## 六 · 踩坑速查

1. **`cpr-mapping.json` 是全项目最好的中文源** —— 改名前先来这拿，别急着翻规则书/翻译。
2. **映射表的 id 是旧快照** —— 用户点过一键匹配后，部分件会被 CPR 重建（新 id 不在表里）⇒ **按 id 匹配优先，identifier 兜底**，两路都要试。
3. **`game.__X` 全局变量同一会话内保持，但每个脚本必须自己确认存在** —— 本次因 `game.__后` / `game.__N` 不存在，**连续报错两次**（`N is not a function` / `Cannot read properties of undefined`）。跨脚本复用时先 `const X = game.__X` 且带兜底。
4. **execute-js 不能用 `const` 自增** —— `const 双语 = 0; 双语++` 报 `Assignment to constant variable`，要 `let`。
5. **compendium 改活动名用点号路径最安全** —— `up["system.activities." + k + ".name"] = 新名`（不整段替换活动对象，避免丢字段）。
6. **效果名改名必须带整条效果对象**（`effects: o.effects.map(e => Object.assign({}, e, {name}))`）—— 只给 `_id + name` 会丢字段；点号路径 `effects.0.name` 会变成**追加一条**（见 `foundry_learn [L008]`）。
7. **`getIndex()` 不索引 flags**（恒 0），要读 flags 必须 `getDocuments()`。
8. **`foundry_file_system` 的 source 只认 `data`**（`modules` 报 `The requested file storage modules does not exist!`）。
9. **CPR 官方 `getItemByIdentifier` 签名是 `(actor, identifier)`** —— 它是「在某个 actor 身上找物品」，**不能当官方包查找器**。
10. **别按模块版本号统一件的版本号** —— 每个 CPR 宏有独立版本（`1.1.0` 占 273 件且全部与官方一致）。
