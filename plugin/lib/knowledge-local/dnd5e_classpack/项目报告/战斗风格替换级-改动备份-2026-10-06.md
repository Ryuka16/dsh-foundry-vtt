## 四 · 机制依据（源码，`dnd5e.mjs`）

```js
// ItemChoiceAdvancement.apply —— 替换时真的从卡上删掉旧物品
async apply(level, { previousItems, replace: original, retainedData={}, ...data }, options={}) {
  if ( original ) {
    const replacedLevel = Object.entries(this.value.added).reverse().reduce((level, [l, v]) => {
      if ( (original in v) && (Number(l) > level) ) return Number(l); return level;
    }, -Infinity);
    if ( Number.isFinite(replacedLevel) ) {
      this.actor.items.delete(original);        // ★ 旧风格从卡上消失
      this.actor.reset();
      this.updateSource({ [`value.replaced.${level}`]: { level: replacedLevel, original } });
    }
  }
}

// ItemChoiceFlow —— 升级框里的 radio
} else if ( event.target?.type === "radio" ) {
  if ( event.target.value ) await this.advancement.apply(this.level, { replace: event.target.value, previousItems: this.retained });
  else await this.advancement.reverse(this.level, { clearReplacement: true, previousItems: this.retained });
}

// configuredForLevel —— count 为空即视为「已配置」，不会卡升级
configuredForLevel(level) {
  return (this.value.added?.[level] !== undefined) || !this.configuration.choices[level]?.count;
}
```
**奇械师（`classes-new`，键 `hOojzO53l3sHCpHQ`，标题「选择戏法」）是本包里唯一已经用对的地方** —— 它的 choices 就是 `1:{2,true} / 4:{null,true} / 8:{null,true} / 10:{1,false} / 12:{null,true} / 14:{1,false} / 16:{null,true} / 19:{null,true}`，本次改动完全照抄这个形状。

## 五 · 影响范围与回滚

- **影响**：所有装载 `dnd5e_classpack` 模块的世界。改的是**模块包（compendium）源**，不是某个世界的实例。
- **对已建好的老卡**：`count: null` 的等级会被视为「已配置」，**不会追溯删物品**；玩家只在升级经过这些等级时看到替换选项。老卡想换风格，需要手动删旧的再拖新的，或重拖整张卡。
- **回滚**：把第一节的原 `choices` 四个键写回即可：
  ```js
  await d.更新({ "system.advancement.<键>.configuration.choices": { "<原等级>": { "count": 1, "replacement": false } } });
  ```
- **未做（后续可选）**：规则书第 45 行还有第二项 —— **战技大师范型的「替换战技」**。本次只做战斗风格这一项。

**③ 机制实测通过（程序化，2026-10-06 晚）**

```js
// 第一步：给测试卡选入一个战斗风格
await ic.apply(1, { selected: ["Compendium.dnd5e_classpack.class-abilityphb.Item.bfBqO9i1IWHXezXk"] });
//   → 卡上多出「战斗风格：巨武器战斗 Fighting Style:Great Weapon Fighting」
//   → value = {"added":{"1":{"3dczYUFKc69S43QT":"…bfBqO9i1IWHXezXk"}},"replaced":{}}

// 第二步：执行 L4 替换（换掉巨武器 → 防御）
await ic.apply(4, { replace: "VZQBm51A0WbXLdsE", selected: ["Compendium.dnd5e_classpack.class-abilityphb.Item.En7ex9752IkmvyKQ"] });
//   → 卡上：巨武器消失、"战斗风格：防御 Fighting Style: Defense" 出现
//   → 旧件还在: false    防御在吗: true
//   → value.replaced = {"4":{"level":1,"original":"VZQBm51A0WbXLdsE","replacement":"VyEahnGVGCG5Q0Uj"}}
```
**⇒ 这三条就是用户要的：「选中就把旧的从卡上删掉、新的补上、卡里只有一个风格」。**
**注意 `replaced["4"].level = 1` —— 它记录了「被换掉的那个是第 1 级给的」，撤销时靠这个还回去。**

**④ 已排除一个伪障碍**：`configuredForLevel(level)` 对 `count:空` 返回 true，看起来像「视为已配置就不弹了」；但实测它的**唯一调用点**是渲染时的 `configured: advancement.configuredForLevel(level)`（只是卡面显示的「已配置」标记），**不是 flow 开关**。真正的开关是流程里的 `context.replaceable = levelConfig.replacement`。
