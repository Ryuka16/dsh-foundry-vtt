## 二 · 扫描方法（本轮效率关键）

### 2.1 ★ 提速 20 倍的关键：`getDocuments({_id__in: [...]})`

**旧法**（逐件 `getDocument(id)`）：70 件 ≈ 56 秒 ⇒ HTTP 408，每批只能 30~70 件。
**新法**（批量 `getDocuments({_id__in: 批})`）：**400 件秒回**，800 件也秒回 ⇒ 一次调用能扫完整个包。

```js
const P = game.packs.get("dnd5e_classpack.itempack");
const idx = (await P.getIndex()).contents;
const docs = await P.getDocuments({ _id__in: idx.map(e => e._id) });   // 1679 件一次拿全
```

⇒ **一次调用扫完 itempack 全部 1679 件**（此前要 20+ 批）。这是本轮能"一口气跑完 4075 件"的直接原因。

### 2.2 三阶段流程

1. **建队列**：拉全部索引 → 过滤「有活动 ∨ 有效果」的件（空件跳过，约占 28%）
2. **判据扫**：每批 180~200 件，把 20 条判据一次跑完，只输出命中
3. **逐件定性**：读命中件的完整数据（描述 + 活动 + 效果 + changes），判定真错 / 误报

### 2.3 ★ 纪律：报 0 之前必做阳性对照

第 1 批（180 件）报「命中 0」时**没有直接采信**，而是先打印该批的关键特征作对照：
```
{件:180, 有禁用:2, 有空效:3, 有CPR:0, 有描述含优势:20, 有活动:159, 有效果:70}
样本: 禁用|extra-ability|注魔箭矢 Magic Arrow ｜ 空效|spell|跳跃术 Jump …
```
⇒ 对照证明判据确实在跑（有禁用/空效/含优势的件确实存在），只是都不满足命中条件 ⇒ **0 是可信的**。
⇒ 这条纪律在本轮再次证明价值（此前多次因「静默失败」误判）。

## 六·补二 · ★★★ 本轮最大的技术坑：**17 位 effect id 静默失败**

### 现象
