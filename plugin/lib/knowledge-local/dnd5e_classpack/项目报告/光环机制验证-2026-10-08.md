## 一 · 起因

3 件物品的 `flags.dae.macro.command` 完全相同，都调用**未安装**的 ActiveAuras：

```js
if (args[0].macroPass === "preActiveEffects" || args[0].tag === "OnUse") {
  return await game.modules.get("ActiveAuras").api.AAHelpers.applyTemplate(args);
}
```

| 物品 | 包 / id |
|---|---|
| 焚云术 Incendiary Cloud | `dnd5e_classpack.spell / FUiSyN2j2j3ufukn` |
| 暗黑星辰 Dark Star | `dnd5e_classpack.spell / KS5iEDJFWv7JWwb2` |
| 魔能祈唤:飞蝇斗篷 | `dnd5e_classpack.class-abilityphb` |

且三件的 `flags["midi-qol"].onUseMacroName` **为空**、无效果宏 change、无 `itemCondition`
⇒ **宏根本不会被触发**，即使触发也因模块不存在而失败 = **双重失效（无害的空转）**。

## 三 · ★ 新路径：Region + `executeScript` 行为（**机制已实测跑通**）

`region-attacher` 已装 1.11.1，包内有 5 件先例（臭云术 / 匕首之云 / 纠缠术 / 蛛网术 / 艾伐黑触手），
但它们的行为脚本调 `game.gps.*`。**我们完全可以自己建 Region，不依赖任何第三方模块。**

### 3.1 源码依据（`foundry.data.regionBehaviors.ExecuteScriptRegionBehaviorType`）
```js
async _handleRegionEvent(event) {
  const fn = new AsyncFunction("scene", "region", "behavior", "event", `{${this.source}\n}`);
  await fn.call(globalThis, this.scene, this.region, this.behavior, event);
}
```
⇒ 脚本上下文变量正好是 **`scene` / `region` / `behavior` / `event`**，支持 `async/await`，`this` = globalThis。
⇒ 行为类型字符串 = **`"executeScript"`**，字段 = `system.events`（数组）+ `system.source`（脚本字符串）。

### 3.2 实测已跑通的部分（**全部有数据**）

**① 建 Region 成功**
```js
const 区 = await canvas.scene.createEmbeddedDocuments("Region", [{
  name: "焚云术 Incendiary Cloud",
  shapes: [{ hole: false, type: "polygon", points: pts }],
  behaviors: [{ name: "进场", type: "executeScript",
    system: { events: ["tokenEnter", "tokenMoveIn"], source: 挂脚本 } }],
  visibility: 0
}]);
```
读回：`行为数 1`、`行为类型 executeScript`、`事件 ["tokenEnter","tokenMoveIn"]`、`场景Region数 1` ✓

**② 模板形状 → Region polygon 的换算（可用，抄自 region-attacher）**
```js
const obj = 模板.object;
if (!obj.shape) obj._refreshShape();
const s = obj.shape;
const pts = (s.points || s.toPolygon().points).map(function(pt, i){
  return i % 2 ? pt + 模板.y : pt + 模板.x;
});
```
实测：circle 20ft 模板 ⇒ `s.points` 为 falsy，走 `toPolygon()` ⇒ **45 个点 ⇒ 90 个坐标** ✓

**③ 脚本确实被触发、效果确实挂上了 —— 这是本轮最硬的证据**
把木桩移出 Region 再移回，读 `token.actor.effects`：
```
效果名录: ["焚云术 Incendiary Cloud", "焚云术 Incendiary Cloud"]   ← 挂了 2 条
时长: { type:"turns", rounds: 10 }                                  ← 写的 rounds 生效
```
⇒ **`MidiQOL.socket().executeAsGM("createEffects", { actorUuid, effects })` 可用** ✓
⇒ 同一 token 进入会**同时触发 `tokenEnter` 与 `tokenMoveIn`** ⇒ **挂效果前必须按名字去重**。

**④ Region 的 flag 存读正常**
```js
await 区[0].setFlag("world", "lhDC", 16);   // 存
region.getFlag("world", "lhDC")             // 读 ⇒ 16 ✓
```
读回：`flags.world = { lhName:"焚云术 Incendiary Cloud", lhDC:16, lhDmg:"10d8", lhType:"fire", lhSave:"dex", lhRounds:10 }` ✓

### 3.3 ❌ 两个卡住的问题（**未解决，留给下一个 AI**）

**问题 1：行为脚本里 `region.getFlag` 读到 `undefined`（只有第一个 flag 读到了）**

挂上去的效果 changes 长这样：
```
flags.midi-qol.OverTime | m2 | "turn=end, saveAbility=undefined, saveDC=undefined,
   saveMagic=true, damageRoll=undefined, damageType=undefined, saveDamage=halfdamage,
   allowIncapacitated=true"
```
⇒ 效果**名**读到了（`region.getFlag("world","lhName")` 返回值正确），
但 `lhDC` / `lhDmg` / `lhType` / `lhSave` **全部返回 `undefined`**。
而**脚本外**读同一个 Region 的同一批 flag ⇒ **全部正常**。

**推测根因（未验证）**：`setFlag` 是异步写入，而我建 Region 时**木桩已经在区域内** ⇒ Region 一落地就触发了一次 `tokenEnter`，
此时只有**第一个** `setFlag` 已完成，其余 5 个还在队列里 ⇒ 脚本读到 undefined。
但**第二次**（我主动移出再移回）挂的效果**同样是 undefined**，这个解释覆盖不了 ⇒ **根因未明**。

**问题 2：`behavior.update({"system.source": 新脚本})` 之后行为不再触发**

换成诊断脚本（读 767 字符，回读确认长度一致）后再移木桩进出 ⇒ **木桩 effects 为空，一次都没触发**。
⇒ 怀疑 **Region 行为被 update 后订阅失效**（需要整段重建 Region / 重建 behavior 文档），
或 **relay 移动 token 与画布事件不同步**。**未验证。**

## 四 · 如果下一个 AI 要继续做 —— 建议的下一步

1. **先解决「行为脚本读 flag」的时序问题**：不要用 `region.getFlag` 传参，
   **把 DC / 伤害等参数直接内联进脚本字符串**（建 Region 时就拼好），彻底绕开读取时机。
   ⚠ 代价：脚本会变长，但 Region 行为脚本**没有 relay 黑名单限制**（它写在世界数据里，不走 execute_js）。
2. **行为脚本要改时，整段重建 Region**（`delete` + `create`），不要 `behavior.update`。
3. **验证方式**：在测试场景建一个 Region → `foundry_move_token` 移 token 进出 → 读 `token.actor.effects`。
4. **参考坐标**：测试桩 = 木桩（actor `YODb7l4b8ypIgPVQ`）；场景 `hBv2aRFZ0qQnk9Q1`（4000×3000 / grid 100 / 5ft）。
5. **不要用 `system.script` 读 Region 行为脚本** —— 字段是 **`system.source`**（踩过这个坑，曾因此误判「5 件区域行为是空壳」）。
