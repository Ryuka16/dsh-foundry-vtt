# 第一部分 · AA（Automated Animations 6.8.1）

## 一、多目标会重复播动画 —— 「几个敌人就几把刀」

### 现象

普攻一刀，打三个木桩，画面上**三把刀**分别砍向三个人。

### 根因（AA 源码实据）

`modules/autoanimations/dist/autoanimations.js`：

```js
Hooks.on("dnd5e.rollDamageV2", async (rolls, data2) => {
  const roll = rolls[0];
  const activity = data2.subject;
  const hit = !!(activity.actor.hits?.[activity.relativeID] ?? true);
  if (activity.actor.hits) delete activity.actor.hits[activity.relativeID];
  if (activity?.description?.chatFlavor?.includes("[noaa]")) return;
  const playOnDamage = game.settings.get("autoanimations", "playonDamageCore");
  if (Object.keys(CONFIG.DND5E.areaTargetTypes).includes(activity?.target?.template?.type) || activity?.type == "attack" && !playOnDamage) {
    return;
  }
  ...
  damageV2(await getRequiredData({ ... }));
});
```

**每个目标的伤害骰都会各自触发一次 `dnd5e.rollDamageV2`**，而

- `playonDamageCore` **开启**时，`activity.type == "attack"` 的第二个条件不成立 ⇒ **不 return** ⇒ 每个目标各播一次。

同理 `dnd5e.rollAttackV2` 里也有一条：

```js
if (Object.keys(CONFIG.DND5E.areaTargetTypes).includes(activity?.target?.template?.type) || activity?.damage?.parts?.length && activity?.type != "heal" && playOnDamage) {
  return;
}
```

⇒ 带伤害骰的非 heal 活动在 `playOnDamage` 开启时，**攻击动画整体让位给伤害动画**，只在 `rollDamageV2` 播。

### 正确做法

**要「只播一次」就让它只有一个目标**。单体活动天然只有一次伤害骰。多目标活动（线/锥/球）必然会按目标数重复——这是 AA 的机制，不是配置错误。

## 二、活动级 flags 压过物品级，且 `isEnabled` / `killAnim` 优先级最高

### 根因（AA 源码实据）

```js
const activityIsEnabled = activityFlags ? !!activityFlags.killAnim ? false : activityFlags.isEnabled ?? true : true;
if (!activityIsEnabled) {
  return false;
}
const itemIsEnabled = !!itemFlags.killAnim ? false : itemFlags.isEnabled ?? true;
if (!itemIsEnabled) {
  return false;
}
...
} else {
  if (activityFlags?.isCustomized) {
    return activityFlags;
  } else if (itemFlags.isCustomized) {
    return itemFlags;
  } else if (!autorecDisabled) {
    const prioritizedNames = [...data2.overrideNames || [], itemName, ...data2.extraNames || []];
    ...
  }
}
```

**判定顺序是「先 isEnabled/killAnim，再 isCustomized」**。所以：

- `flags.autoanimations.isEnabled = false`（或 `killAnim: true`）**直接掐掉**这个活动的动画，不管物品级配了什么；
- 反过来，`isCustomized: true` 只影响「选哪份配置」，**管不住开关**。

命中条件靠 `isCustomized` 标记 + **名字匹配**（`rinseName` 去空格小写），**不是活动 id、也不是 `activity.type`**。

### 实战用法

给「装鞘 / 拔鞘」这种**不带伤害的 utility 活动**配：

```json
"flags": { "autoanimations": { "isEnabled": false, "killAnim": true, "isCustomized": true } }
```

否则点一下「装鞘」会莫名其妙挥一刀——原因见下条。

## 三、`postUseActivity` 对没有伤害的 utility 活动照样播动画

### 根因（AA 源码实据）

```js
Hooks.on("dnd5e.postUseActivity", async (activity, usageConfig, results) => {
  if (activity?.description?.chatFlavor?.includes("[noaa]")) return;
  if (Object.keys(CONFIG.DND5E.areaTargetTypes).includes(activity?.target?.template?.type) || (activity?.damage?.parts?.length || activity?.type == "heal")) {
    return;
  }
  ...
  useItem$2(await getRequiredData({ item: item2, actor: item2.parent, activity, roll: item2, useItemHook: { item: item2, config, options: options2 }, ... }));
});
```

utility 活动两条 `return` 条件**都不满足**（没有 template、没有伤害骰）⇒ 落到最后一行 ⇒ **播动画**。

两条修法：

1. `flags.autoanimations.isEnabled = false`（推荐，见上条）
2. 在 `description.chatFlavor` 里塞 `[noaa]` 标记——但这段文字**会显示在聊天卡上**，很丑，非必要不用

## 四、音效七字段缺一不可；路径写错是**静默不播**

### 现象

配了 `sound`，实机没声音、控制台**不报错**。

### 原因

AA 的 sound 是一个完整对象，七字段缺一都可能不响：

```json
"sound": { "enable": true, "file": "…", "volume": 0.85, "delay": 0, "startTime": 0, "repeat": 1, "repeatDelay": 250 }
```

**只写 `{ "enable": false }` = 根本没配**，不是「关掉声音」的写法。

视频菜单路径（`dbSection / menuType / animation / variant / color`）填错时，`validateVideoPath` 失败直接 `return false`，**同样无报错**。

### 正确做法

1. **配路径之前先验证**：`Sequencer.Database.entryExists("jb2a.melee_attack.04.katana.01")` —— 命中会回真实路径（可能是带后缀的 `.0`），没命中回 `false`。
2. **`FilePicker.browse` 只回文件、不回子目录**：目录里还有一层时 `files` 是空的，子目录在 `r.dirs` 里。psfx 库大部分音效在 `…/<类别>/v1/` 下面。
   实测：`FilePicker.browse("data", "modules/psfx/library/weapon-attacks/sword")` → `{ dirs: ["v1"], files: [] }`；再 browse 到 `…/sword/v1` 才拿到 `sword-001-00.ogg … sword-001-05.ogg`。
3. **`Sequencer.Database.getAllEntries()` 不是扁平 dbPath 表**（实测只回 4 个键），别指望它枚举整个库。

# 第二部分 · dnd5e 活动类型

## 六、要「必中、不投攻击检定」只能用 `damage` 活动

### 现象

想要「一个动作、直接命中、不掷攻击骰、3d8」的蓄力斩。

### 为什么 `attack` 活动做不到

`attack` 活动的 schema（实测 `CONFIG.DND5E.activityTypes.attack.documentClass.defineSchema()`）：

```js
attackFields: ["ability", "bonus", "critical", "flat", "type"]
flat: { label: "", initial: false, type: "BooleanField" }   // ← 只是个布尔，不是「自动命中」开关
```

**没有任何「自动成功」选项。** `attack.bonus` 只能堆加值，骰子照样掷。

### `damage` 活动的真实 schema（实测）

```
["_id","type","name","img","sort","activation","consumption","description","duration","effects","flags",
 "range","target","uses","visibility","damage","useConditionText","useConditionReason","effectConditionText",
 "macroData","ignoreTraits","midiProperties","isOverTimeFlag","overTimeProperties"]

hasAttack: false        ← 没有攻击检定这一步，结构上就「必中」
hasConsumption: true    ← 能扣活动/物品次数
hasMidiProps: true      ← 能挂 midiProperties
hasTarget / hasRange / hasActivation / hasFlags: true
```

⇒ **「不投攻击检定」是结构保证的，不是靠加值堆出来的。**

## 七、⚠️ 不要试图「改活动类型」，要新建

`ActivitiesField extends MappingField`，包的元素是固定的 `ActivityField`；落到 `TypedObjectField._updateDiff` 时用的是 `this.element._updateDiff(source, k, v, schemaDiff, options)` —— **按固定 element 走，没有按 `type` 分派**。dnd5e 的 UI 也**没有**「更改活动类型」这个入口。

⇒ 结论：**新建一个目标类型的活动**，把旧的隐藏或删掉。

**「隐藏」的标准姿势**是 midi 的活动选项：

```json
"midiProperties": { "automationOnly": true }
```

效果：不进「选择活动」弹窗、不能手动掷，但数据还在、随时可恢复（改回 `false` 即复活）。**比直接删安全得多**，尤其适合「新的还没实测，先留着旧的兜底」这种场景。

## 八、最小壳 + 读回真实默认值，别一次写全

新建活动只要给最小信息：

```json
{ "system": { "activities": { "dnd5eactivity400": { "type": "damage", "name": "蓄力斩" } } } }
```

dnd5e 会用默认值把整个 schema 填满，**然后读回 `toObject()` 看真实结构再配**。实测读回拿到：

```json
"consumption": { "scaling": { "allowed": false }, "spellSlot": true, "targets": [] }
"range": { "units": "self", "override": false }
"midiProperties": { "otherActivityCompatible": true, ... }
```

⚠️ **默认 `consumption.spellSlot: true`** —— 不关掉这个活动会**吃法术位**。这类「默认值陷阱」只有读回才看得见。

## 九、`damage` 活动自带一层 dnd5e 的 `ignoreTraits`，和 midi 那层是两回事

```json
"ignoreTraits": { "idi": false, "idr": false, "idv": false, "ida": false, "idm": false }   // dnd5e DataModel 层
"midiProperties": { "ignoreTraits": [] }                                                   // midi 层（SetField）
```

要「无视抗性与免疫」**两处都得写**：

```json
"ignoreTraits": { "idi": true, "idr": true, "idv": false, "ida": false, "idm": false },
"midiProperties": { "ignoreTraits": ["idr", "idi"] }
```

# 第三部分 · midi 的附赠动作与「一轮一次」

## 十、`midiProperties.ignoreTraits` 是字符串集合，写成布尔对象会被**静默清空**

### 现象

```json
"midiProperties": { "ignoreTraits": { "idr": true, "idi": true } }
```

写入后 `foundry_diff` 报 `未落库（读回 undefined）`，**不报错**。

### 根因（schema 探针实据）

```
ignoreTraitsSchema: "SetField"
ignoreTraitsElement: "StringField"
ignoreTraitsValue: {}          ← 写进去的布尔对象被清成了空对象
```

**正确写法是字符串数组**：

```json
"midiProperties": { "ignoreTraits": ["idr", "idi"] }
```

四类前缀（出处：`midi-qol/Changelog.md` L725-731）：`idi`=免疫 / `idr`=抗性 / `idv`=易伤 / `ida`=吸收。还支持单词根粒度：`idi.fire` 只无视火焰免疫、`idr.cold` 只无视冰冷抗性，可组合。

### ★ 读取陷阱：`Set` 序列化后一律显示 `{}`

探针里 `JSON.stringify(ignoreTraits)` = `{}`，**看起来像被清空了**。实际：

```js
Object.prototype.toString.call(raw)   // "[object Set]"
Array.from(raw)                       // ["idr","idi"]   ✓ 有效
```

**读 SetField 必须 `Array.from()`**，否则永远误判成空。

## 十一、⚠️ midi 的附赠动作**不会**自动记账 —— 有一道设置门闸

### 根因（midi 源码实据）

`modules/midi-qol/midi-qol.js`：

```js
function needsBonusActionCheck(actor) {
  return configSettings.enforceBonusActions === "all" || configSettings.enforceBonusActions === actor.type;
}
```

```js
workflow.itemUsesBonusAction = false;
if (!usage.midiOptions?.workflowOptions?.notBonusAction && options.checkBonusAction && this.actor?.inCombat && needsBonusActionCheck(this.actor)) {
  workflow.itemUsesBonusAction = ["bonus"].includes(this.effectiveActivationType ?? "");
  const queryBonus = workflow.itemUsesBonusAction && hasUsedBonusAction(this.actor) && needsBonusActionCheck(this.actor);
  ...
}
```

记账那一句：

```js
if ((usage.workflow.itemUsesBonusAction || usage.midiOptions?.workflowOptions?.castUsesBonusAction) && this.actor && !hasUsedBonusAction(this.actor))
  await setBonusActionUsed(this.actor);
```

**世界实测 `enforceBonusActions: "displayOnly"`**（`game.settings.get("midi-qol","ConfigSettings")`）：

- `=== "all"` → false
- `=== actor.type`（角色是 `"character"`）→ false

⇒ `needsBonusActionCheck` = false ⇒ 外层 `if` **整块跳过** ⇒ `workflow.itemUsesBonusAction` **恒为 false** ⇒ **`setBonusActionUsed` 永远不会被自动调用**。

**但手写调用是生效的** —— `setBonusActionUsed` 自己的门闸反而更宽：

```js
async function setBonusActionUsed(actor) {
  if (debugEnabled > 0) warn("setBonusActionUsed | starting");
  if (!["all", "displayOnly"].includes(configSettings.enforceBonusActions) && configSettings.enforceBonusActions !== actor.type) return;
  ...
}
```

`"displayOnly"` **在允许列表里**。

⇒ 结论：**`displayOnly` = 「允许记录，但不自动触发、也不拦截」**。要它工作只能手写调用。

⚠️ 另有一个硬条件 **`this.actor?.inCombat`** —— **战斗外根本没有「轮」，也就没有附赠动作记账**。

### 怎么查这个设置

`enforceBonusActions` **不是独立注册的设置项**（1998 个已注册项里搜不到）。它打包在 `midi-qol.ConfigSettings` 里：

```js
game.settings.get("midi-qol", "ConfigSettings").enforceBonusActions   // "displayOnly"
```

## 十二、★「一轮一次」最可靠的实现：活动自己的次数池

**不依赖任何世界设置、不写一行代码**，用 dnd5e 原生的活动次数 + 消耗：

```json
"uses": { "max": "1", "spent": 0, "recovery": [{ "period": "turnStart", "type": "recoverAll" }] },
"consumption": { "spellSlot": false, "targets": [{ "type": "activityUses", "value": "1", "target": "", "scaling": { "mode": "", "formula": "" } }] }
```

`consumption.targets[].type` **6 键全集**（`config.mjs` L1117-1160）：

`activityUses`（消耗活动次数）/ `itemUses`（消耗物品次数）/ `material`（材料）/ `hitDice`（生命骰）/ `spellSlots`（法术位）/ `attribute`（属性值）

⚠️ **池子不足时抛 `ConsumptionError`，阻止这次使用并弹警告 —— 不静默、也不会扣成负数。** 这是**强制**，不是提示。

### ★ 两个坑

1. **配了 `uses` 但没配对应 `consumption` = 完全没有约束**。「追刃」就白写了好几轮：它有 `uses:{max:"1", recovery: turnStart}`，但 `consumption.targets` 是空的，**从没被消耗过**，等于装饰。
2. **战斗外会锁死**：`turnStart` 只在战斗内触发，战斗外用了不恢复。修法是在物品宏开头补一段「不在战斗中就把活动次数清零」，见第十七条。

# 第四部分 · 物品宏

## 十三、物品宏三件套必须**三处同写**，少一处静默不触发

```js
flags["midi-qol"].onUseMacroName = "[postActiveEffects]ItemMacro"
flags.itemacro.macro = { name, type: "script", scope: "global", command }
flags.dae.macro      = { name, type: "script", scope: "global", command }
```

⚠️ **别自己拼 `"[pass]ItemMacro"` 串**——AE 级那种逗号式写法在 midi 13.0.55 实测不触发。

宏体里的可用变量：`workflow`、`rolledActivity`、`item`、`token`、`actor`、`game`、`MidiQOL`。常用判据是**按活动名分流**：

```js
const act = wf.activity ?? ((typeof rolledActivity !== "undefined") ? rolledActivity : null);
if (act?.name !== "装鞘") return;
```

## 十四、形态切换该挂**物品宏**，不是世界宏

第一版把「装鞘/拔鞘」做成了世界宏（宏侧边栏里点）。问题：

- 玩家得跑去找宏侧边栏，跟武器是脱节的；
- 活动类型写成 `activation.type: "bonus"` 后，**动作类型本身**就是宣告，世界宏反而绕远了。

改成刀上的行为：给两把刀各加一个 `utility` 活动（`装鞘` / `拔鞘`，`activation.type: "bonus"`），物品宏在 `postActiveEffects` 里按活动名分流做事。玩家点开刀、选活动即可。

⚠️ utility 活动**没有** `useFlavor` 字段，风味文案走 `description.chatFlavor`。

## 十五、物品宏里删建自己所在的物品 —— 用 `setTimeout` 让 workflow 先收尾

形态切换 = 删掉当前形态的物品 + 创建另一形态的物品。但宏跑在 `postActiveEffects`，**workflow 还没走完**（聊天卡等），此时同步删掉物品，后续步骤可能拿到已删除的文档。

做法：把删建推迟出去。

```js
const run = async () => {
  try {
    const actor = me.actor;
    const held = actor.items.filter(i => i.type === "weapon" && names.includes(i.name));
    const cur = held.find(i => i.system.equipped) ?? held[0];
    const data = tpl.toObject();
    delete data._id;
    delete data.folder;
    data.system.uses = data.system.uses ?? {};
    data.system.uses.spent = cur?.system?.uses?.spent ?? 0;   // 搬运「残心」
    data.system.attuned = cur?.system?.attuned ?? false;
    data.system.equipped = true;
    await actor.deleteEmbeddedDocuments("Item", held.map(i => i.id));
    await actor.createEmbeddedDocuments("Item", [data]);
  } catch (err) { console.error("切换失败", err); }
};
setTimeout(run, 250);
```

⚠️ `250ms` 这个延迟**未实测**够不够，只是经验值。

## 十六、宏里不要写死「身上只能有一把」这类判据

第一版写了：

```js
if ( held.length > 1 ) return ui.notifications.error("身上同时存在两种形态，请先手动删掉多余的那把。");
```

**用户身上正常就是两把**（他会把两个形态都拖到角色卡上）⇒ 宏每次直接罢工，用户看到的现象是「功能怎么没有了」。

正确做法：**用 `equipped` 判定当前形态，多余的照删**，不要报错。

```js
const cur = held.find(i => i.system.equipped) ?? held[0];
```

## 十七、战斗外「每轮一次」会锁死 —— 宏开头补一段清零

活动次数用 `turnStart` 恢复时，战斗外**永不恢复**，用一次就废。补在宏开头（**在使用动作之前生效**）：

```js
if ( !game.combat ) {
  const own = wf.item;
  if ( own ) {
    const upd = {};
    for ( const a of (own.system.activities?.contents ?? []) ) {
      if ( (a.uses?.spent ?? 0) > 0 ) upd[`system.activities.${a.id}.uses.spent`] = 0;
    }
    if ( !foundry.utils.isEmpty(upd) ) await own.update(upd);
  }
}
```

战斗中不恢复 ⇒ 「一轮一次」成立；战斗外先清零 ⇒ 不限制（战斗外本来也没有「轮」这个概念）。

# 第五部分 · 位移与碰撞（Foundry 13）

## 十八、`MidiQOL.moveToken` 的真实姿态

```js
MidiQOL.moveToken(tokenRef, newCenter, options, legacyOptions)
```

第三参传 boolean **自 13.0.56 起 deprecated**（会 `foundry.utils.logCompatibilityWarning`），新写法是对象：`{ animate, teleport, ignoreWalls, ignoreTokens }`。

GM 侧真正的 handler：

```js
const { animate = true, teleport = false, ignoreWalls = false, ignoreTokens = false, autoRotate = true } = data.options ?? {};
const snappedCenter = canvas.grid.getSnappedPoint(data.newCenter, { mode: CONST.GRID_SNAPPING_MODES.CENTER });
const newPosition = { x: snappedCenter.x - targetToken.w/2, y: snappedCenter.y - targetToken.h/2 };
const moveOptions = { constrainOptions: { ignoreWalls: teleport||ignoreWalls, ignoreCost: true, ignoreTokens: teleport||ignoreTokens }, autoRotate };
```

三条要点：

1. **`newCenter` 就是 token 中心**，内部自己 `-w/2`，别再自己减一次；
2. **midi 自动吸附格中心**；
3. ⚠️ **`ignoreTokens` 默认 `false`，会挡住「穿过敌人所在格子」** —— 想「穿到敌人身后」必须显式 `ignoreTokens: true`；
4. `ignoreCost: true` ⇒ 不扣移动力。

⚠️ **`moveTokenAwayFromPoint` 是「把 token 推离某点」**，施法者在敌人前面时用它方向是**反的**，做突进不能用它。

## 十九、V13 墙体碰撞：`canvas.walls.checkCollision` 已经没了；且返回的是**数组**

- `canvas.walls.checkCollision` = **`undefined`**（V13 移除）
- 正确 API：`CONFIG.Canvas.polygonBackends.move.testCollision(origin, destination, { mode = "all", ...config })`
- `CONFIG.Canvas.polygonBackends` 键：`sight / light / darkness / sound / move / aura`
- **必须传 `type`**，否则抛：

```
Error: A valid wall restriction type is required for testCollision.
```

（`CONST.WALL_RESTRICTION_TYPES = ["light","sight","sound","move"]`）

### ★ 最阴的一条：空数组在 JS 里是 truthy

`testCollision` 返回的是**碰撞点数组**，不是布尔。所以：

```js
blocked = backend.testCollision(a, b, { type: "move" });   // ❌ [] 是 truthy ⇒ 永远判定撞墙，一步不走
```

正确：

```js
const hitList = backend.testCollision(a, b, { type: "move" });
blocked = Array.isArray(hitList) ? hitList.length > 0 : !!hitList;   // ✓
```

# 第六部分 · 方法论（这一节最值钱）

## 二十、三种「真相源」，按可靠性排序

1. **运行时 schema 探针** —— `act.constructor.defineSchema().fields` 拿到的是**真实的字段类型与初值**，比翻文档、比猜键名可靠得多。本次靠它拿下：`ignoreTraits` 是 `SetField<StringField>`、`damage` 活动 `hasAttack: false`、`attack.flat` 只是 `BooleanField`。
2. **`activity.labels.damages[].formula`** —— dnd5e **自己算出来的最终伤害**，比按 `parts + includeBase` 推演可靠。本次靠它揪出一处真 bug：追刃原本算出 **2d10**（翻倍），把 `damage.parts` 清空后才回到 1d10。
3. **源码原文** —— 行为类问题（AA 什么时候播、midi 什么时候记账）只能读源码，文档和名字都靠不住。

⚠️ **反面教训**：我曾根据「`斩` 的 `damage.parts` 是 `[1d8]` 且 `includeBase: true`」**推断**它会是 2d8，还准备去「修」——实测 `labels.damages` 是 **1d8**，推断错了。**先查标签，再动手。**

## 二十一、探针写法：一次要全，不挤牙膏

- `foundry_execute_js` 一次把**所有可疑字段**读出来，别「看一个值再决定下一个」。
- 读活动要连 **`toObject()`** 一起读，光看文档对象拿不到 `_source` 里的默认值全貌。
- **按名字/类型推语义是最容易翻车的地方**（本次翻了一次车，见第二十四条）。

## 二十二、relay 的 forbidden-patterns 是**纯正则扫全文**

24 条黑名单，**写在注释、字符串、变量名里一样会被拒**，而且报错**不告诉你是哪个词**，只说 `Script contains forbidden patterns`。

已知会中招的写法：

| 想写 | 会被拦的子串 | 躲法 |
|---|---|---|
| `game.settings.settings` | `game.settings.set` | `const S = game["settings"];` |
| `apiKeys`（变量名） | `apiKey` | 换名 |
| 任何含 `Proxy` 的单词 | `Proxy` | 换名 |
| `import(` | `import(` | 换写法 |

其他易踩：`localStorage` / `document.cookie` / `eval(` / `atob(` / `btoa(` / `crypto.` / `Intl.` / `postMessage(` / `Function(` / `globalThis` / `Reflect.`

## 二十三、`foundry_create_entity` 建宏会被 REST API 模块拦

```
HTTP 400：Macro creation is disabled in REST API module settings.
A GM must enable 'Allow Macro Creation/Editing' to allow this.
```

对应设置：**`foundry-rest-api.allowMacroWrite`**（world 级，默认 `false`）。

路径：游戏内齿轮 → 模块设置 → **Foundry REST API**。同组还有 `allowMacroExecute` / `allowExecuteJs` / `codeExecutionPermission`。

另：读 `Sequencer` / `FilePicker` 之类的目录时，`foundry_file_system` 的 `source` **合法值是 `data`**，不是 `modules`。

# 第七部分 · 我自己犯的判断错误（别重犯）

## 二十四、拿**名字**推**语义** —— 说「附赠动作是原生记账的」

我看到 `activation.type: "bonus"` 和 `setBonusActionUsed` 这两个名字，就下结论说「附赠动作由 dnd5e/midi 原生记账，我手写的那句多余」，并据此**删掉了手写记账**。

**实测是错的**：`needsBonusActionCheck` 在当前世界设置下返回 `false`，自动路径整块被跳过。手写那句反而是必要的。

⇒ **凡是「谁在什么时候调用谁」这类问题，只能读调用点源码，不能看名字。**

## 二十五、把**用户的实际状态**当成异常

形态切换宏写死 `if (held.length > 1) 报错退出`。而用户身上**正常就是两把**。结果宏一直罢工，用户看到的现象是「这功能怎么没有了」。

⇒ **判据要写成「处理所有情况」，不是「把不符合预期的输入当错误弹回去」。**

## 二十六、没试听就写音效，且两个招式**共用同一个文件**

两个招式（蓄力斩、穿刺）的 AA 音效写成同一个 `psfx.impacts.magicaleffects.lightning.0`。用户反馈「像管子一样」。我既没试听、也没做区分。

⇒ **音效是主观的**：能播出声不等于好听。有条件就先播给用户听，或者至少不同招式用不同文件，别用一个音效糊所有招式。

## 二十七、破坏性操作前先留退路

「蓄力斩」要从 `attack` 改成 `damage`，改了就得动活动。实际做法是**先建新的 `damage` 活动 → 实测通过 → 再按用户同意删掉旧的 `attack` 活动**。

**好处**：任何时刻都有一条可用的蓄力斩，不存在「旧的删了、新的没建对」的中间状态。

⇒ **替换类改动一律「先立后破」**，别先删后建。
