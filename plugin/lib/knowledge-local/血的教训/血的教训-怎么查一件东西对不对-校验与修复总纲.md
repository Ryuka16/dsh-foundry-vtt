# 血的教训 · 怎么查一件东西对不对 —— 校验与修复总纲

> 适用对象：**物品 / 法术 / 专长 / 种族特性 / 职业 / 子职**（FVTT + dnd5e 5.3.3）
> 立此文档的原因：前前后后猜了 30 多版、花掉 20 小时和 70 块钱，大部分浪费在**错误的判据**上。
> 本文把「哪些判据能用、哪些一定翻车、改的时候怎么改才不炸」一次写清。
> 配套：`血的教训-批量改模组数据篇.md`（批量操作细节）、`血的教训-建卡与升级授予篇.md`（advancement）

---

## 〇 · 只读十条（最贵的十条）

1. **中文描述 ⇄ 程序结构的静态判据，精确率长期 0~25%，一律不要用。**
   靠得住的只有三种外部锚点：**官方包逐字段对照 / 规则书原文 / 运行时实测**。
2. **「零效果」不等于「缺效果」。** 效果有四种不在 `item.effects` 里的合法形态（见 §2.1），
   只看 `effects` 会大面积误报（实测 feats-all 50 件里 38 件被误判）。
3. **compendium 上改 `effects` / `flags` / `activities` 只能「读旧 → 改 → 重建文档」**，
   `d.update(...)` 一律静默无效（不报错、读回不变）。
4. **`mode 3` 不是「禁用」，是「取更小的值」** —— 用它去中性化会把 10 变成 1。
   禁用要用 `disabled: true`。
5. **`traits.dr.value` / `statuses` 是 Set** —— `JSON.stringify` 恒为 `{}`，
   会让人误判「没写进去」。读必须 `Array.from()`。
6. **magic item 的 `transfer:true` 效果，必须 `equipped=true` + `attunement="attuned"` 才生效。**
   实测时忘了设，会得出「修复无效」的错误结论。
7. **官方件不一定比本包好。** 实测官方护盾术效果 `duration.seconds = null`（无战斗时算不出剩余时长），
   本包版本反而更完整。**官方对照只用于「官方有 ⟹ 必须有」，不用于「无脑抄」**。
8. **规则书原文是唯一能定「该给什么」的东西**；`【自动化无法匹配】` 这类作者自注**不可信**
   （本项目全部内容都是 AI 上一会话自己写的）。
9. **命中不等于真错。** 任何判据筛出的结果都必须**逐条人工核实**，不许批量改
   （实测 change-key 判据 333 命中只有 3 真错，不核实就会毁掉 330 条正确数据）。
10. **改完必须做「假键空白对照」** —— 否则分不清「键生效」与「值本来就是这样」。

## 一 · 查的总体流程（八步）

```
① 摸底     → 这东西在哪个包、什么类型、有没有活动/效果/flags
② 判有无   → 用「四形态并集」判断到底有没有自动化（§2.1）
③ 拿锚点   → 规则书原文 + 官方包对照（§2.2）
④ 逐条读   → 描述里每一句机制 ⇄ 数据里的每一个键（§2.3）
⑤ 计时长   → 描述时长 ⇄ 活动/效果时长（唯一全对的通用静态判据，§2.4）
⑥ 实测     → 装到临时角色上量派生值（§3）
⑦ 修       → 重建文档（§4）
⑧ 验证复扫 → 读回 + 复扫全库（§5）
```

**投入产出参考（2026-10-07 实测）**：均匀抽 100 件逐条读，**约 5 分钟**，查出 9 件真错（命中率 9%）。
同期用自动判据扫全库，多次出现「几百命中、零真错」。
⇒ **结论：抽样逐条读远比全库自动扫描划算。**

## 二 · 查 · 判据篇

### 2.1 ★ 判断「有没有自动化」—— 必须四者取并集

只看 `item.effects` 会把下面四类全判成「无效果」：

| 形态 | 判据字段 | 实测规模 |
|---|---|---|
| 普通效果 | `item.effects[]` | 主体 |
| **自选专长**（勾选后才生成效果） | `flags["longhua-feats"].options` | feats-all **50 件**，其中 38 件 `effects` 为空 |
| **CPR 嵌入宏**（宏自己创建效果） | `flags["chris-premades"].embeddedMacros` | 多件 |
| **ActiveAuras 光环** | 效果上的 `flags.ActiveAuras` | 防活物护罩等 |
| **dnd5e 原生 flag** | `flags.dnd5e.tavernBrawlerFeat` 等 | 斗殴高手等 |

```js
const 有自动化 = (o, e) =>
  (o.effects||[]).length ||
  (o.flags?.["longhua-feats"]?.options||[]).length ||
  (o.flags?.["chris-premades"]?.embeddedMacros||[]).length ||
  (e?.flags?.ActiveAuras) ||
  (o.flags?.dnd5e && Object.keys(o.flags.dnd5e).length);
```

⇒ **正确说法**：`effects` 空 + `longhua-feats.options` 有 = **正常**（属性 +1 走勾选）；
两者都空才是真候选。

### 2.2 外部锚点（唯一靠谱的两种）

**A · 官方包逐字段对照**
- 方向只有一条：**官方有 ⟹ 本包必须有**（实测 **0 误报**）。
- 反向（本包有而官方没有）**全是增强，不是错** —— 别去「修」。
- 配对方式：`system.identifier` 优先；中文包要靠**英文名归一化**。
- 官方件取自 `dnd5e.items` / `dnd5e.spells` / `dnd5e.classes` / `dnd5e.subclasses` / `dnd5e.races`。
- ⚠️ 格式差异要识别：本包带 `Convenient Effect: ` 前缀 ⇒ 字面不等但内容相同（误报）。

**B · 规则书原文**
- 库：`00_规则资料\5E 不全书-纯文本\`（4276 个 .txt）—— **grep 出文件名+行号再 read**。
- 中英之间**没有空格**（`优质Fine（瓶装）`），搜中文名或英文名**单独搜**。
- 搜不到先**换词根**（葡萄酒 → 酒 → Wine），不要断言「资料库里没有」。

### 2.3 ★ 逐条读：描述里的每一句 ⇄ 数据里的每一个键

**这是唯一能抓「重力井型错误」（描述说 A、实际做 B）的方法。**

读的时候逐句问四个问题：

| 问 | 举例（重力井） |
|---|---|
| **作用对象对不对**（谁受影响？） | 描述「该目标」；数据无条件推离**所有**命中目标 ⇒ 错 |
| **方向/符号对不对**（加还是减、优势还是劣势） | 描述「劣势」；changes 写 `advantage` ⇒ 错 |
| **数值对不对** | 描述「AC +2」；changes 只有 `dr.poison` ⇒ 缺 |
| **时机/时长对不对** | 描述「10 分钟」；两处都不写 ⇒ 0 秒立即掉 ⇒ 错 |

**已抓到的真错清单（可作模板）：**
- 两条冲突效果并存（风暴腰带 `取大29` + `覆盖29` ⇒ 30 力量被压回 29）
- 效果名指向另一个物品（守护者纹章挂着虔信护符的加值 ⇒ 同调白得法术 DC）
- 效果的 `transfer:true` 却挂着敌方状态（prone/frightened…）⇒ 会挂到自己身上
- 描述有常驻抗性/感官，数据里没有（红龙面具、风巨灵、石巨人）
- 描述有三种形态增益，只有一个空活动（月之赋能）

### 2.4 计时长（唯一全对通的用静态判据）

**战迹 22 命中 / 14 真错。** 机制（实测归纳）：

| 情形 | 实际时长来源 |
|---|---|
| 活动有实际时长 | 用活动的（勇气联结 活动 10minute ⇒ 实测 600s ✓） |
| 活动 `units:"inst"` | **退回用物品效果自己的 `duration`** |
| 效果写 `rounds`/`turns` 而 `game.combat` 为 null | **算不出剩余 ⇒ 显示「永久」** |
| 两处都没写 | 0 秒立即掉 |

**修法铁律（两处都写对）**：
```
描述 N 分钟 ⇒ 活动 {value:"N",units:"minute"} ∧ 效果 {seconds:N*60}
1 回合      ⇒ 活动 {value:"1",units:"turn"}   ∧ 效果 {seconds:6}
专注        ⇒ concentration:true + flags.dae.specialDuration:["concentration"]
永久        ⇒ 两处都不写
```

### 2.5 引用完整性扫描（高精度，0 误报）

**引用型字段全集**（缺一个就漏一类断链）：
```
活动：effects[]._id / otherActivityId / midiProperties.triggeredActivityId
     / enchant.riders[].uuid / summon.profiles[].uuid / transform.uuid
     / consumption.targets[].resource / cachedSpell
效果：flags.dae.macro / flags.itemacro.macro / flags["midi-qol"].onUseMacroName
     / change key 里的 macro.StatusEffect / flags.dae.specialDuration
物品：flags["chris-premades"].info.identifier / macros.midi.actor|activity|item
     / flags["midi-qol"].optional / system.source.rules
其他：flags.autoanimations / flags.auraeffects / flags.dnd5e.riders
```
- `triggeredActivityId` **只认 活动 id / identifier / uuid，不认活动 name**
  ⇒ 填中文名（「豁免」「治疗」）会**永久不触发**。
- `consumption.targets` 三种合法写法：**空串**（指向自己物品的 uses）/ **物品 uuid** / **identifier**；
  `spellSlots` 类型下 `target` 字段**完全被忽略**。
- 判据：能不能在**这张 actor** 上找到。

### 2.6 枚举值合法性（高精度，全中）

- **14 类伤害**：`necrotic, piercing, poison, bludgeoning, radiant, cold, slashing, vitality, fire, thunder, force, acid, lightning, psychic`（另有 `none` / `midi-none` 两个特殊值合法）
- **状态 id 必须来自 `CONFIG.statusEffects`**（实测 62 条）；带 `Convenient Effect: ` 前缀的 id **不在表里** ⇒ 图标画不出来
- **困难地形 9 种**：`slope, ice, sand, mud, liquid, snow, rocks, plants, web`
- **治疗 types 是闭集三键**：`healing` / `temphp` / `maximum`
- **所有 `_id` 必须恰好 16 位字母数字**（17 位会被 5.3.3 拒绝）

### 2.7 ❌ 明确禁用（会烧钱）的判据

| 判据 | 战绩 | 为什么失败 |
|---|---|---|
| 描述骰子 ⇄ 数据骰子 | 三次迭代 0~25% | 漏 `custom.formula` / 误用 `.base` 路径 / 漏 utility 的 `roll`；`@classes.*.levels` 公式与描述里的多个等级值**等价** |
| 描述状态名 ⇄ `statuses` | 588 命中 / ~0 真错 | 中文分不清「施加该状态」与「提及该状态」 |
| change key ⇄ actor schema | 333 命中 / **3 真错（0.9%）** | **最危险** —— 不核实就会毁掉 330 条正确数据 |
| 机制词 → 必备字段 | 719 命中 / 极少 | 中文自然语言与程序结构不同构 |

**唯一例外**：`system.traits.di.all` 这类**已证实无效的键**（实测 3 条），但那也是实测出来的，不是扫出来的。

## 三 · 查 · 运行时实测（唯一金标准）

**唯一有效的测法**：写 change → 读一个**会被它影响的派生值** → **同时用假键做空白对照**。

```js
// 1) 建临时桩（记得删）
const a = await Actor.create({ name:"临时测试桩", type:"character",
  system:{ abilities:{str:{value:10},dex:{value:10},con:{value:10},int:{value:10},wis:{value:10},cha:{value:10}},
           attributes:{ ac:{calc:"default"}, hp:{value:20,max:20} } }});
// 2) 基线
const 基线 = { dr: Array.from(a.system.traits.dr.value), dv: a.system.attributes.senses.darkvision,
               acBonus: a.system.attributes.ac.bonus, ac: a.system.attributes.ac.value };
// 3) 装件 —— ★ 魔法物品必须装备 + 同调，否则 transfer 效果不生效
for (const [pack,id] of 清单) {
  const o = (await game.packs.get("dnd5e_classpack."+pack).getDocument(id)).toObject();
  delete o._id; o.folder = null;
  if (o.system?.equipped !== undefined) o.system.equipped = true;
  if (o.system?.attunement !== undefined) o.system.attunement = "attuned";
  await a.createEmbeddedDocuments("Item", [o], { keepId:true });
}
await new Promise(r=>setTimeout(r, 400));   // DAE 写 flags 要一拍
// 4) 读派生值 + 5) 假键空白对照 + 6) reset（验不累积）+ 7) a.delete()
```

**高频坑（全部实测）**
1. **`Actor#effects` 只含卡文档自身的效果** ⇒ 要读 **`actor.appliedEffects`**（transfer 效果在这里）
2. **`traits.dr.value` 是 Set** ⇒ `JSON.stringify` 恒 `{}`，必须 `Array.from()`
3. **`MidiQOL.computeSkillAdvantage` 是 async**，不 `await` 得到空对象 ⇒ 误判「键无效」
4. **权威判据是 `r.attribution.ADV["skill.ste"]`**，不是 `r.advantage`（可能是空对象）
5. **DAE 写 flag 需要一拍**（`await new Promise(r=>setTimeout(r,300))`）—— 假阴性来源
6. **技能熟练在 `system.skills.X.value`**（0/1/2/0.5），不是 `proficient`
7. **dnd5e 5.3.3 没有 `system.attributes.spelldc`** —— 卡面 DC 是 UI 现算的
8. **测护甲前必须把 `attributes.ac.calc` 从 `natural` 改 `default`**，否则 AC 恒=10

## 四 · 改 · 修复篇

### 4.1 ★★ compendium 写入的硬约束（全部实测）

| 想做什么 | 能不能直接 update | 正确做法 |
|---|---|---|
| 改 `effects` 数组 | ❌ 无效（`updateDocuments([{_id, effects:[...]}])` 会**追加**而非替换） | **重建**：`o.effects = 目标数组; create(o,{pack,keepId:true})` |
| 删内嵌效果 | ❌ `update({effects:短数组})` 与 `effects.-=<id>` **都失败** | **重建** |
| 改 `flags` | ❌ 无效 | **重建** |
| 清空 `system.activities` | ❌ `d.update({"system.activities":{}})` 无效 | **重建** |
| 改活动**名** | ✅ 点号路径 `system.activities.<key>.name` 有效 | — |
| 改活动**内容/类型** | ✅ **保留原 key** 整体替换即可（dnd5e 按新 type 重新实例化） | `upd["system.activities."+原key] = 新对象` |
| 批量改 | ✅ `updateDocuments([...], {pack})` —— 快两个数量级（160 件归档仅 377ms+663ms） | — |

**★ 为什么改活动要用「保留原 key」而不是 `-=<旧键>`**：
实测 `-=<键名>` 会触发 `FeatData.preUpdateActivities` 拿键名当 id 去 `this.activities.get(id)`，
拿到 `undefined` 后访问 `.cachedSpell` 抛 TypeError —— **活动删不掉还报错**。

**★ effects 数组的合并语义**：
元素**带 `_id`** ⇒ 按 id 合并；**不带** ⇒ 追加。
⇒ 只想改效果名，也必须传**整条效果对象**（只给 `_id`+`name` 会丢字段）。

### 4.2 重建文档的标准写法

```js
const 重 = async (pack, id, 改) => {
  const p = game.packs.get("dnd5e_classpack." + pack);
  const d = await p.getDocument(id);          // ★ 必须用完整 16 位 id
  const o = d.toObject();
  改(o);                                       // 原地改 o
  await p.documentClass.create(o, { pack: p.collection, keepId: true });
  return (await p.getDocument(id)).toObject(); // 读回
};
```
- **`keepId:true` 是必须的** —— 换了 id 会让引用它的 advancement / 活动全部断链。
- ⚠️ `getIndex()` 的条目 id 字段是 **`_id` 不是 `id`** —— 写成 `e.id` 全是 undefined，
  `getDocument(undefined)` 返 null ⇒ **循环静默全跳过**（实测 550 次全跑空、0 改动 0 报错）。

### 4.3 一次调用能做完的复合修改

`foundry_patch_item` 支持一次调用同时改 **system + activities + flags + 挂宏**（内部读一次、改完整段写回），
比拆成两次 HTTP 更稳。挂物品宏它会**自动写全三处**（少写一处就静默不触发）：
```
① flags["midi-qol"].onUseMacroName = "[<macroPass>]ItemMacro"
② flags.itemacro.macro = {name,type:"script",scope,command}
③ flags.dae.macro       = {name,type:"script",scope,command}
```

### 4.4 改动前的三道闸（防止又一次「改了 400 件才发现改错」）

1. **勘察闸** —— 动手前把「模块 CHANGELOG + module.json + 目录结构 + 200 件样本」**一次拿全**。
   （实测教训：改 400+ 件前没读 CHANGELOG，不知道 `cpr-mapping.json` 一直存在，白干一轮）
2. **因果闸** —— **说不出「X 改正确之后，Y 会变成什么」就不许改**。
   只能描述相关、说不出因果的，就是没想清。
3. **备份闸** —— **说不出怎么恢复就不许执行**。dump 后必须**落盘成本地文件**
   （`game.__bak` 这类内存变量换世界就丢 —— 实测踩过）。

### 4.5 改的时候「不要做什么」

- **不要用 mode 3 当禁用**（那是「取小」）
- **不要因为「描述提到某状态」就加 statuses**（会用错场合）
- **不要无脑抄官方**（官方护盾术的 `seconds:null` 反而更差）
- **不要给条件式机制加无条件键** —— 例如「攀爬时的运动优势」加通用 `advantage.skill.ath`
  会**错给所有运动检定**。**宁可效果空着，也不给玩家一个错的数值。**
- **不要一次扫 7 个包** —— `getDocuments()` 必 HTTP 408；**一次只处理 2~4 包**
- **408 后先读回确认，绝不重跑** —— 实测一次 408 的调用**实际已写入 42 件**

## 五 · 验 · 改完必做的三件事

1. **读回**：`foundry_diff`（点号路径逐字段比对期望值）或 `foundry_inspect`

2. **运行时实测**：见 §3（装件 → 读派生值 → 假键对照 → 清理）

## 六 · 分对象的专属检查清单

### 6.1 物品（武器 / 护甲 / 消耗品 / 奇物）
- [ ] **类型对不对** —— 描述说是武器/护甲，`type` 却是 `loot` ⇒ 不进武器栏、不参与 AC、挂不上活动
      （实测 18 件 BMT 通用件；**Foundry 不允许改文档 `type`，只能重建**）
- [ ] **AC 双算** —— dnd5e 算 AC = `armor.value + armor.magicalBonus`；
      本包曾把魔法加值算进 value 又填一遍 magicalBonus（实测 35 件，链甲+1 AC 18 应为 17）
- [ ] **缺 `itemProperties`** —— 重甲缺 `stealthDisadvantage`、精金系列还缺 `ada`（实测 22 件）
- [ ] **+N 武器缺攻击活动** —— 规律极干净：基础版有 1 活动、`+1/+2/+3` 全 0（实测 116 件）
- [ ] **`system.damage.base`** —— dnd5e 5.3 武器伤害骰放 `damage.base{number,denomination,bonus,types}`，
      活动里 `parts:[]` + `includeBase:true` 才是官方写法
- [ ] **消耗品 `uses`** —— 药水/弹药 `autoDestroy:true`；**魔杖/法杖 `false`**（可充能，别自毁）

### 6.2 法术
- [ ] **`cast` 活动的 `spell.uuid` 是否有效** —— Plutonium 伪 uuid（含 `plutonium-faux-id`）在世界没装
      plutonium 时 `fromUuid` 返 null ⇒ **点「施放」无反应、不报错**（实测 110 件）
- [ ] **`spell.level` 必须是数字** —— `null` 会报 `Cannot convert undefined or null to object`，连活动都建不了
- [ ] **空 uuid 的 cast 会直接抛错**（`Cannot read properties of undefined (reading 'flags')`）⇒ 改成 utility
- [ ] **是否已被 CPR/GPS 覆盖** —— 若官方有，走官方原件（见 §7）
- [ ] **伤害/豁免/模板在活动里**（不是物品级）；`save.dc = {calculation:"", formula:"15"}` 才是固定 DC

### 6.3 专长
- [ ] **是否有「自选」体系**（`flags.longhua-feats.options`）—— 属性 +1 常走勾选，不是缺
- [ ] **描述里的常驻增益有没有落实** —— 抗性 / 感官 / 先攻优势（实测风巨灵缺抗性、石巨人缺黑暗视觉）
- [ ] **限时增益** —— 应挂在活动上（`transfer:false` + `activity.effects[]._id`），不是常驻

### 6.4 种族特性
- [ ] **`spell.spellbook` 必须 `false`** —— 天生法术缓存副本若进法术书，会显示成「可以一直使用」
      （实测 racial-traits 56 件 / 120 条 cast 活动）
- [ ] **`traits.languages.value` 必须全大写 `"ALL"`** —— 源码 `if (languages.value.has("ALL"))`
- [ ] **天生法术 `method:"innate"`** + `{max:"1", per:"lr"}`（官方金标准：`dnd5e.races` 只有 12 个带 spell 的 advancement）
- [ ] **技能/语言的来源** —— 常在种族物品的 `advancement`（`value.chosen`），别误判成「多给了」

### 6.5 职业 / 子职
- [ ] ★★ **`system.spellcasting.ability`** —— **非施法职业必须是空串 `""`**。
      拖职业物品时 dnd5e 执行 `actor.update({"system.attributes.spellcasting": ability})`，
      **不检查 progression** ⇒ 武僧/战士/游荡者的卡面会凭空多出「感知 DC 13 / 法术攻击 +5」，

- [ ] **子职的 `classIdentifier`** 指向正确职业
- [ ] **`startingEquipment` 的 uuid 有效**（本包曾正确配置但建卡没导入 ⇒ 别当成包的错）
- [ ] **14 个职业应与官方 `dnd5e.classes` 逐字一致**（本包已校准）

## 七 · 与外部自动化体系（CPR / GPS）的边界

**核心原则：CPR/GPS 做过的，一律用官方原件，不要自己另做一份。**
（用户原话：「CPR 所有的东西都是经过验证的」）

- **匹配靠 identifier，不是名字**：
  `flags["chris-premades"].info.identifier`（驼峰，如 `cloudOfDaggers`）
  vs GPS 的短横线 `cloud-of-daggers` ⇒ 比对前必须归一化 `s.toLowerCase().replace(/[^a-z0-9]/g,"")`
  ⚠️ 反面案例：本包「护盾术」(ident `shield`) 按名字搜 "Shield" 会命中 `CPRMonsterFeatures` 的
  `shieldGuardianShield`（盾牌守卫的盾）—— **完全另一个东西且不报错**
- **GPS 的宏挂在 `flags["midi-qol"].onUseMacroName`**，指向运行时 `game.gps.<identifier>`，
  **不是** `flags["chris-premades"].macros`（第一次漏导就是因为这个）
- **换活动/flags，不换 effects** —— 官方效果反而可能更差（官方护盾术 `seconds:null`）
- **CPR 官方包分 2014 与 2024 两套** —— 对照前先确认版本（本项目 = 2014/legacy）
- 汉化用**双语** `中文 英文原名`：`轰雷剑 Booming Blade`（英文一字不动，方便 CPR 重新匹配）
- **重名件**（同 identifier 多件）多半是 TCE / SCAG 等**多来源版本**，不是错
