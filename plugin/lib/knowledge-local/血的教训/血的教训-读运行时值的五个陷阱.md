# 血的教训 · 读运行时值的三个陷阱（FVTT / dnd5e / midi / DAE）

> 立此文档的起因：2026-10-07 排查 dnd5e_classpack 零活动件时，
> **三次因为「读法不对」而得出「数据是错的」结论，三次全是假警报。**
> 其中一次差点去改一批**本来就对**的抗性数据。
> 这三个坑不分模块、不分项目，**任何 FVTT 调试都会撞上**，故单独成篇。

---

## 陷阱一 · `JSON.stringify(Set)` 恒为 `{}`

### 现象

```js
actor.system.traits.dr          // → {"value":{},"custom":"","bypasses":{}}
JSON.stringify(actor.system.traits.dr.value)   // → "{}"    ❌ 看起来是空的
```

### 真相

dnd5e 的 `traits.dr.value` / `di.value` / `dv.value` / `ci.value` 是 **`Set`**，不是数组。
`JSON.stringify` 对 Set 一律输出 `{}` —— **有值也输出 `{}`**。

### 正确读法

```js
Array.from(actor.system.traits.dr.value)   // ✅ ["poison","acid"]
[...actor.system.traits.dr.value]          // ✅ 等价
```

### 代价

本轮开始时用错读法，得到「效果写进去但没生效」的结论，
进而怀疑 `changes` 的 mode / key 写错，**差点批量"修"一批本来就正确的数据**。
同一轮里 `ci`（状态免疫）也一样被误读为空。

### 自检句

> 凡是读 dnd5e 的 `traits.*.value`，**先问自己这行有没有 `Array.from`**。
> 没有 ⇒ 你读到的 `{}` 毫无意义。

同样属于 Set/Map 的还有：`actor.system.traits.languages.value`、`traits.armorProf`、`traits.weaponProf`。

## 陷阱二 · `MidiQOL.computeSkillAdvantage` 的返回形状不稳定

### 现象

```js
const r = await MidiQOL.computeSkillAdvantage(actor, "ste", {});
r.advantage.active     // ❌ 有时 true，有时 undefined
```

同一段代码、同一个 actor，**不同调用时序下返回结构不同**：
有时 `advantage = {active:true, suppressed:false, override:false}`，
有时 `advantage = {}`（空对象）。

### 正确判据

**看 midi 自己吐出来的「归因」字段**，那是它判定过程的原始记录：

```js
r.attribution.ADV["skill.ste"]      // ✅ "优势 (隐匿)"
r.legacyAttribution                 // ✅ ["ADV:skill.ste"]
```

有归因 = 真的判成了优势；没归因 = 没有。
**不要读 `advantage.active`。**

### 同类 API

- `MidiQOL.computeAbilityAdvantage(actor, rollType, abilityId, options, tracker)`
  —— 源码里的 flag 名（**权威**）：
  ```js
  advantageFlags: [ "advantage.all", "advantage.ability.all",
                    `advantage.${rollType}.all`, `advantage.${rollType}.${abilityId}` ]
  ```
  ⇒ 「全豁免优势」= `flags.midi-qol.advantage.save.all`
  ⇒ 「感知豁免优势」= `flags.midi-qol.advantage.save.wis`
- `MidiQOL.computeToolAdvantage` —— 同理

### 兜底判据（最不容易骗人）

**直接读 DAE 写进 actor 的 flag**：

```js
actor.flags["midi-qol"].advantage.skill.ste    // → true
actor.flags["midi-qol"].advantage.save         // → {all: true}
```

这是**运行时真实结果**，不依赖任何计算 API 的返回形状。

## 陷阱三 · DAE 写 flag **需要一拍**，立刻读会读到空

### 现象

```js
await item.update({ system: { equipped: true } });
actor.flags["midi-qol"]        // ❌ 还是空的
```

### 真相

DAE 是在 actor 的 `prepareData` 周期里把 transfer 效果的 `changes` 铺进 `actor.flags` 的，
**`update` 的 Promise resolve 时还没铺完**。

### 正确做法

```js
await item.update({ system: { equipped: true } });
await new Promise(r => setTimeout(r, 300));   // ✅ 等一拍
actor.flags["midi-qol"]                        // ✅ 有了
```

### 代价

同一轮里，「精灵靴」先被判为「优势不生效」，
加延时后立刻正常（`attribution.ADV["skill.ste"] = "优势 (隐匿)"`）。
**这是一个纯粹的假阴性，与数据无关。**

### 自检句

> 凡是「写 → 立刻读」的验证，**先怀疑自己要等一拍**，
> 而不是先怀疑数据写错了。延时 300ms 起步，必要时 500ms。

## 陷阱四（附带）· 验证「键是否生效」必须读**派生值**，不能回读键自己

DAE 只是把 change **写进 data**，所以：

```js
await effect.update(...)                       // 写 key = system.attributes.senses.darkvision
actor.system.attributes.senses.darkvision      // 回读能读到 —— 但这**不构成证据**
```

写一个**必假的键**（如 `system.attack.bonus`）也一样能回读出来。
⇒ **回读键自己不构成证明。**

**正确测法**：读一个**会被它影响的派生值**，并同时挂一个假键做空白对照。

| 想验的键 | 该读的派生值 |
|---|---|
| `traits.dr.value` | `Array.from(actor.system.traits.dr.value)` |
| `attributes.ac.bonus` | `actor.system.attributes.ac.value`（**先把 `ac.calc` 从 `natural` 临时改 `default`**，否则 AC 恒=10 测不出） |
| `attributes.movement.swim` | `actor.system.attributes.movement.swim`（改 `walk` 看它跟不跟着变） |
| `abilities.X.value` | `actor.system.abilities.X.value` / `...mod` |
| `system.bonuses.mwak.damage` | `actor.getRollData().bonuses.mwak.damage`（★ `item.labels.damage` **不含** bonus） |
| `flags.midi-qol.advantage.*` | `actor.flags["midi-qol"].*` + `computeXxxAdvantage().attribution` |

## 陷阱五（附带）· `advancement` 为空 **≠** 缺口

扫到 **14 个职业全部没有 `Spellcasting` advancement**，一度判为「角色根本无法施法」的致命缺口。

**实查**：dnd5e **5.x 用 `class.system.spellcasting` 字段**承载施法能力：

```json
{ "progression": "full", "ability": "wis",
  "preparation": { "formula": "@abilities.wis.mod + @classes.cleric.levels" } }
```

本包 14 个职业全部正确，与官方 `dnd5e.classes` **逐字一致**。

⇒ 若贸然「修」会给 14 个职业加重复的施法 advancement，**搞坏整个施法系统**。

### 判据

> 看见「某某字段是空的」时，**先确认这个版本里它该不该在这里**。
> dnd5e 5.3.3 与 6.0.0 的字段位置差异极大（另见：移速、感官、活动类型数量）。

## 一页速查

| 症状 | 真因 | 正确做法 |
|---|---|---|
| `traits.*.value` 读出来是 `{}` | Set 被 JSON 序列化 | `Array.from(...)` |
| 优势判据时真时假 | `advantage` 字段形状不稳定 | 读 `attribution.ADV` |
| 装完装备 flag 是空的 | DAE 还没铺 | `setTimeout` 300ms 再读 |
| 回读键有值但「就是没用」 | 回读键自己不构成证明 | 读派生值 + 假键空白对照 |
| `advancement` 空 | 5.x 可能在 `system.*` 里 | 先对照官方包同件 |
| 测护甲 AC 恒为 10 | 测试桩 `ac.calc = "natural"` | 临时改 `default`，测完还原 |
| 伤害加值不生效 | `labels.damage` 不含 bonus | 读 `getRollData().bonuses.*` |
| 批量脚本 408 | 脚本太重（多轮全包遍历） | 一次取数、多判据共用 |
| 408 后重跑造重复 | 超时的调用常已落库 | **先读回确认，绝不重跑** |
