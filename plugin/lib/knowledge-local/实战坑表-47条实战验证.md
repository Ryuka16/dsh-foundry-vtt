## [L001] Aura Effects 光环 applyToSelf 不随移动刷新 + 改原型不生效（unlinked token 副本）
- **时间**: 2026-10-07
- **标签**: auraeffects, 光环, applyToSelf, unlinked-token, cpr, embeddedMacros, 方阵行军
- **现象**: 方阵行军（Aura Effects 1.5.2 光环，applyToSelf:true）行为随机：有时「没有亡灵在身边也一直 +3 AC」，有时「有亡灵在 10 尺内但自己和先攻都不加」。拖 token 进出范围时，盟友能正确得到/失去加成，但光环持有者自己的 changes 完全不动。
- **根因**: 两层原因叠加。①模块层：auras.mjs 所有 hook（createToken/updateToken/moveToken）都以「被动方 token.actor」为基准评估光环，且送达逻辑 L53 硬排除 mainToken（t !== mainToken）——所以「光环持有者自己」那份 changes 只在 effect.prepareDerivedData 里更新，而它只在 actor 真实更新时跑，拖 token 不触发。②Foundry 层：NPC 默认 prototypeToken.actorLink=false（unlinked token），已放置的 token 持有独立 actor 副本，其 effects 存在 tok.document.delta 里 —— 改原型 actor 的 effect 不会同步到已放置的 token。实测证据：原型 script 长度 1861 / token 那份仍是旧的 710；protoScriptLen≠tokenScriptLen，sameActorDoc=false。另：AuraActiveEffectData.mjs L81 `this.parent.parent` 对原型 actor 的 effect 是 NULL，导致 L89 `actor?.getActiveTokens()` 短路，applyToSelf 分支整个跳过。③helpers.mjs:83-97 executeScript 的 catch 返回 true（放行），所以 script 报错时表现为「一切正常但你的副作用没跑」。
- **正确做法**: 光环 AE 的 system.script 只做纯判定（别塞副作用），把同步交给 CPR 嵌入式宏，且必须同时写「原型 actor」和「已放置 token 的 actor」两份。四个宏（flags.chris-premades.embeddedMacros）：{type:"movement",pass:"moved"} + {type:"movement",pass:"movedNear"} —— 宿主自己移动 / 别人走近时，用 tokenUtils.findNearby(tok,10,"all") 判定并 genericUtils.update(eff,{changes}) ，随后必须 await me.update({"flags.auraeffects.lastSync": Date.now()}) 触发 actor 重算（只改 effect.changes 不会让 AC 重算）；{type:"effect",pass:"created"} —— 送达出去的效果被创建时，若 flags.auraeffects.fromAura 为真则把它自己的 changes 补成正确值（因为送达发生在宏之前，送出去时 changes 可能还是空的，表现为「目标有 buff 图标但 AC 不变」）；{type:"effect",pass:"deleted"} —— 效果消失时回调光环持有者重算。script 纯判定版语义（模块问的是「这个候选 token 该不该在光环内」）：候选和源都必须是目标类型，且源周围存在另一个符合条件的 token 才算 true。卸载/重放 token 后新 token 会从原型复制，自动正确。

## [L002] 不施法职业的 spellcasting.ability 会污染卡面（武僧显示「感知 DC 13」）
- **时间**: 2026-10-07
- **标签**: spellcasting, 卡面, 职业, 子职, dnd5e, attributes.spellcasting
- **现象**: 武僧/战士/游荡者/野蛮人这类不施法职业，卡面（法术书页）显示「[属性名] DC N / 法术攻击 +N」，如武僧显示「感知 DC 13、法术攻击 +5」。改包也修不掉已有卡。
- **根因**: dnd5e 5.3.3 拖入职业/子职物品时执行 await actor.update({ "system.attributes.spellcasting": this.parent.spellcasting.ability })，★不检查 progression ⇒ 只要 ability 非空（哪怕 progression:"none"）就永久写进卡。attributes.spellcasting 是 StringField 存档字段（不是派生值），一旦写进 _source 就留在卡上。另：this.attributes.spell.dc = ability ? ability.dc : 8 + this.attributes.prof ⇒ spell.dc 永远有值（最少 10），不存在「DC 空所以不显示」。
- **正确做法**: ① 包内：不施法职业/子职的 system.spellcasting.ability 必须写空串 ""（progression:"none" 不能豁免你）。② 但 third（诡术师/奥法骑士）保留 int 是对的，别一刀切；合法 progression = full/half/third/pact/artificer。③ 老卡必须单独清：await actor.update({"system.attributes.spellcasting":""}) + 卡上那份职业副本 update({"system.spellcasting.ability":""})，或删掉重拖。④ 判据：spellcasting 存在 ∧ ability 非空 ∧ progression ∉ {full,half,third,pact,artificer}。⑤ 能力 DC 应靠 save.dc.calculation 表达（实测：calculation="int" ⇒ dc.value=8+prof+intMod，与 attributes.spellcasting 完全无关，可做对照实验验证——假说A按int算 vs 假说B按spellcasting算，必须让两者数字不同，用 intMod=0 的 npc 做会两个都得10等于没做）。

## [L003] AC5E 没有伤害倍率字段 —— 「伤害减半」类机制做不了精确版
- **时间**: 2026-10-07
- **标签**: AC5E, damage, 倍率, 减半, 能力边界
- **现象**: 给敌人挂效果、要让「他的武器攻击造成的伤害减半」（如 DND5E 魔射手-虚弱矢），查 AC5E 找不到对应 flag；上一会话的自注写「AC5E 的 damage 模式只能加值/改骰，不能做倍率」。需查证自注是否属实。
- **根因**: 通读 模块文档\Automated Conditions 5e (AC5E)\Flags-functionality.md L100-139 确认：damage 模式只有 bonus(加值)、extraDice(加/乘骰数，语法 bonus=2 加骰、bonus=x2 或 ^2 乘骰，无 ×0.5)、diceUpgrade/diceDowngrade(改骰面)、modifyDenomination(改骰面)、typeOverride(改类型)、modifier(Foundry roll modifiers，adv/dis 为伤害优劣势)、critical。没有任何"倍率/最终值乘算"入口。
- **正确做法**: 「把目标造成的伤害减半」类机制不要承诺能做。可行的只有近似：① flags.automated-conditions-5e.damage.modifier = "dis"（伤害劣势，方向对但不精确）；② 若能接受改骰面，用 diceDowngrade（d8→d6 ≠ 减半）。判定前先查 AC5E 文档，不要凭"AC5E 很强大"就假设能做。同类已知做不到的还有：按 HP 分档（圣言术）、精确移除抗性（SetField 无移除）。

## [L004] dnd5e 活动等级门控用 visibility.level.min/max
- **时间**: 2026-10-07
- **标签**: activity, 等级门控, visibility.level, relevantLevel, dnd5e
- **现象**: 某个物品活动应该只在达到特定等级后才能使用（例如「18 级后额外 2d6 伤害」），但活动级看不到等级限制字段，L3 的角色也能点。
- **根因**: dnd5e.mjs 源码判定：`if ( ((this.visibility?.level?.min ?? -Infinity) > level) || ((this.visibility?.level?.max ?? Infinity) < level) ) return false;` —— level 取活动的 relevantLevel。字段类型是对象 {min, max}，缺省时 min=-Infinity / max=+Infinity（即不限制）。
- **正确做法**: 给活动加等级门控：`d.update({"system.activities.<活动键>.visibility.level": {min: 18, max: null}})`（实测读回 {"min":18,"max":null} 生效）。用途：某活动只在特定等级可用时（如魔射手放逐矢的「18 级额外 2d6 力场伤害」不该在 L3 就能点）。★ 另一条更常用的路子是公式缩放：`(ceil(@classes.fighter.levels/17)*2)d6` ⇒ L3~17 得 2d6、L18+ 得 4d6，无需门控即可自动随等级变化。

## [L005] compendium 的 getIndex() 不索引 flags，用它统计会恒得 0
- **时间**: 2026-10-08
- **标签**: compendium, getIndex, flags, 批量扫描, 408
- **现象**: 扫 21 个 classpack 包统计「有多少件挂了 flags["chris-premades"]」，结果 total=0 / byPack={}，差点得出「classpack 里根本没有 CPR 物品」的错误结论。但同一批包里明明有 556 件带 CPR flags（后续 getDocuments 证实）。
- **根因**: CompendiumCollection#getIndex() 返回的 index entry 只含 name/type/img/sort/folder 等索引字段，flags 不在其中。实测 index.contents[i].flags === undefined（hasFlags: false）。
- **正确做法**: 要按 flags 筛选/统计，必须用 `await pack.getDocuments()` 拉完整文档再读 d.flags。index 只能用于「按名字/类型找 id」。若数据量大，一次只处理 1~2 个包，否则单次 execute_js（约 35s 上限）会 HTTP 408。

## [L006] compendium 上 effects:[...] 是追加不是替换，删/换只能重建文档
- **时间**: 2026-10-08
- **标签**: compendium, effects, updateDocuments, 重建文档, 内嵌文档
- **现象**: updateDocuments([{_id, effects:[一条新效果]}], {pack}) 后读回，effects 变成两条（原有那条 + 新写那条），旧效果没被替换掉。想「用官方效果覆盖本包效果」时，反而把两条都留下了。
- **根因**: Foundry 对内嵌文档数组的 update 语义：传 effects:[新数组] 时，_id 不匹配的会被当作新增合并进去，而不是整体替换。实测写 1 条新效果后读回是 2 条（原有 + 新的，_id 不同）。这与普通 ArrayField「整体替换」的直觉相反。
- **正确做法**: 要真正替换或删除内嵌 effects，只有重建文档一条路：const o = doc.toObject(); o.effects = 目标数组; await pack.documentClass.create(o, { pack, keepId: true }); ——实测有效，且重建后 system.activities 完好无损。本次 39 件效果名汉化全部走此法。

## [L008] compendium 里改 effect 名：传带 _id 的完整数组是「合并」，传点号路径 effects.0.name 是「追加」
- **时间**: 2026-10-08
- **标签**: compendium, effects, updateDocuments, dnd5e, locked
- **现象**: 要改 compendium 里物品的内嵌效果名。用 updateDocuments([{_id:"物品id", "effects.0.name":"新名"}], {pack}) ⇒ 读回**两条效果**（旧的 + 新的，_id 不同）⇒ 效果被克隆了一份。
- **根因**: Foundry 的 ArrayField 更新语义：数组元素**带 _id** 时按 id 合并（原地更新那一条）；不带 _id（或纯点号路径新建）时按「追加」处理。我此前记录的「compendium 的 effects 只能重建文档」只对**不带 _id 的新数组**成立，结论过宽。
- **正确做法**: 改效果名/改效果字段一律用：`const o = doc.toObject(); await pack.documentClass.updateDocuments([{_id: doc.id, effects: o.effects.map(e => Object.assign({}, e, {name: 新名}))}], {pack: "包名"})` ⇒ 实测效果条数不变、名字原地更新（`12oJ5jVCx8i48uFC:护盾术 Shield` → `12oJ5jVCx8i48uFC:Shield`）。**必须把整条效果对象都带上**（只给 _id+name 会丢其他字段）。若已误用点号路径造出重复，用 `pack.documentClass.create(o, {pack, keepId:true})` 重建修复。另：compendium 若 locked:true，任何写入都报 `You may not update documents in the locked compendium "<x>"` ⇒ 先 `await pack.configure({locked:false})`。

## [L011] 批量改数据前三道闸：勘察闸 → 因果闸 → 备份闸（任一道没过不许动手）
- **时间**: 2026-10-08
- **标签**: 元规则, 批量改, 因果推断, 备份, 勘察, CHANGELOG, 流程纪律, classpack
- **现象**: 我要对 ≥50 件数据做批量写入（改名/改字段/覆盖），理由是「我看了两个样本的 diff，差异字段是 X」。实测代价：据两件轰雷剑的 diff 让用户把 496 件物品名全改成纯英文，之后又全部改回来，20 分钟大半在补救。触发信号有三条，中任意一条就该停：① 改动规模 ≥50 件而我的依据只是 1~2 个样本；② 我把「A 和 B 不一样」当成了「A 导致 B」；③ 我说不出这批数据改错了怎么恢复。
- **根因**: 两件样本的 diff 只能指出「哪里不一样」，指不出「哪个是原因」。本次拿「错的那件缺 flags.chris-premades.info.rules/forceCEOff/effectActivation」这个差异，直接推出「因为活动名带中文所以 CPR 匹配不上」，中间没有任何因果链验证；把相关当因果，就会得出一个「正确但无用」的方案，然后拿它去改 496 件数据。而模块自己的 CHANGELOG.md 第一行就写着「无需修改物品名即可匹配」。判据：如果只能说「因为 X 所以 Y」、却说不出「把 X 改正确之后 Y 会变成什么样」，那 X 就不是病因。
- **正确做法**: 动手前过三道闸，任何一道没过就不许写：\n① 【勘察闸 · 动手前 ≤1 分钟，一次拿全】fetch("modules/&lt;模块id&gt;/CHANGELOG.md") + fetch("modules/&lt;模块id&gt;/module.json") + foundry_file_system{source:"data", path:"modules/&lt;模块id&gt;"} 列模块目录 + 一次拉 200 件的字段样本（不是看一件想一件）。目的：回答「作者原本怎么设计的」和「有没有现成映射表/备份」。工具里已有的一律先用：foundry_knowledge{topic:"manuals"/"local"}、foundry_reference、foundry_howto。\n② 【因果闸】写出「因为 X 所以 Y」之后，必须再写出一句「把 X 改成正确值后，Y 会怎么变」。写不出 ⇒ 判为相关而非因果 ⇒ 停下改数据，转去读文档或直接问用户。\n③ 【备份闸】动手前先答「改错了怎么恢复原样？」。答不出 ⇒ 不许执行。答得出 ⇒ 先把将被覆盖的值一次 dump 全（不是逐件读），挂 game.__bak，并立刻落盘成本地文件——game.__* 换世界就没了（实测踩过），落盘才叫备份。\n④ 【回滚预演】改完立刻用 foundry_diff 或回读脚本核对至少 5 件，确认可逆，再往下批量。

## [L047] 法术的时长与专注在【物品级】system.duration / properties，活动级 inst+override:false 是「继承」不是「错」
- **时间**: 2026-10-09
- **标签**: spell, duration, concentration, override, item-level, inheritance
- **现象**: 扫全库 545 件法术，91 件命中「描述说限时（N 分钟/小时）而活动级 duration 全是 inst」⇒ 险些全部判为真错并批量改活动级。

**实测对照**（`dnd5e_classpack.spell`）：
```
生命灵光 9WDd3gopYOGyYnrT  物品级 duration={value:"10",units:"minute"} + properties 含 "concentration" ｜ 活动级 inst/override:false
放逐术   lopw7wVkPoE7gbNu   物品级 duration={value:"1",units:"minute"}  ｜ 活动级 inst/override:false
通晓语言 v0KfpSysfp5ug9kx  物品级 duration={value:"1",units:"hour"}    ｜ 活动级 inst/override:false
魔法伎俩 zaUmr54yGtLyvUVC  物品级 duration={value:"1",units:"hour"}    ｜ 活动级 inst/override:false
```
**配套实测**：spell 包 545 件里 `properties` 含 `concentration` 的 246 件 ✓；「描述含『专注』但无该属性」只有 5 件，逐件读上下文**全是误报** —— 灵魂牢笼（「如同你正专注于一个法术」）/ 突触静止（描述的是效果持续，法术本身非专注）/ 思想编码（条件句「专注于一个允许读取思想的法术」）/ 守卫刻文（「如果**被刻入的法术**需要专注」）/ 动植物定位术（「你**专注于**附近的自然之音」= 叙事动词）。

判据写法：**不要用「描述含时限词 ∧ 活动级 inst」判错** —— 那会命中 91 件全是误报。要判时长，必须**先读物品级 `system.duration`**，再与描述比对。
