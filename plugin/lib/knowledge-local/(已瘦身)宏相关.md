宏的应用场景
宏可以实现诸如自定义动画，更多的自动化等效果。但也会因为过多代码拖慢工作流，出现服务器卡顿，或是严重的bug影响工作流结算，请使用前在应用环境（服务器中）进行充分的测试以免出现影响体验的问题。
此外，由于DND系统（其它系统API调整较少）经常更换或删除API接口，应用宏时请务必确认版本，包括FVTT版本和规则系统版本。更新VTT系统或是规则系统时，请一并更新宏（这也就是为什么宏写多了版本就会难以更新的原因），宏的便捷程度和数量多少因不同规则和不同使用者而异。

添加一个宏
在FVTT中使用宏需要创建一个宏来执行，可以是使用物品，添加dae效果或是特殊效果。

在物品的此处（不同UI和版本有所区别）可以添加物品的宏。
此外，还可以使用hook来绑定全局宏，使用图块或区域来触发宏，或是使用dae效果来执行一个宏。不同情况触发的方式不同，以具体宏为准。
- 从快捷栏添加的宏只有点击执行时才会执行，适合全局效果，或是单次效果，例如清除测量版等。
- 从人物身上添加的宏会在所有人物相应动作时触发，适合绑定人物的效果，例如重击动画。
- 从物品中添加的宏只会在物品使用时触发，适合诸如饮血剑，奥术回想等自动化。
如果一个宏需要让玩家来执行，请在核心设置的权限管理中，打开玩家的宏权限。

JavaScript 对象
（译者注：可以参考菜鸟教程-JavaScript-对象）
JavaScript 对象是一种结构化存储数据的方法。对象是一组键值对，每个键是一个字符串，每个值可以是任何类型的数据，包括其他对象。
物体可以通过花括号{} 来识别。例如：
{ name: "John", age: 30, city: "New York", }
对象的属性可以通过点符号.来访问。例如，如果这是 指示物 数据的一部分：
{
document: {
name: "John",
texture: {
src: "icons/svg/dice-target.svg",
},
width: 1,
height: 1,
}
}
你可以使用 token.document.texture.src 访问指示物的图像路径。例如：
console.log(token.document.texture.src);
控制台输出：
icons/svg/dice-target.svg // 以DND5e的范例角色Akra为例，输出会是systems/dnd5e/tokens/heroes/ClericDragonborn.webp
关于引号的说明
在访问对象时，在这些例子中，有时你会看到部分对象被引号包裹。这是因为对象是字符串。例如，指示物document.texture对象的 src 属性是一个包含图像路径的字符串。
有时，键也需要引号标记，因为键包含特殊字符。
例如：
{
document: { // document键，没有特别的字符，因此不需要用引号标记
name: "John", // "John"是一个字符串值，所以我们要用引号标记
texture: {
src: "icons/svg/dice-target.svg",
},
width: 1, // 1是一个数字，所以我们不需要用引号标记
height: 1,
}
}
嵌套属性也可以通过对象中的点符号访问，上述示例等价于：
{
document: {
name: "John",
"texture.src": "icons/svg/dice-target.svg", // 这个键包含特殊符号，所以要用引号标记
width: 1,
height: 1,
}
}
请注意，如果你想避免混淆，也可以选择一直用引号标记，例如：
{
"document": {
"name": "John",
"texture.src": "icons/svg/dice-target.svg",
"width": 1,
"height": 1,
}
}

文档与非文档
在 FVTT中，理解文件与非文档的概念至关重要。通常，文档是永久存储在游戏世界中的数据结构，而页面重新加载时其他所有内容都会丢失。

实际操作
在上一篇文章中，我们讨论了作为宏参数，可访问actor 对象和 token 对象。

actor 是文档

token 是可放置的（非文档）;他们的文档是 TokenDocument。

需要说明的是，当你在宏中访问token时，你访问的是场景中的令牌的视觉表现（译者注：不太理解视觉表现是什么意思，但是原文如此，大概只是说访问的token的数据不是持久化数据吧），而不是存储在 TokenDocument 中的实际数据。
要访问指示物的数据，你需要使用 token.document 属性来访问 TokenDocument。
示例（将指示物文档记录到控制台）：
console.log(token.document);

与文档的互动
如前所述，文档是存储在游戏世界数据库中的数据。改变文档数据会反映在游戏界面里（译者注：即Client端），但不会影响游戏世界数据库（译者注：即服务器端或者GM端）。
JavaScript 中的赋值
（译者注：可以参考菜鸟教程-JavaScript变量）
在 JavaScript 中，你可以用 = 作符为变量赋值。例如：
let name = "John";
变量是存储在内存中以便以后参考的数据。例如：
let name = "John";
console.log(name);
这段代码的输出将是John。
JavaScript 中有两种变量：let 和 const。let 关键字声明一个可以重新分配的变量，而 const 关键字声明一个无法重新分配的变量。（译者注：这里的重新分配指的是v = "xxx";这种重新分配，而不是对部分的修改，比如v.doc = "xxx"）
let name = "John";name = "Jane";console.log(name);
这段代码的输出将会是 Jane.
const name = "John";name = "Jane";console.log(name);
该代码的输出将是错误，因为name变量无法重新分配。
为文档分配值
虽然你可以在 JavaScript 中为变量赋值，但这种方法对文档不适用。给文档分配值不会改变游戏世界中存储的数据;它只会为你的客户端更改，直到你刷新页面。（译者注：这里要注意区分游戏世界和客户端的数据）
示例（更改令牌名称）：
token.document.name = "Jane";
这行不通，因为游戏世界中代币名称不会改变。
更新文档
正确的更新文档方式是使用update方法。该方法将一个对象作为参数，并用该对象的值更新文档。
示例（更新令牌名称）：
token.document.update({ name: "Jane" });
这会更新所有用户在游戏世界中的代币名称。
你可以通过传递一个拥有多个属性的对象来同时更新多个属性。
示例（更新令牌名称和大小）：
token.document.update({  name: "Jane",  width: 2,  height: 2,});
异步操作
当文档更新时，数据需要通过网络传输到服务器，再返回客户端。因此，游戏世界中的数据不会立即更新。
让我们看看一个异步作的例子：
console.log(token.document.name); // Output: John
token.document.update({ name: "Jane" });
console.log(token.document.name); // Output: John
即使我们更新了标记的名称，游戏世界中的名字仍然是 John，因为数据不会立即更新。
等待更新完成后再记录名称，我们会得到正确的输出：
await token.document.update({ name: "Jane" });
console.log(token.document.name); // Output: Jane
await关键字用于等待更新完成后再继续运行代码。
请记住，任何与游戏世界数据库交互的动作都是异步的，所以如果你需要与更新后的数据交互，就需要用 await 来等待作完成。
示例：更改指示物的图像
比如说，我们想改变一个指示物的形象，比如它是一个变形者。
token.document.update({ "texture.src": "my/new/image.webp" });
这会为所有用户改变所选标记在游戏世界中的图像。

高级：IF 语句
假设我们想让宏基于当前图片在两张图片之间切换。我们可以利用目前学到的内容和 IF 语句来实现这一点。
const currentImage = token.document.texture.src;
const humanForm = "assets/images/human.webp";
const shapeshifterForm = "assets/images/shapeshifter.webp";
if (currentImage === humanForm) {
token.document.update({ "texture.src": shapeshifterForm });
} else {
token.document.update({ "texture.src": humanForm });
}
这会根据当前图像改变所选标记的图像。
JavaScript 中的 IF 语句
（译者注：可以参考菜鸟教程-JavaScript条件语句）
在 JavaScript 中，IF 语句用于执行代码块如果IF条件为真。IF 语句的基本语法如下：
if (condition) {  // code to execute if the condition is true}
以下是 JavaScript 中 IF 语句的一个示例：
let age = 25;
if (age >= 18) {
console.log("You are an adult");
}
如果IF条件为假，else 关键字可用于执行另一个代码块：
let age = 15;
if (age >= 18) {
console.log("You are an adult");
} else {
console.log("You are a minor");
}

掌握了如何在 Foundry VTT 中与文档交互后，你现在可以有效地将它们整合进宏中。虽然宏通常直接调用token和actor对象，但了解如何访问其他文档则会开启更多可能性。

ID 和 UUID
在 Foundry VTT 中，文档通过其 ID 和 UUID 进行区分。
IDs
ID 是文档中特定的唯一标识符。然而，大多数 ID 需要上下文信息，通常是其容器。
UUIDs
UUID 作为文档的通用标识符，由 Foundry VTT 自动生成。他们使得文档可以在游戏世界中无关上下文或容器地被识别。
ID 对比 UUID：一个实用示例
请考虑我们上一篇文章中的token。
console.log(token.document.id); // Output: 'ieHxQxCWYVtY07oi' (这个ID基于你的token是独一无二的)
console.log(token.document.uuid); // Output: 'Scene.xcKEdiLWe09s5Pfl.Token.ieHxQxCWYVtY07oi' 同上
在这里，这个指示物在其场景中被ID唯一标识。与此同时，UUID 不仅包含指示物的 ID（ieHxQxCWYVtY07oi），还包含它所属的场景（xcKEdiLWe09s5Pfl）。一般来说，使用 UUID 更可靠。

查找文档的 ID 或 UUID
要获取文档的 ID 或 UUID（除控制台日志外），请在 FVTT 界面中执行以下步骤：

打开文档表（例如，指示物配置、角色卡或场景配置）。

在左上角，找到书籍图标。

左键点击复制ID;右键点击复制 UUID。

通过 ID 或 UUID 访问文档
现在你掌握了 ID 或 UUID 知识，可以在宏里面利用他们来访问文档。
在宏中通过 UUID 访问文档
const tokenUUID = "Scene.xcKEdiLWe09s5Pfl.Token.ieHxQxCWYVtY07oi";
const tokenDocument = fromUuidSync(tokenUUID);
console.log(tokenDocument);
当文档存在于合集包中时，数据检索需要访问数据库，因此需要await数据检索，正如update方法所述。
const tokenUUID = "Scene.xcKEdiLWe09s5Pfl.Token.ieHxQxCWYVtY07oi";
const tokenDocument = await fromUuid(tokenUUID);
console.log(tokenDocument);
注意，无论文档是否属于汇编，使用fromUuid进行文档检索 ，都需要await。
（译者注：fromUUID会去获取服务器的数据，是一个异步函数；fromUUIDsync则只会加载已经在内存中的内容，如果不介意速度，最好都用前者，不会出错）
通过 ID 访问文档
通过 ID 访问文档更为复杂，因为需要知道文档在游戏世界中的位置。在这种情况下，采用 get 方法。
const tokenID = "ieHxQxCWYVtY07oi";// 假设相关token已经在当前场景中
const tokenDocument = canvas.scene.tokens.get(tokenID);
console.log(tokenDocument);
例如，通过 ID 访问 某个日志 的 某个页 需要先知道 对应日志 的 ID。
const pageID = "jKgK9K9gK9gK9K9g";
const journalID = "f3qwfqwfqwfqwfqw";
const journalDocument = game.journal.get(journalID);
const pageDocument = journalDocument.pages.get(pageID);
console.log(pageDocument);

JavaScript 数组、数组方法和循环
（译者注：可以参考菜鸟教程-JavaScript-数组）
在 JavaScript 中，数组是存储在单个变量中的值的集合。数组用于在单个变量中存储多个值，可以通过索引访问或循环遍历。它们可以通过方括号 [] 来区分。
示例：
const myArray = [1, 2, 3, 4, 5];
console.log(myArray[0]); // Output: 1
console.log(myArray[2]); // Output: 3
console.log(myArray.length); // Output: 5
您可以使用 push 方法向数组添加值。
示例：
const myArray = [1, 2, 3, 4, 5];
myArray.push(6);
console.log(myArray); // Output: [1, 2, 3, 4, 5, 6]

查找所有具有特定名称的文档
正如我们在前面的示例中所见，您可以使用 getName 方法来按名称查找文档。但是，如果您有多个同名的文档， getName 方法将返回第一个具有该名称的文档。

如上例所示，我们使用 await 关键字等待更新完成后再处理下一个文档。虽然在本例中每个更新彼此独立，无需如此操作，但在处理异步代码时，使用 await 仍是良好的编程习惯。

高级：批量更新
如果您需要处理大量文档，可以通过批量更新来提升性能。在大多数使用场景中，这并非特别必要，可能只是为了优化而优化。但处理多个文档时，采用批量更新仍是良好的实践。
需要注意的是，批量更新只能在相同的 Collection 内进行。例如，您无法同时批量更新指示物和物品，也无法通过单次更新修改所有场景中的所有指示物。

在 Foundry 中，集合是一种包含一组文档的数据结构。诸如 game.actors 、 game.items 、 game.scenes 和 game.journals 等都属于集合。您可以在 game.collections 中找到它们的完整列表。
虽然像 Actor 这样的对象本身不是集合，但它们是可以将其他文档作为集合嵌入其中的文档。例如， Actor.items就是属于该角色的物品集合。

sort 排序
在 JavaScript 中，你可以使用 sort 方法对数组进行排序。 sort 方法接受一个回调函数（译者注：这里的回调函数可以参考菜鸟教程-JavaScript-函数，其实就是作为参数的函数）作为参数，该函数会为数组中的每个元素调用。排序方法的每次迭代都会比较当前元素与下一个元素，并返回一个数字，指示这两个元素的顺序。（译者注：和很多语言不一样，js Array.sort只接受数字返回，而不是布尔返回）
const results = [3, 1, 2, 4, 5, 6];

results.sort((a, b) => b - a); // 降序排序
console.log(results); // Output: [6, 5, 4, 3, 2, 1] (example output)
让我们来看一个扩展版本的排序方法，以便更清晰地理解。
const results = [3, 1, 2, 4, 5, 6];

results.sort((a, b) => {
if (a > b) {
return 1;
} else if (a < b) {
return -1;
} else {
return 0;
}
});
console.log(results); // Output: [6, 5, 4, 3, 2, 1] (example output)
这段代码实现了与之前完全相同的结果，但更具可读性且更易于理解。

如果返回一个负数， a 将被放置在 b 之前。

如果返回一个正数， b 将被放置在 a 之前。

如果返回 0 ，则位置不变。

Slice 切片
slice 方法用于提取数组的一部分。它接受两个参数：起始索引和结束索引。起始索引包含在内，而结束索引不包含在内。（译者注：如果只有一个参数，则结束索引默认为末尾）
const results = [3, 1, 2, 4, 5, 6];

const firstFourResults = results.slice(0, 4); // 获取前四个结果
console.log(firstFourResults); // Output: [3, 1, 2, 4] (example output)
const results = [3, 1, 2, 4, 5, 6];

const lastTwoResults = results.slice(-2); // 获取最后两个结果
console.log(lastTwoResults); // Output: [5, 6] (example output)
这与以下相同：
const results = [3, 1, 2, 4, 5, 6];

const secondToLastResult = results.slice(4, 6); // 获取最后两个结果
console.log(secondToLastResult); // Output: [5, 6] (example output)

JavaScript：相等运算符
（译者注：可以参考菜鸟教程-JavaScript-比较和逻辑运算符）
我们已在之前的文章中了解了一些相等运算符，现在让我们更深入地探讨一下。
严格相等与宽松相等
到目前为止，我们一直在使用严格相等运算符 === 。该运算符会检查两个值是否在值和类型上都相同。通常建议始终使用严格相等运算符，但我们将探讨宽松相等运算符的工作原理，以防你在其他资源中遇到它。
console.log(1 === 1); // true
console.log(1 == 1); // true
在这个例子中，两个运算符之间没有区别。
console.log(1 === "1"); // false
console.log(1 == "1"); // true
请注意，严格相等运算符在这里返回 false，而宽松相等运算符返回 true。这是因为虽然两个值都是 1 ，但它们不是同一类型。一个是数字，另一个是字符串。
另一个例子：
console.log(1 === 1.0); // true
console.log(1 == "1.0"); // false
在这个例子中，严格相等运算符返回 true，但宽松相等运算符返回 false。这是因为值 1.0 是一个数字，而字符串 "1.0" 是一个字符串。
宽松相等运算符会在比较之前将值强制转换为字符串。因此，虽然在严格相等中两个数字相同，但宽松相等实际上会检查 "1" == "1.0" ，这将返回 false。
（译者注：因此不建议在js中使用==，建议全用===，同理，下面的NOT运算符最好也用!==而不是!=）
NOT 运算符
如果你想检查两个值是否不相同，可以使用 NOT 运算符 !== 。如果值不相同，该运算符将返回 true；如果值相同，则返回 false。
与相等运算符类似，NOT 运算符也可以进行严格或宽松的比较。
console.log(1 !== 1); // false
console.log(1 != 1); // false
console.log(1 !== "1"); // true
console.log(1 != "1"); // false
console.log(1 !== 1.0); // false
console.log(1 != "1.0"); // true

从函数中返回一个值

控制区域触发次数
在前面的示例中，当进入区域时，伤害会施加到角色身上。这是区域的一个很好的用途，但大多数时候，你可能希望只运行一次陷阱行为或其他行为。
方法一：禁用行为
被触发的行为在区域脚本中作为一个变量behavior可以被使用，你可以通过将 behavior.disabled 属性设置为 true 来禁用该行为。这将防止在进入区域时运行该行为。
const { data, name, region, user } = event;
const token = data.token;

// 我们确保用户是GM，因为玩家无法禁用behavior
if (game.users.activeGM === user) {
// 被触发的行为在区域脚本中作为一个变量可用，就像'event'一样。
behavior.update({ disabled: true });
}

// 在这里我们可以决定这个特定脚本是像之前示例中那样以GM还是玩家形式运行
if (user !== game.user) return;

// 举个例子，给角色治疗10点生命值
token.actor.applyDamage([{ value: 10, type: "healing" }]);
从此刻起，该行为已被禁用，未来进入区域时也不会再运行。
方法二：存储永久计数器
有时你可能希望某个行为运行特定次数，例如一个只能使用前三次的治疗喷泉。在这种情况下，我们可以在行为中存储一个计数器。
const { data, name, region, user } = event;
const token = data.token;
const MAX_USES = 3;

// 首先我们检查当前的使用情况
const uses = behavior.getFlag("core", "uses") || 0; // 如果标志未被设置，||语法用于设置默认值

// 如果使用次数超过最大值，我们就退出脚本
if (uses >= MAX_USES) return;

// 我们确保用户是GM，因为玩家无法对行为进行更新
if (game.users.activeGM === user) {
behavior.setFlag("core", "uses", uses + 1);
}

if (user !== game.user) return;

// 举个例子，给角色治疗10点生命值
token.actor.applyDamage([{ value: 10, type: "healing" }]);

在正式开始学习之前，确立对以下事实的认知是必要的：
如何获取文档数据
FVTT中几乎所有能被持久性保存——即不会随着页面刷新而消失——的数据，都派生自同一个类：Document，即文档。在一场游戏中，你的人物背后的数据就是一个Document，其内包含着它的名称、指示物图片链接等信息；人物所持用的武器也被存储为Document，其内包含着物品名、物品图片链接等信息……有关Document的更多信息将在后面介绍。
让我们看看如何获取文档数据。FVTT为此提供了许多方法，但最为简单的还是fromUuidSync全局函数。这个函数接受一个存储了文档Uuid的字符串作为参数，并将Uuid对应的文档返回。如：
const actor = fromUuidSync('Actor.114514itjustwork');
//获得对应Uuid的角色数据。类型为Actor，Document的一种派生类。
//其它类似的Document派生类有Item、ChatMessage……
一般而言，你总是能够通过对应文档的卡模板来获取其Uuid。

文档的修改
当你在FVTT中访问数据时，你实际上是将存储于服务器端数据库的对应数据拷贝至本地。也就是说，每个人所访问的数据实际上是相互独立的。
要想同步且根本地修改数据，必须通过某种方法将修改写入服务器端的数据库中。为满足这一需求，FVTT为文档实现了update方法。它接受一个对象作为参数，通过对照参数和文档内的值键对来进行数据的修改。一次对update方法的调用应该如下：
const newValue = {
"name":"paper1",
"power":{
"value":1,
"max":10
}
};
actor.update(newValue);
//若newValue中含有文档定义中不具备的数据，则对应值不会被写入。
//如：若actor.power.value并不存在，调用后，actor.name和actor.power.max会被正常修改，actor.power.value依旧不存在。
//即使是你手动给actor附上此字段，update依旧不会修改此值。
//也就是说：update只修改文档定义中具备的数据，无视文档定义中不具备的数据。

事件监听
若你体验过JS编程，那么浏览器的事件监听必然是不可绕过的话题。一般的，我们可以通过以下语句来创建一个事件监听器：
DOMElement.addEventListener(event_name,handle);
在FVTT中，还有一种和这个同样常用的事件监听机制：Hooks。它的语法和addEventListener类似：
function sayHello(){
console.log("HelloWorld");
}

Hooks.on('Hello',sayHello);//接收到Hello事件后，调用sayHello

Hooks.call('Hello');//发送一个Hello事件
对于系统编程，我们必须额外注意FVTT自动发送的这个Hook事件：init。这个Hook事件会在FVTT初始化时发出，一些系统初始化的工作只能在此刻完成。

通常的，一个游戏系统存储在 FVTT用户数据路径/Data/systems 中。观察其中已经存在的游戏系统实例，你会发现，系统的文件目录结构大致如下：

├─templates/
│ └─characterSheet.hbs
└─......
在这繁多的文件中，只有一个是必须提供给FVTT的：system.json。一个没有system.json文件的系统不会被FVTT读取。
system.json必须被放置在系统的顶层目录。它通常会包括这个系统的规范化描述：名称，id，作者，认证版本号……
让我们观察一个可能的system.json实例：
{
"id":"helloworld",
"title":"你好世界！",
"description":"一个简单的自建系统。",
"version":"0.0.1",
"compatibility":{
"verified":13
},
"authors":[{
"name":"paper1"
}],
"documentTypes":{
"Actor":{
"character":{}
},
"Item":{
"weapon":{}
}
}
}
其中，三个字段尤其值得注意：

id代表此系统的唯一标识符。它应当同系统所在的文件夹名称相同，且由小写字母组成。

title代表此系统展示给用户的，人类可读标题。

FVTT规定，一个system.json必须具有上述两个字段。

documentTypes声明了对应文档的子类型。对于Actor文档——即我们平日使用的角色所对应的文档，我们为它声明了一个叫做character的子类型；对于Item文档——即我们平日使用的物品所对应的文档，我们为它声明了一个叫做Item的子类型。

若一个文档不具备可用的子类型，那么它是无法被正常创建的。好在，FVTT默认地为除人物和物品以外的文档都创建了对应的类型，因此我们只需要对这二者进行类型声明。
将这个系统放置到 FVTT用户数据路径/Data/systems 中，然后重启你的FVTT。此时，你应当已经可以看到FVTT载入了这个系统，并且能够用它来正常创建世界了。
进入世界后，你应该会发现在创建角色或物品时，可以选用自己声明的类型来创建。
这个系统尤为重要，此后若无特殊提及，则我们默认都是在基于这个系统进行讨论和开发。

如果你安装了子mod，此处是预设完整的，不需要变动，除非你想更改其中一些东西（你知道你在做什么）。

四、创建物品堆
当你第一次把一个物品拖到场景中时，模块会在你的侧边栏创建角色

不要删，它是你放置在地图上所有物品堆的共同原始角色，以及创建出物品堆的默认形式。
每次迁移世界都会重新生成一次，因此有时会有多个该角色，如果你不是强迫症建议用文件夹装起来。
如果你向已有的物品堆上拖拽物品，系统会提示你是否要将其加入该堆。
拖拽物品前按住左 Alt 键会绕过对话框，将该物品添加到物品堆中。
你也可以打开物品堆，将物品拖放到界面中。
另外，已经配置好的随机表也可以，将【已配置好每条随机项目内物品】的随机表拖入已有的物品堆，就会掷一次随机表并把那件物品加入，金库除外，因为金库采用了网格式储存，和物品堆/商人/宝箱不一样。
最后，你也可以为任意一个NPC配置物品堆，并将其设置为某种类型，以实现手动战利品/商人/银行 的功能。
五、查看物品堆
1、作为PC
如果你是玩家，可以通过双击物品堆来查看。你需要在物品堆旁边放一个token才能检查，除非物品堆配置的互动距离较远（参见arms reach）。
2、作为NPC
如果你是GM，你可以同时框选目标NPC和物品堆然后双击物品堆，此时你就作为该NPC在查看了。

最后，点击拿走即可拿走物品，点击“在X人间平分”可将货币尽可能平均地分配给每个有代表角色的PC账号的默认角色。
六、各类物品堆子类型
物品堆有4种类型，分别是：
物品堆
容器
商人
金库
现在我们从物品堆开始讲起。
1、物品堆

这是最简单，最没功能的普通物品堆，不能上锁，只能放拿东西。
注意：DM要放东西一定要点击配置更新！否则不会将你的新物品实际放入。
对每个物品堆，DM都可以点击设置物品堆来更改其默认属性。

主要设置不重要，除了你有需求，在此设置打开物品堆触发宏。

其它设置中，默认情况即可。除了第一个类型，此处将会改变其类型以适应不同需求。
2、容器
首先在主要设置中，勾选启用，再在其它设置中将类型切换为“容器”。
容器和物品堆的唯一区别就是容器可以上锁，同时它可以对各种状态下的容器图标进行更改。

当你设置关闭和锁定后，容器类型的物品堆会在其右键菜单上出现两个新图标，可以快捷切换关闭和锁定状态。
锁定状态下，无法查看物品堆内容。
关闭状态下，没有任何区别，双击照样查看，也可以拿走，只是多了一个“点击关闭”的UI。
3、金库
首先在主要设置中，勾选启用，再在其它设置中将类型切换为“金库”。

这是一个金库的页面。可以看到金库同其它类型的物品堆不同，是网格状存储。右键点击物品可以选择查看、取走或拆分。你也可以使用金库授权功能配合一些开锁mod（如puzzle lock）实现抢劫银行金库的感觉。

如果在金库设置处开启日志，那么会多一栏记录，在此处可以看到存入和取出的记录，DM如果不给自己分配角色，那么会显示unknown character。

如果你想要使用“购买背包以扩大使用面积”的房规，那么自建一个任意物理物品，然后在其item piles设置里勾选金库扩展器，即可在金库开启金库扩展模式时，存入此物品，将金库的格子大小变多。

你也可以用大量的时间为每一件物品配置其在金库中占据的网格大小来实现物品管理。
注意：将容器（物品）放入金库时，会使容器内的每件物品都在金库中显示并占据一个格子，不过实际上仍然在容器内。而物品堆/容器（类型）则不会有此问题，因为金库的网格存储是独特的。
4、商人

首先在主要设置中，勾选启用，再在其它设置中将类型切换为“商人”。
此时，你将看到NPC的面板产生了变化，成为了商店的形式。它默认将NPC身上所有你设置排除的东西以外的物品全部加入商店，并且由于NPC身上的武器都是另外创建的，没有价格所以是免费，因此记得把商人身上的东西都删了再填充。

对每个物品而言，左侧点击数量可以更改其存量，齿轮可以单个配置该物品，眼睛可以隐藏该物品，商店图标可以将其设置为非卖品（可以看到，但不能买）。

物品的单独设置不是必须在商人身上设置好，这只是一个快速打开物品的物品堆设置菜单的功能，可以在外面做好了放进来。

价格设置处，你可以为该物品配置它在出售或购入时需要的成本，此处就可以使用之前的预设价格或次级货币了，设置完成后，在商人界面该物品价格处将会出现一个角标，点击角标可以切换其使用的价格。
但目前我认为有bug，无法切换，也无法使用次要价格。

商人左下角可以编辑描述，以及它的一些常用的快速设置，包括购买选项，倍数等等。

主要设置部分，如果你想模拟真实商人，那么取消勾选无限货币和无限数量，并给商人一定的资金，这可以限制PC无限出售物品。
基准价格指的是物品价格设置中你对该物品单独设置的额外成本/额外购买方式，但实际测试我并没有发现取消勾选后有什么区别。

你也可以为商人调整出售价格和针对某个人的价格，但最多只能200%，模组中的5倍10倍奸商只能通过调整物品基础价格再加上倍数来实现。

八、战利品联动功能
使用此功能需要通过monk's tokenbar实现。

在monk's tokenbar的战利品设置中，我们首先要将“将敌人转换为战利品”改为item piles，然后勾选“显示战利品菜单”和“仅限被击败”（此处选开）。如果想自动转换金币，还要勾选战后设置中的根据CR自动转换金币。

在战利品实体选项中，有3种方法：
1、Convert tokens可以将每个敌人战后都直接变成物品堆，优点：快速，缺点：敌人一多东西分散。

2、Create entry here可以在日志页面创建本次战斗获得的战利品，优点：统一，缺点：日志用的次数不多，不一定能想起来看。
3、创建一个“战利品”NPC，将其item piles设置为物品堆。之后，在战利品实体处选择该NPC。个人认为这是最优方法。此时，需要勾选“创建画布对象”以在战后创建战利品，“打开战利品实体”选开。

结束遭遇时，你将会看到这样的面板。
