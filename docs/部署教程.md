# 从零部署教程：让 DSH 的 AI 操控你的 Foundry VTT

> 本教程假设你**现在什么都没有**：一台 Windows 电脑，装好了 DSH，云端/服务器上跑着一个 FVTT V13 世界（dnd5e 系统）。照着做，大约 30 分钟跑通。

**跑通后你能干什么**：开一个 DSH 新对话，说人话——「在激活地图上放一只僵尸」「给这个怪加个啃咬，命中后 DC11 体质豁免，失败中毒」「掷 1d20+5」「把这场遭遇的先攻全掷了」——AI 自己挑工具、查世界包、动手操作、回报结果。

---

## 第 0 步：下载（先弄明白要下什么）

去 GitHub Release 页：

```
https://github.com/Ryuka16/dsh-foundry-vtt/releases/latest
```

页面上会看到几个文件，别懵，就两种：

| 文件 | 是什么 | 什么时候用 |
|---|---|---|
| `dsh-foundry-vtt-全家桶.zip` | **完整安装包**：relay 源码 + DSH 插件 + 本教程 + 示例配置，解压即用 | **从零开始就下这个（推荐）** |
| `dsh-foundry-vtt-plugin-v*.zip` | 只有 DSH 插件（不含 relay） | 你已经有 relay 了，只想更新插件时用 |
| `Source code (zip)` / `(tar.gz)` | GitHub 自动打包的**仓库源码快照** | 内容=全家桶 zip 几乎一样，但它不含「我配好的相对路径脚本」以外的差别；clone 仓库的人用它 |

> 另：懂 git 的话直接 `git clone https://github.com/Ryuka16/dsh-foundry-vtt.git`，效果等于全家桶 zip。

**本教程按「下了全家桶 zip，解压到比如 `D:\dsh-foundry-vtt\`」往下写。** 解压后你会看到：

```
dsh-foundry-vtt\
├─ plugin\          ← 第 5 步要装进 DSH 的东西

│  ├─ start-relay.bat   ← Windows 双击启动脚本（推荐）
│  └─ start-relay.ps1   ← PowerShell 启动脚本模板
├─ mcp-server\      ← 可选，接标准 MCP client 才用，新手忽略
├─ docs\部署教程.md  ← 就是本文
└─ config.example.json ← 第 6 步照着抄
```

## 第 1 步：桌机启动 relay（Windows 免编译）

relay 是跑在你电脑上的「桥」：云端 FVTT 的模块通过浏览器连它，DSH 插件通过它操控世界。

### 1.1 改启动脚本

用**记事本**打开 `D:\dsh-foundry-vtt\relay\start-relay.bat`（PowerShell 用户开 `start-relay.ps1`，一样的内容），改两处：

1. `ADMIN_EMAIL='you@example.com'` → 改成你的邮箱（随便编一个也行，这是你登录 relay 管理后台的账号）
2. `ADMIN_PASSWORD='CHANGE_ME'` → 改成强密码（这是管理密码，丢了只能删 data 目录重来）

其余不用动（脚本里的速率限制 100000 是必须的，别改小）。

### 1.2 启动

**双击 `start-relay.bat`**（黑窗口跑起来别关）。看到类似日志不报错就说明起来了。

**另开一个 PowerShell** 验证：

```powershell
Invoke-RestMethod http://localhost:3010/api/health
```

返回 `ok` 就是成功了。**这个窗口要一直开着**（relay 是常驻程序）。以后每次开机都要跑一次这个脚本（第 8 步讲怎么开机自启）。

---

## 第 2 步：云端 FVTT 装模块

模块（foundry-rest-api）是装在 FVTT 服务器上的插件，负责把世界数据翻译成 API。

1. 浏览器登录你的 FVTT（GM 账号）→ **游戏设置（Game Settings）→ 管理模块（Manage Modules）→ 安装模块（Install Module）**。
2. 底部 Manifest URL 输入框粘贴：

   ```
   https://github.com/ThreeHats/foundryvtt-rest-api/releases/latest/download/module.json
   ```

3. 装好后在模块列表里**启用**它（模块 id：`foundry-rest-api`），保存。
4. 刷新页面。之后模块设置里会出现 **REST API Connection → Manage Connection** 菜单按钮（第 3 步用）。

> ⚠️ **最重要的一条规则**：这个模块的实时通道由**你浏览器里开着的 FVTT 页面**发起。也就是说——**GM 浏览器必须开着那个 FVTT 世界页面**，AI 才操控得到。浏览器关了 = 世界离线，AI 会报 `No Foundry world is connected`。这是设计使然（云端服务器零公网暴露、不用开任何端口、不用安全组改动）。

## 第 3 步：模块配对（Enter Code 流程）

配对 = 让模块和 relay 互相认识。**不要用模块里的「浏览器配对」按钮**（它依赖的批准页我们没构建，会 404），用 **Enter Code**。

### 3.1 在 PowerShell 里走 4 个命令

```powershell
# ① 管理员登录 relay，拿 sessionToken
$login = Invoke-RestMethod -Method POST http://localhost:3010/auth/login -ContentType 'application/json' `
  -Body '{"email":"你的邮箱","password":"你的密码"}'
$token = $login.sessionToken

# ② 发起配对请求
$pair = Invoke-RestMethod -Method POST http://localhost:3010/auth/pair-request -ContentType 'application/json' `
  -Body '{"worldId":"你的世界id","worldTitle":"你的世界名","systemId":"dnd5e","systemVersion":"5.3.3","foundryVersion":"13.351","serverFingerprint":"my-pc"}'
$code = $pair.code   # 8 位

# ③ 管理员批准
Invoke-RestMethod -Method POST "http://localhost:3010/auth/pair-request/$code/approve" `
  -ContentType 'application/json' -Headers @{Authorization="Bearer $token"} `
  -Body '{"remoteScopes":["*"],"allowedTargetClients":[],"remoteRequestsPerHour":10000}'

# ④ 拿 6 位配对码（5 分钟内有效）
Invoke-RestMethod "http://localhost:3010/auth/pair-request/$code/status"
# 返回里有 "pairingCode":"XXXXXX" ← 记下这 6 位
```

**你的世界 id / 世界名怎么查**：FVTT 登录后的世界页面，地址栏 URL 形如 `http://你的服务器:30000/worlds/<世界id>`，`<世界id>` 就是 worldId；世界列表里显示的名字就是 worldTitle。`systemVersion` 在 FVTT 里 设置→系统 能看到（dnd5e 的版本号）。

### 3.2 模块里输码

回到 FVTT 页面：**模块设置 → REST API Connection → Manage Connection**：

1. 先点 **Edit URL**，确认填的是 `ws://localhost:3010`（必须 ws:// 开头）。
2. 点 **Enter Code**，输入第 ④ 步拿到的 6 位码。

成功后 relay 窗口日志会出现：

```
Pairing completed clientId=fvtt_xxxx... worldId=你的世界id
Client connected clientId=fvtt_xxxx... foundryVersion=13.351 systemId=dnd5e
```

**记下这个 `clientId`（fvtt_ 开头的那串）**——普通用法用不到它（全局 key 自动路由），只有进阶锁世界时（第 4 步的 `scopedClientIds`、第 6 步固定 `clientId`）才需要。

> 没看到日志？检查：relay 窗口开着吗？模块的 Relay URL 是 `ws://localhost:3010` 吗（https 或漏 ws:// 都不行）？FVTT 世界页面开着吗？还是不行就把 relay 日志发出来。

### 3.3 换世界 / 开了新世界：重新配对

**配对是按世界的**：每个世界 id 单独配一次。开了新世界、或切到一个没配过对的世界，模块就会提示要重新连接——这不是坏了，重跑一遍配对就行。配过一次的世界永远有效（记录在 `relay\data\relay.db`）。

1. 查新世界 id：进入新世界后，地址栏 URL 形如 `http://你的服务器:30000/worlds/<世界id>`。
2. 把上面 **3.1 的 ①~④ 四条命令重跑一遍**，`worldId` / `worldTitle` 换成新世界的，拿到新的 6 位码。
3. 在新世界的 FVTT 页面里 **Manage Connection → Enter Code** 输入新码。

**配完之后什么都不用改**（v1.1.5 起）：插件用全局 API key，调用时不带 clientId，relay 自动路由到「当前唯一在线」的世界——你浏览器开着哪个世界页，AI 就操作哪个世界。有几十个世界也随便切。

> 唯一注意：一次只开一个世界页。多个世界同时在线时 relay 会报 `Multiple clients connected`，关掉多余的世界页面即可。

> 切回之前配过对的世界**不用重新配**，relay 记得它。配对记录存在 `relay\data\relay.db` 里——这也是为什么备份这个文件很重要（见第 8 步）。

---

### 3.4 让 AI 自己出配对码（推荐，不用手打上面四条命令）

插件装好、且 `config.json` 里填了 `relayAdminEmail` / `relayAdminPassword` 之后，
直接在新对话里说一句 **「给我配对码」**，AI 会调 `foundry_mint_pairing_code` 自动走完
①登录 → ②发起配对请求 → ③批准 → ④取码 四步，把 6 位码给你。你只要在模块里点「Enter Code」输入即可。

> 前提：`relayAdminEmail` / `relayAdminPassword` 必须与 relay 启动时的 `ADMIN_EMAIL` / `ADMIN_PASSWORD` 一致。
> 没装插件或不想用工具时，回到 3.1 手打四条命令也行（完全等价）。

## 第 4 步：创建 API key

API key 是 DSH 插件调用 relay 的通行证（64 位十六进制串）。**推荐建全局 key（不传 `scopedClientIds`）：一个 key 通吃所有世界，配合自动路由，换世界零配置。**

```powershell
$body = @{
  name = 'mcp-control'
  scopes = @(
    'entity:read','entity:write','roll:read','roll:execute','chat:read','chat:write',
    'encounter:read','encounter:manage','macro:list','macro:execute','macro:write',
    'scene:read','scene:write','canvas:read','canvas:write','effects:read','effects:write',
    'user:read','user:write','file:read','file:write','playlist:control','world:info',
    'clients:read','sheet:read','events:subscribe','session:manage','execute-js',
    'search','structure:read','structure:write','dnd5e'
  )
} | ConvertTo-Json -Depth 4
Invoke-RestMethod -Method POST http://localhost:3010/auth/api-keys `
  -ContentType 'application/json' -Headers @{Authorization="Bearer $token"} -Body $body
# 返回里的 key 字段（64 位十六进制）就是 API key ← 记下
```

> 进阶：想锁死只能操作某几个世界，给上面 body 加 `scopedClientIds = @('fvtt_xxxx', 'fvtt_yyyy')`（第 3 步记下的 clientId 串）。普通用户不用加。

> 小知识：数据 API 只认 scoped API key（走 `x-api-key` 头）。管理员 sessionToken 直接打数据端点会 401，这是正常的安全设计，不是坏了。

## 第 5 步：把插件装进 DSH

现在把 `plugin\` 目录装进 DSH，新对话的 AI 才能看到 88 个工具。

### 方式 A：用 dsh-super-injector（如果你 DSH 里已装了这个注入器插件）

在 DSH 里对 AI 说：

```
dev_install_package dir=D:\dsh-foundry-vtt\plugin
```

它会自动改 profile 配置、建链接、热装配生效；重启 DSH 后依然在（持久）。

### 方式 B：手动装配（3 个小动作）

1. 用记事本打开 `C:\Users\你的用户名\.dsh\profiles\web\package.json`（`.dsh` 是隐藏文件夹，资源管理器地址栏直接输入路径就能进）：
   - `dependencies` 里加一行：`"@dsh-external/dsh-foundry-vtt": "link:D:/dsh-foundry-vtt/plugin"`（**注意：路径分隔符用正斜杠 `/`，或者反斜杠写成 `\\`**）
   - `dsh.profile.bundles` 数组里加一项：`"@dsh-external/dsh-foundry-vtt"`
2. 建链接（PowerShell 执行，路径按你的实际改）：

   ```powershell
   cmd /c mklink /J "C:\Users\你的用户名\.dsh\profiles\web\node_modules\@dsh-external\dsh-foundry-vtt" "D:\dsh-foundry-vtt\plugin"
   ```

3. 完全退出并重启 DSH。

> 插件已带编译产物 `lib/index.js`，**不用 build**。只有你改了 `src/` 源码才需要 node 重编译（教程末尾附录）。

## 第 6 步：写 config.json

1. 在资源管理器地址栏输入 `C:\Users\你的用户名\.dsh\` 回车。
2. 新建文件夹，命名 `dsh-foundry-vtt`。
3. 进去后新建文本文件，改名为 `config.json`（注意扩展名是 .json 不是 .txt）。
4. 用记事本打开，内容照着 `config.example.json` 抄，最少填两项即可：

```json
{
  "relayUrl": "http://localhost:3010",
  "apiKey": "第4步拿到的64位key",
  "clientId": ""
}
```

> `clientId` 留空 = 自动路由（推荐）：relay 自动把请求发到当前唯一在线的世界。想固定只操作某个世界时才填第 3 步记下的 fvtt_xxxx。

5. 保存（Windows 11 记事本默认 UTF-8 无 BOM，直接保存即可）。

> 这个配置在用户主目录，和插件目录分开——所以重装 DSH、挪插件目录都不丢配置。

## 第 8 步：日常运维

### 让 relay 自动上班（推荐：随 DSH 自动启动）

在 `config.json` 里填上 `relayExePath`（relay.exe 的绝对路径，见 config.example.json 最后四行）——**以后每次打开 DSH，插件会先探一下 relay：没在跑就静默拉起，在跑就跳过**。不用管开机自启、不用记着双击，开 DSH 即用。

### 手动开关 relay（可选）

`relay\start-relay.bat` 双击启动（黑窗口别关）；已配置自动启动后一般用不上，仅排查问题时用。想看到底在没在跑：任务管理器搜 `relay.exe`。

### 其它运维要点

- **GM 浏览器要开着 FVTT 世界页**：这是「世界在线」的前提，睡前关机前记得这个。
- **备份命根子**：`relay\data\relay.db`——配对关系、API key 全在里面。定期拷一份走。
- **重装 DSH**：只要不删 `C:\Users\你\.dsh`，插件装配和 config.json 都在；开 DSH 时 relay 会自动拉起。
- **换电脑**：拷三样——relay 目录（含 data 和 relay.exe）、plugin 目录、`.dsh\dsh-foundry-vtt\config.json`；新电脑重做第 5 步装配即可。

## 排障：408「世界显示在线，但请求全超时」（最坑的一个）

**现象**：`foundry_list_worlds` 显示 `online: true`，`/clients` 也返回 200，但任何数据操作都报
`relay 返回 HTTP 408：{"error":"Request timed out"}`。

**根因**：relay 与 FVTT 模块之间的 WebSocket 连接僵死了——relay 侧仍登记着客户端（所以显示「在线」），
但模块进程已经不再回包。**「在线」是假象。**

**处理（实测有效，30 秒）**：
1. 结束 `relay.exe` 进程；
2. 重新启动 relay（配了 `relayExePath` 的话，重启 DSH 会自动拉起；也可双击 relay 目录的 `start-relay.bat`）；
3. 在 FVTT 页面按 F5 刷新一次（模块会重连）；
4. 重试原操作。

**不要做的事**（都是实测踩过的坑）：
- ❌ 逐文件去读 relay 的 Go 源码找根因 —— 实测为此耗掉近一小时，最后结论就是「重启 relay」；
- ❌ 反复重试同一个请求；
- ❌ 以为世界没开、跑去 FVTT 里翻设置。

> 插件 v1.1.6 起内置自诊断：遇到 408 会在错误信息里直接给出上面这段结论和处理办法。
> AI 也可以随时读内置手册：`foundry_knowledge topic:"deploy"`（架构 / 安装四步 / 配对流程 / 故障速查表 / 配置字段）。

## 常见坑大全

| 现象 | 原因 | 处理 |
|---|---|---|
| 批准页 `/pair/{code}` 404 | relay 前端 SPA 未构建（go-relay 纯后端） | 用 Enter Code 流程（第 3 步），别用浏览器配对 |
| 配对 429 限流 | 默认速率限制太小 | start-relay.ps1 模板已调到 100000，别改小 |
| `No Foundry world is connected` | GM 浏览器关了 FVTT 页面 | 重新打开世界页 |
| `execute-js is disabled in REST API module settings` | 模块设置里 execute-js 默认禁用 | 改物品自动化直接用 `foundry_update_entity` 的内嵌 uuid（`Actor.<id>.Item.<id>`），不用 execute_js |
| update/add_effect 偶发「does not exist」但实际生效 | 模块端回读间歇误报 | 工具内置回读确认，返回 `verified:true` 即已生效 |
| 新建怪的武器没伤害 | dnd5e 5.3.x 丢弃旧版 `parts[].formula` | 伤害骰必须放 `item.system.damage.base{number,denomination,bonus,types}`；AI 工具描述已内置此警告 |
| AI 把怪「新建」而不是从世界包拿 | 新建会丢汉化/数值/特性 | 工具描述写死工作流：search → import_entity → place_token |
| 终端里中文显示乱码（如 `ææ`） | PowerShell GBK 显示假象 | 数据本身是 UTF-8 正确的，换 node 直调或无视 |
| 世界内场景搜不到 | search 只索引 compendium | 查场景用 `foundry_get_scene` |
| 说「放地图上」AI 放错场景 | 没读激活场景 | 工具描述写死：未指定场景先 `get_scene(active=true)` |
| 401 全端点 | scoped key 失效/没 scope | 重建 API key（第 4 步） |
| 双击 `start-relay.bat` 报 `'elay' is not recognized` | bat 被编辑器改成 LF 换行/GBK 编码 | 用包里原版（CRLF + ASCII），别用记事本乱存 |
| 手动 `powershell -File start-relay.ps1` 报 Set-Location 乱码找不到路径 | ps1 丢了 UTF-8 BOM（5.1 按 GBK 读中文路径） | 用带 BOM 的 UTF-8 重存，或直接配 config.json 的 `relayExePath` 走自动启动 |
| config.json 读取失败 | 文件带 BOM | 用记事本重新另存为 UTF-8（无 BOM） |

## 附录二：自己编译 relay（Linux/Mac 或换 CPU 架构才需要）

包里已带 Windows x64 的 `relay.exe`，正常不用编译。需要时：

```powershell
# 先装 Go ≥ 1.23：https://go.dev/dl/
cd D:\dsh-foundry-vtt\relay\go-relay
$env:GOPROXY = 'https://goproxy.cn,direct'   # 国内网络加速，必须
```
