## 前置条件

| 项 | 要求 |
|---|---|
| 桌机系统 | Windows 10/11（教程命令为 PowerShell） |
| node | ≥ 20（装插件依赖用；插件运行时零依赖） |
| Go | ≥ 1.23（编译 relay 用；也可下载官方 prebuilt 跳过） |
| git | 任意新版本 |
| DSH | DeepSeek Harness（本插件装配目标） |
| FVTT | V13（模块兼容 min V12 / verified V13） |

**网络要点**：relay 与桌机走 `localhost`；FVTT 在云端、模块在 GM 浏览器里跑，浏览器回连桌机 `ws://localhost:3010`——**云端服务器不需要开任何新端口**。

---

## 第一步：云端 FVTT 装模块

1. 登录 FVTT（GM 账号），进入 **游戏设置 → 管理模块 → 安装模块**。
2. 粘贴 manifest URL：

   ```
   https://github.com/ThreeHats/foundryvtt-rest-api/releases/latest/download/module.json
   ```

3. 在世界中启用模块（模块 id：`foundry-rest-api`）。
4. 刷新页面后，模块设置里会出现菜单按钮 **REST API Connection → Manage Connection**（配对时用）。

> 模块 WebSocket 由 **GM 浏览器（role 4）发起**。这意味着：**GM 浏览器必须开着那个 FVTT 页面**，世界才算「在线」，AI 才操控得到。浏览器关了 = 世界离线（AI 会收到 `No Foundry world is connected`）。

## 第二步：桌机编译并启动 relay

### 编译（或下载官方 release）

```powershell
cd relay\go-relay
$env:GOPROXY = 'https://goproxy.cn,direct'   # 国内网络加速
go build -o relay.exe ./cmd/server/
```

产出 `relay.exe`（约 43MB，纯 Go 无 CGO，SQLite 用 modernc.org/sqlite 免 C 编译）。不想编译就去 ThreeHats 官方 GitHub Releases 下载 prebuilt。

### 启动脚本

仓库已带模板 `relay/start-relay.ps1`，改两处即可用：

```powershell
# relay/start-relay.ps1（模板）
$env:DB_TYPE='sqlite'
$env:PORT='3010'
$env:APP_ENV='production'
$env:LOG_LEVEL='info'
$env:PER_MINUTE_REQUEST_LIMIT='0'
$env:KEY_REQUEST_RATE_LIMIT='100000'   # 重要：默认 20/15min，模块 3 秒轮询会 429
$env:PAIRING_RATE_LIMIT='100000'       # 重要：默认 10，配对交换会被限流
$env:FRONTEND_URL='http://localhost:3010'
$env:DATA_DIR="$PSScriptRoot\data"     # relay.db 落这里
$env:ADMIN_EMAIL='you@example.com'     # 改成你的
$env:ADMIN_PASSWORD='CHANGE_ME'        # 改成强密码！
Set-Location "$PSScriptRoot\go-relay"
.\relay.exe
```

启动后验证：

```powershell
Invoke-RestMethod http://localhost:3010/api/health   # 返回 ok
```

`ADMIN_EMAIL`/`ADMIN_PASSWORD` 首次启动会自动建管理员账号，无需注册 UI。

## 第三步：模块配对（Enter Code 流程）

> ⚠️ 模块的「浏览器配对」按钮会打开 relay 前端批准页 `/pair/{code}`——本仓库不构建 relay 前端（go-relay 是纯后端，前端是独立 Astro 项目），批准页会 404。**不要用浏览器配对，用 Enter Code**，全程 curl 即可。

先在 relay 里登录管理员、发起配对请求、批准、拿 6 位配对码：

```powershell
# ① 管理员登录，拿 sessionToken
$login = Invoke-RestMethod -Method POST http://localhost:3010/auth/login -ContentType 'application/json' `
  -Body '{"email":"you@example.com","password":"CHANGE_ME"}'
$token = $login.sessionToken   # 或 $login.data.sessionToken，按实际返回取

# ② 发起配对请求（匿名，body 里的世界信息在 FVTT 世界页或 relay 日志可见）
$pair = Invoke-RestMethod -Method POST http://localhost:3010/auth/pair-request -ContentType 'application/json' `
  -Body '{"worldId":"你的世界id","worldTitle":"你的世界名","systemId":"dnd5e","systemVersion":"5.3.x","foundryVersion":"13.351","serverFingerprint":"my-pc"}'
$code = $pair.code   # 8 位

# ③ 管理员批准
Invoke-RestMethod -Method POST "http://localhost:3010/auth/pair-request/$code/approve" `
  -ContentType 'application/json' -Headers @{Authorization="Bearer $token"} `
  -Body '{"remoteScopes":["*"],"allowedTargetClients":[],"remoteRequestsPerHour":10000}'

# ④ 轮询拿 6 位配对码（约 5 分钟内有效）
Invoke-RestMethod "http://localhost:3010/auth/pair-request/$code/status"   # 返回 pairingCode 字段
```

然后到 FVTT：**模块设置 → REST API Connection → Manage Connection → 先 Edit URL 确认 `ws://localhost:3010` → Enter Code → 输入 6 位配对码**。

成功后 relay 日志会出现：

```
Pairing completed clientId=fvtt_xxxx ... worldId=你的世界id
Client connected clientId=fvtt_xxxx foundryVersion=13.351 systemId=dnd5e worldId=你的世界id
```

记下这个 `clientId`（第六步配置要用）。

> worldId/worldTitle 怎么查：登录 FVTT 世界后看地址栏 `worlds/<worldId>`；或直接在 relay 日志里找模块连上时打印的 `worldId=`。

## 第四步：创建 API key

```powershell
# 用管理员的 sessionToken 创建全权限 scoped key
$body = @{
  name = 'mcp-control'
  scopes = @(
    'entity:read','entity:write','roll:read','roll:execute','chat:read','chat:write',
    'encounter:read','encounter:manage','macro:list','macro:execute','macro:write',
    'scene:read','scene:write','canvas:read','canvas:write','effects:read','effects:write',
    'user:read','user:write','file:read','file:write','playlist:control','world:info',
    'clients:read','sheet:read','events:subscribe','session:manage','execute-js',
    'search','structure:read','structure:write','dnd5e'
  )
  scopedClientIds = @('fvtt_xxxx')   # 第三步记下的 clientId
} | ConvertTo-Json -Depth 4
Invoke-RestMethod -Method POST http://localhost:3010/auth/api-keys `
  -ContentType 'application/json' -Headers @{Authorization="Bearer $token"} -Body $body
# 返回里的 key（64 位十六进制）就是 FOUNDRY_API_KEY
```

> 注意：打数据 API 必须用 scoped API key（`x-api-key` header）。管理员 sessionToken 直接打数据端点会 401（`A scoped API key is required for API calls`）。

## 第五步：装配 DSH 插件

把 `plugin/` 目录装进 DSH，让新对话的 AI 能看到 86 个工具。

### 方式 A：dsh-super-injector（推荐，免重启热装配）

在 DSH 里对 AI 说（或直接调工具）：

```
dev_install_package dir=C:\path\to\dsh-foundry-vtt\plugin
```

它会改 profile 的 `package.json`（dependencies 加 link + bundles 数组加包名）、建 node_modules junction、热装配生效；**重启 DSH 后由 bundles 列表自动装配**（持久）。

### 方式 B：手动装配

1. 编辑 `~/.dsh/profiles/<profile>/package.json`：
   - `dependencies` 加 `"@dsh-external/dsh-foundry-vtt": "link:C:\\path\\to\\plugin"`
   - `dsh.profile.bundles` 数组加 `"@dsh-external/dsh-foundry-vtt"`
2. 建 junction：`cmd /c mklink /J "%USERPROFILE%\.dsh\profiles\<profile>\node_modules\@dsh-external\dsh-foundry-vtt" "C:\path\to\plugin"`
3. 重启 DSH。

> 编译产物 `lib/index.js` 已随仓库提供。若改了 `src/` 要重编译：
> ```powershell
> cd plugin
> npm install --no-audit --no-fund
> .\node_modules\.bin\tsc.cmd -p tsconfig.json
> ```

## 第六步：配置 config.json

插件配置放在 **`~/.dsh/dsh-foundry-vtt/config.json`**（在用户主目录，与插件目录分离——所以重装 DSH、换插件目录都不丢配置）：

```json
{
  "relayUrl": "http://localhost:3010",
  "apiKey": "第四步拿到的64位key",
  "clientId": "第三步记下的fvtt_xxxx"
}
```

- 兜底顺序：config.json → 环境变量 `FOUNDRY_RELAY_URL`/`FOUNDRY_API_KEY`/`FOUNDRY_CLIENT_ID` → `http://localhost:3010`。
- **文件必须 UTF-8 无 BOM**（PowerShell `Set-Content` 默认带 BOM 会导致 JSON.parse 失败）。

## 验证

开一个 DSH 新对话，说：

> 「列出我的 FVTT 世界，看看在线吗」

AI 应该调用 `foundry_list_worlds`，返回你的世界（含 dnd5e 版本、foundry 版本、online: true）。

进阶验证：

- 「帮我掷 1d20+5」
- 「在激活地图上放一只僵尸」——AI 会自己走 search → import_entity → get_scene(active=true) → place_token，这是工具描述里写死的推荐工作流
- 「给这只怪加个啃咬（1d8），命中后 DC11 体质豁免，失败中毒」——AI 会照 midi-qol 自动化结构改物品

## 常见坑大全

| 现象 | 原因 | 处理 |
|---|---|---|
| 批准页 `/pair/{code}` 404 | relay 前端 SPA 未构建（go-relay 纯后端） | 用 Enter Code 流程（本教程第三步） |
| 模块轮询 / 配对交换 429 | `KEY_REQUEST_RATE_LIMIT`/`PAIRING_RATE_LIMIT` 默认太小（20/15min、10） | start-relay.ps1 里调到 100000（模板已带） |
| `No Foundry world is connected` | GM 浏览器关了 FVTT 页面 | 重新打开世界页；模块 WS 由 GM 浏览器发起 |
| `execute-js is disabled in REST API module settings` | 模块设置里 execute-js 默认禁用 | 要么在模块设置开启；要么别用 execute_js——改物品自动化直接用 `foundry_update_entity` 的内嵌 uuid（`Actor.<id>.Item.<id>`） |
| update/add_effect 偶发「does not exist」但实际生效 | 模块端 fromUuid 回读间歇误报 | 工具内置回读确认，返回 `verified:true` 即为已生效，AI 会正确判断 |
| 新建怪的武器没伤害 | dnd5e 5.3.x 丢弃旧版 `parts[].formula` | 伤害骰必须放 `item.system.damage.base{number,denomination,bonus,types}`；activities 的 `damage.parts` 留空数组 + `includeBase:true`（工具描述已内置此警告） |
| AI 把怪「新建」而不是从世界包拿 | 新建会丢汉化/数值/特性 | 工具描述写死工作流：search → import_entity → place_token，禁止新建 |
| 终端里中文显示乱码（如 `ææ`） | PowerShell GBK 显示假象 | 数据本身是 UTF-8 正确的，换 UTF-8 终端（如 node 直调）或无视 |
| 世界内场景搜不到 | search 只索引 compendium | 查场景用 `foundry_get_scene`（active=true 拿激活场景） |
| 说「放地图上」AI 放错场景 | 没读激活场景 | 工具描述写死：未指定场景先 `get_scene(active=true)`，place_token 不传 sceneId 即默认激活场景 |
| 401 全端点 | scoped key 失效/没 scope | 重建 API key（第四步） |

## 日常运维

- **开机自启 relay**：任务计划程序或启动目录加 `relay\start-relay.ps1`。
- **备份 relay.db**：`relay\data\relay.db` 是命根子——配对关系、API key 全在里面。备份它 + 教程文档，换机重装 = 拷 relay 目录 + 插件目录 + `~/.dsh` 配置。
- **重装 DSH**：只要不删 `~/.dsh`，插件装配（bundles）与 config.json 都在；重跑 relay 即可。
- **换机**：拷三样东西——relay 目录（含 data）、插件目录、`~/.dsh/dsh-foundry-vtt/config.json`；重装配插件（第五步）即可。
